从零开始：跟着一次矩阵乘法走进 H100

这一节用一块 NVIDIA H100（SXM 版，2022 年发布，2024–25 年大模型训练和推理的主力）当标本，把后面每一节都要用到的概念按顺序讲一遍：SM 与张量核心、峰值算力、存储层次、一次矩阵乘法的数据流、三种瓶颈。已经熟悉 GPU 编程的读者可以直接跳到「Roofline」。

贯穿全章的例子：一层权重乘一批 token

大模型里绝大部分计算是同一个形状：激活矩阵乘权重矩阵（第 章）。取一个具体的：某一层的权重 \(W\) 是 \(8192\times 8192\)，用 BF16 存（每个数 2 字节），共 134 MB；输入是 \(m\) 个 token 的激活 \(X\)（\(m\times 8192\)），输出 \(Y = XW\)（\(m\times 8192\)）。

  • \(m = 4096\)：一次读入一段 4096 token 的提示，即预填充。计算量 \(2\times 4096\times 8192^2\approx 5.5\times 10^{11}\) 次浮点运算（FLOPs）；要读写的数据至少 \(134 + 67 + 67 = 268\) MB（W、X、Y 各一遍）。
  • \(m = 1\)：给一个用户生成下一个 token，即解码。计算量只有 \(1.3\times 10^{8}\)，数据量却几乎不变：W 的 134 MB 一个字节也省不掉。

同一个矩阵、两种用法，计算量差 4096 倍，数据量只差一倍。这一章的大部分内容都在解释：这个差别在硬件上意味着什么。

GPU 为什么长这样：用很多线程换吞吐

CPU 为“一串指令尽快做完”设计：几十个大核心，大量面积花在分支预测、乱序执行和大缓存上。GPU 为“海量相同的简单运算一起做完”设计：H100 有 132 个流式多处理器（streaming multiprocessor，SM），每个 SM 同时驻留最多 2048 个线程。

线程不是一个一个调度的。每 32 个线程组成一个线程束（warp），同一时刻执行同一条指令、处理不同的数据（SIMT，单指令多线程）。某个线程束在等显存的数据时，SM 立刻换一个数据已经就绪的线程束来执行，切换几乎没有代价。CPU 靠缓存减少等待；GPU 靠“同时有足够多的活可干”把等待藏起来。

在 GPU 上运行的一个函数叫内核（kernel）。启动内核时指定一个由许多“线程块”组成的网格，每个线程块被分到某个 SM 上执行。一次矩阵乘法通常就是一个内核，每个线程块负责输出矩阵的一小块。本章标题里的“内核”就是指它，和操作系统内核无关。同一块芯片能跑多快，很大程度上看内核怎样安排数据。

一个 SM 里有什么：峰值算力从哪来

每个 SM 分成 4 个子分区，每个子分区有一个线程束调度器、32 条 FP32 运算通道和一个张量核心（tensor core）。张量核心是专门做小矩阵乘加 \(D = AB + C\) 的电路：一条指令处理一整块小矩阵，而不是一对数。BF16 下，每个张量核心每个时钟周期完成 512 次乘加；一次乘加（FMA）算 2 次浮点运算。于是：

\[ \begin{aligned} \htmlClass{sym-P}{P_{\text{峰值}}} &= \htmlClass{sym-nsm}{N_{\text{SM}}}\times \htmlClass{sym-ops}{c}\times \htmlClass{sym-f}{f} \\ &= 132\times 4096\times 1.83\ \text{GHz}\approx 989\ \text{TFLOPS} \end{aligned} \]
峰值算力 = SM 个数 × 每个 SM 每个时钟周期能做的浮点运算数 × 时钟频率。BF16 下，一个 SM 的 4 个张量核心每周期合计 \(4\times 512\times 2 = 4096\) 次运算。
\(P_{\text{峰值}}\)
峰值算力（每秒浮点运算数，FLOPS），厂商公布的稠密数字
\(N_{\text{SM}}\)
SM 个数：H100 SXM 启用 132 个（整颗芯片有 144 个）
\(c\)
每个 SM 每周期的运算数：BF16 为 4096，FP8 翻倍为 8192
\(f\)
时钟频率：张量核心的峰值按 1.83 GHz 计算
BF16：\(132\times 4096\times 1.83\times10^9\approx 9.9\times 10^{14}\)，即 989 TFLOPS；FP8 为 1979 TFLOPS。不走张量核心的普通 FP32 运算（逐元素操作、softmax 里的指数）只有约 67 TFLOPS，差 15 倍：一个运算能不能写成矩阵乘法，决定了它能用上多少算力。例子里 \(m = 4096\) 的矩阵乘法要 \(5.5\times10^{11}\) 次运算，在峰值下需要 0.56 毫秒。

存储层次：越近越快、越小

算得快只是一半，数据还得送得到。H100 的存储分成几级，越靠近张量核心越快、越小：

寄存器、共享内存和 L2 都是片上 SRAM：用晶体管直接存储，紧挨计算单元，快但占面积，所以小。HBM（高带宽显存）是几层 DRAM 芯片堆叠起来、和 GPU 封装在一起的显存，容量大，但每个字节都要穿过芯片边缘有限的引脚才能进来。整块 H100 的片上存储加起来约 120 MB，放不下例子里一个 134 MB 的权重矩阵。

从 HBM 往外，每走一级带宽大约降一个数量级：HBM 3.35 TB/s，NVLink 每个方向 450 GB/s，网卡 50 GB/s。往里走则反过来：共享内存约是 HBM 的 10 倍。能耗也是这样：按 Horowitz（2014）在 45 纳米工艺下的估算，从 DRAM 读 64 位要 1.3–2.6 nJ，一次 16 位浮点乘法只要约 1 pJ，差上千倍。在 GPU 上，搬数据比算数据贵得多。

跟着一次矩阵乘法走一遍

现在把 \(m = 4096\) 的 \(Y = XW\) 交给 H100。一个典型的高性能内核这样做：

  1. 切块。把输出 \(Y\)（\(4096\times 8192\)）切成 \(128\times128\) 的块，共 \(32\times 64 = 2048\) 块，每个线程块负责一块。
  2. 分波。2048 块分给 132 个 SM，每个 SM 一次算一块，要 \(\lceil 2048/132\rceil = 16\) 波；最后一波只有 68 块，将近一半的 SM 空着。块数不是 SM 数的整数倍造成的浪费叫波次量化（wave quantization），这里损失 3%；矩阵小的时候可以损失一半。
  3. 搬数据。算一块 \(Y\) 需要 \(X\) 的 128 行和 \(W\) 的 128 列。沿着内积方向（长 8192）分成 128 步、每步 64：每一步由 TMA（Tensor Memory Accelerator，张量内存加速器，H100 新增的拷贝单元）把 \(X\) 的 \(128\times 64\) 和 \(W\) 的 \(64\times128\) 两个小块（共 32 KB）从显存经 L2 搬进共享内存。一个线程发一条指令就能搬一整块，其余线程不用参与。
  4. 流水。共享内存同时放 4 份左右这样的小块：张量核心在算第 \(s\) 步时，TMA 已经在搬第 \(s+1\)、\(s+2\) 步。只要搬得比算得快，张量核心就不用等。
  5. 计算与累加。张量核心直接从共享内存读这两个小块，做 \(128\times128\times64\approx 105\) 万次乘加，约 512 个时钟周期。结果累加在寄存器里一个 \(128\times128\) 的 FP32 累加器上（64 KB，占这个 SM 寄存器的四分之一），128 步里一直不离开芯片。
  6. 收尾。128 步之后，累加器转成 BF16，顺便可以做加偏置、激活函数这类逐元素操作，再写回显存（32 KB）。这一段叫 epilogue。

关键的约束在第 3、4 步：搬数据的速度够不够。

\[ \begin{aligned} \htmlClass{sym-need}{\text{需要的带宽}} &= \frac{\htmlClass{sym-ops}{c}}{\htmlClass{sym-It}{I_{\text{块}}}}\times N_{\text{SM}}\times f \\ \htmlClass{sym-It}{I_{\text{块}}} &= \frac{2\times128\times128\times 64}{32\ \text{KB}} = 64\ \text{FLOPs/字节} \end{aligned} \]
每个 SM 每周期要做 \(c = 4096\) 次运算；每搬进一个字节只够做 \(I_{\text{块}}\) 次运算；所以每个 SM 每周期要被喂进 \(c/I_{\text{块}}\) 个字节，乘以 SM 数和频率，就是全芯片需要的带宽。
需要的带宽
让张量核心一直满负荷，每秒必须送进 SM 的字节数
\(I_{\text{块}}\)
块级的算术强度：每搬进共享内存一个字节，做多少次运算
\(c\)
每个 SM 每周期的运算数，BF16 为 4096
\(4096/64 = 64\) 字节/周期/SM，\(64\times132\times1.83\times10^9\approx 15.5\) TB/s，是 HBM 带宽的 4.6 倍。如果每一步的数据都从显存来，张量核心只有约 22% 的时间在算。所以大部分数据必须来自 L2：同时在算同一行块的几个 SM 读的是同一段 \(X\)，第一个从显存取，后面的命中 L2。2048 块合计要从 L2 读 8.6 GB：\(X\) 的每个字节被读 64 次，\(W\) 的每个字节被读 32 次。实际的 Hopper 内核常用 \(128\times 256\) 的块，并让相邻两个 SM 共享一次读入，进一步减轻 L2 的负担。

下面把这个过程拆成单步。切换到 \(m = 1\)（解码）再走一遍：输出只有 64 块，132 个 SM 里一半没活干；每一步搬 16 KB 的 W，只做 8192 次有用的乘加，张量核心 99% 以上的时间在等数据。

三种瓶颈：算不过来、搬不过来、等不过来

一个内核的耗时，近似取下面三者中最大的那个（Horace He 的分类）：

  • 计算受限（compute-bound）：运算数 ÷ 峰值算力。\(m = 4096\) 的例子：0.56 毫秒，而读写 268 MB 只要 80 微秒。
  • 访存受限（memory-bound）：读写的字节数 ÷ 显存带宽。\(m = 1\) 的例子：读 134 MB 要 40 微秒，计算只要 0.14 微秒，算力用了 0.3%。
  • 开销受限（overhead-bound）：既不在算也不在搬，而是在等。每启动一个内核有几微秒的固定开销；PyTorch 逐个下发算子时，每个算子还有 Python 和框架的开销。小模型、小批量解码时，GPU 可能一大半时间在等 CPU 发下一条命令。对策是 CUDA Graphs（把一串内核录下来一次性下发）和把小操作合并成一个内核。

前两种之间的界线由硬件的“算力 ÷ 带宽”决定。下一节把它画成一张图。

Roofline：算得快还是搬得快

判断一段计算受限于算力还是带宽，看它的算术强度：每从显存读写一个字节，做多少次运算。Roofline 模型把可达到的性能画成一条“屋顶线”：

\[ \text{可达到的性能} = \min\Big(\htmlClass{sym-P}{P_{\text{峰值}}},\ \ \htmlClass{sym-I}{I}\times \htmlClass{sym-BW}{\text{BW}}\Big),\qquad I = \frac{\text{FLOPs}}{\text{读写的字节数}} \]
算术强度低时，性能等于“强度 × 带宽”，随强度线性上升，叫访存受限；强度超过拐点 \(P/\text{BW}\) 后，性能封顶于峰值算力，叫计算受限。
\(P_{\text{峰值}}\)
芯片的峰值算力（FLOPS）
\(\text{BW}\)
显存带宽（字节 / 秒）
\(I\)
这段计算的算术强度（FLOPs / 字节）
H100 的拐点：\(989\times 10^{12}/3.35\times 10^{12}\approx 295\) FLOPs/字节。生成时单个用户每步要读出全部权重，每个 BF16 权重（2 字节）只参与一次乘加（2 FLOPs），强度约 1，只能用到峰值算力的约 0.3%。一个 8B 模型用 FP8 存储（8 GB），每生成一个 token 至少要读 8 GB，速度上限约 \(3.35\text{ TB/s}/8\text{ GB}\approx 420\) token/s，无论算力多强。

屋顶的转折处 \(I^\ast = P/\text{BW}\) 叫拐点（ridge point）：每读一个字节，至少要做这么多次运算，算力才不闲着。它是一个硬件参数，和跑什么程序无关。那么一次矩阵乘法的强度是多少？

\[ I(\htmlClass{sym-m}{m},\htmlClass{sym-n}{n},\htmlClass{sym-k}{k}) = \frac{2mnk}{\htmlClass{sym-b}{b}\,(mk + kn + mn)} = \frac{2/b}{\htmlClass{c-new}{\frac1m} + \frac1n + \frac1k} \]
分子是运算数：输出有 \(mn\) 个数，每个是长度 \(k\) 的内积，\(k\) 次乘、\(k\) 次加。分母是最少要读写的字节：\(A\)（\(m\times k\)）、\(B\)（\(k\times n\)）各读一遍，\(C\)（\(m\times n\)）写一遍。右边的写法说明：强度由三条边里最短的那条决定。
\(m\)
一次参与计算的 token 数（激活矩阵的行数）
\(n\)
输出维度
\(k\)
内积长度（输入维度）
\(b\)
每个数的字节数：BF16 为 2，FP8 为 1
例子的 \(n = k = 8192\)，BF16：\(m = 1\) 时 \(I\approx 1.0\)；\(m = 64\) 时 \(I\approx 63\)；\(m = 4096\) 时 \(I = 2048\)。H100 的拐点是 295，\(m\) 要到约 320 才转为计算受限。同一个权重矩阵，预填充时计算受限，解码时访存受限，差别只在一次喂进来多少个 token。

这解释了推理系统的许多设计（第 章）：预填充一次处理整个提示，几千个 token 共用一次权重读取，强度高、计算受限；解码一次生成一个 token，强度低、访存受限，所以要把很多用户的请求拼成一批，让一次权重读取服务 \(B\) 个 token，强度约提高到 \(B\)。量化（第 章）减少要读的字节数，在访存受限时几乎直接换来同比例的加速。解码时的注意力更难办：每个用户的 KV 缓存只服务他自己的那一个 token，拼批提高不了它的强度。一个 KV 头被 \(G\) 个查询头共享（GQA）时，BF16 下强度约为 \(G\)；MLA 让所有头共享同一份压缩的 KV，强度高得多（第 章）。下面的估算器把这些因素放在一起：

矩阵乘法的算术强度：为什么由最短的那条边决定

第 1 步，数运算。\(C = AB\)，\(A\) 是 \(m\times k\)，\(B\) 是 \(k\times n\)。\(C\) 的每个元素是一个长度为 \(k\) 的内积：\(k\) 次乘法、\(k-1\) 次加法，\(k\) 很大时记作 \(2k\) 次运算。\(C\) 有 \(mn\) 个元素，总运算数 \(2mnk\)。

第 2 步，数字节。不管内核怎么写，\(A\)、\(B\) 至少要从显存读一遍，\(C\) 至少要写一遍：\(b(mk + kn + mn)\) 字节。这是下限，相当于假设片上存储足够大、读进来的数可以无限复用。下一节会看到实际能多接近它。

第 3 步，化简。分子分母同除以 \(mnk\)：

\[ I = \frac{2mnk}{b\,(mk + kn + mn)} = \frac{2}{b}\cdot\frac{1}{\frac1n + \frac1m + \frac1k} \]

分母是三条边的倒数之和。最短的那条边倒数最大，占主导。

第 4 步，两种极端。方阵 \(m = n = k\)：\(I = 2n/(3b)\)，BF16 下 \(n = 4096\) 时约 1365，远高于拐点。细长矩阵 \(m \ll n, k\)：\(\frac1m\) 远大于另外两项，\(I\approx 2m/b\)，BF16 下 \(I\approx m\)。解码时 \(m\) 就是批里的 token 数 \(B\)，所以强度约等于 \(B\)。

第 5 步，和拐点比较。细长情形下，计算受限的条件 \(2m/b \ge P/\text{BW}\) 等价于

\[ m \ \ge\ m^\ast = \frac{P\,b}{2\,\text{BW}} \]

H100 的 BF16：\(989\times10^{12}\times 2/(2\times 3.35\times10^{12})\approx 295\)。换成 FP8，\(b\) 减半、\(P\) 翻倍，\(m^\ast\) 不变。这就是第 章里“批多大才能用满算力”的 \(B^\ast\)：它与模型大小、数值精度都无关，只是硬件的“每读一个数能做几次运算”。

这个推导告诉我们：一个矩阵乘法受限于什么，看的是它最短的那条边，而不是它有多大。解码访存受限，是因为它的最短边是批大小；低精度让算力和带宽同比例提升，并不降低这个门槛。想让解码用满算力，只能让一次权重读取服务更多 token：拼批（第 章），或者投机解码、多 token 预测这类一次验证几个 token 的方法。

意外：芯片的算力涨得比“喂数据”的速度快得多

原以为
每一代新芯片算力翻倍，模型就能跑快一倍。
实际发现
Gholami 等（2024）统计了二十年的硬件：峰值算力约每 2 年增长 3 倍，显存带宽只增长约 1.6 倍，芯片间互连约 1.4 倍。二十年间算力增长了约 6 万倍，显存带宽只增长了约 100 倍。这就是内存墙（memory wall）。
为什么
晶体管变小让计算电路越来越便宜，但把数据送进芯片的引脚数、信号速率和封装面积增长慢得多。HBM 把显存堆叠在芯片旁边，已经是为了带宽付出的高昂代价。
现在怎么看
算术强度低的操作（解码、注意力、归一化、逐元素运算）的占比越来越重要。软件上的对策是提高数据复用（分块、算子融合、FlashAttention）、减少数据量（量化、MLA）；硬件上的对策是更大的片上存储（下文的 Groq、Cerebras、LPX）和更快的 HBM（2026 年的 HBM4）。

分块：怎样让矩阵乘法达到峰值

矩阵乘法是少数能达到峰值的运算，因为它天然有数据复用：\(n\times n\) 的矩阵相乘做 \(n^3\) 次乘加，却只需读 \(2n^2\) 个数。但要真正兑现这种复用，必须让读进来的数据在片上被反复使用，而不是用一次就丢、下次再从显存读。办法是分块（tiling）：

\[ I_{\text{分块}} = \frac{2n^3}{\big(2n^3/\htmlClass{sym-T}{T}\big)\times \htmlClass{sym-b}{b}} = \frac{\htmlClass{c-new}{T}}{b} \]
一次在片上计算输出矩阵的一个 \(T\times T\) 区域：沿着内积方向，每读入 A 的一列小块和 B 的一行小块，就做 \(T^2\) 次乘加，结果一直留在片上累加。每个读入的数被用了 \(T\) 次，总读入量从 \(2n^3\) 降到 \(2n^3/T\)，算术强度与 \(T\) 成正比。
\(T\)
分块边长，受片上存储容量限制
\(b\)
每个数的字节数
不分块（\(T = 1\)，每次乘加都从显存读两个数）：BF16 下强度只有 0.5，H100 只能用到峰值的约 0.2%。\(T = 128\)：强度 64，就是「从零开始」里那张公式卡的 \(I_{\text{块}}\)；再加上 L2 缓存和多个 SM 之间的复用，实际的大矩阵乘法能达到峰值的 70–80%。
分块为什么把访存降到 1/T，以及片上存储的平方根定律

第 1 步，不分块。每做一次乘加 \(c_{ij} \mathrel{+}= a_{il}b_{lj}\)，都从显存读 \(a_{il}\) 和 \(b_{lj}\)。共 \(mnk\) 次乘加、读 \(2mnk\) 个数，强度 \(2mnk/(2mnk\cdot b) = 1/b\)，BF16 下 0.5。

第 2 步，按输出分块。一次计算 \(C\) 的一个 \(T_m\times T_n\) 区域，结果留在片上累加。算完这一块需要 \(A\) 的 \(T_m\) 行（\(T_m k\) 个数）和 \(B\) 的 \(T_n\) 列（\(kT_n\) 个数）。共有 \(\frac{m}{T_m}\cdot\frac{n}{T_n}\) 块，总读入量：

\[ \frac{mn}{T_mT_n}\cdot k\,(T_m + T_n)\cdot b = mnk\,b\,\Big(\frac{1}{T_n} + \frac{1}{T_m}\Big) \]

取 \(T_m = T_n = T\)，得 \(2mnk\,b/T\)，正好是不分块时的 \(1/T\)。原因是每个读进来的 \(a_{il}\) 被这一块里的 \(T\) 个输出列共用，每个 \(b_{lj}\) 被 \(T\) 个输出行共用。

第 3 步，强度。\(I = \dfrac{2mnk}{mnk\,b\,(1/T_m + 1/T_n)} = \dfrac{2}{b\,(1/T_m + 1/T_n)}\)，方块时为 \(T/b\)，即上面公式卡的结论。

第 4 步，容量约束。块不能无限大：\(T_m\times T_n\) 个 FP32 累加器（每个 4 字节）必须一直留在片上，此外还有正在用和预取的操作数小块。设片上可用容量为 \(S\) 字节，主要约束是 \(4T_mT_n \le S\)。而 \(\frac{1}{T_m} + \frac{1}{T_n} = \frac{T_m + T_n}{T_mT_n}\)，乘积固定时分子在 \(T_m = T_n\) 时最小（算术–几何平均不等式），所以方块最优，\(T = \sqrt{S/4}\)：

\[ I_{\max} \approx \frac{1}{b}\sqrt{\frac{S}{4}} \ \propto\ \sqrt{S} \]

第 5 步，代入 H100。每个 SM 的寄存器 256 KB，就算全部用来放累加器，\(T = \sqrt{65536} = 256\)，BF16 强度 128。实际内核还要留寄存器给地址和其他变量，常用 \(128\times128\)（累加器 64 KB，强度 64）到 \(128\times 256\)（128 KB，强度约 85）。更大的复用只能靠多个 SM 合作：一个簇里的几个 SM 共享一次读入，相当于把块拼大。

第 6 步，这已经是最优。Hong 与 Kung（1981）证明：在快速存储只有 \(S\) 的机器上，用常规的 \(n^3\) 算法计算 \(n\times n\) 矩阵乘法，快慢两级存储之间的数据传输至少是 \(\Omega(n^3/\sqrt S)\)。分块达到了这个下限，只差一个常数。

这个推导告诉我们：片上存储翻倍，算术强度只涨约 1.4 倍。所以 GPU 每一代不是单纯加大共享内存，而是想办法把更多存储“拼”到同一块计算上：Hopper 的线程块簇和 TMA 多播让几个 SM 共享读入；Blackwell 加了专放累加器的张量内存，让两个 SM 合作做一次矩阵乘。张量核心越做越大也是同一个原因：运算量随边长的三次方增长，数据量只随平方增长，大一圈的乘法单元天然复用更高。

分块解决的是一个内核内部的复用。内核之间也有浪费：矩阵乘法算完写回显存，下一个内核（加偏置）再读出来、写回去，再下一个（激活函数）又读一遍。这些逐元素操作的强度远低于 1，耗时完全由字节数决定：

\[ t_{\text{逐元素}} \approx \frac{\htmlClass{sym-rw}{\text{读} + \text{写的字节数}}}{\htmlClass{sym-BW}{\text{BW}}} \]
逐元素操作几乎不算什么，时间全花在把张量读进来、写出去上。
读 + 写的字节数

例子的输出 \(Y\) 有 67 MB。分开做“加偏置、激活、转精度”三个内核，每个读写一遍共 134 MB，合计 403 MB，约 120 微秒，相当于矩阵乘法本身（0.56 毫秒）的 22%。在矩阵乘法的收尾阶段顺手做掉，额外的显存读写是 0。

把多个操作合并到一个内核里、中间结果不写回显存，叫算子融合（kernel fusion）。FlashAttention（第 章）是融合的极致：注意力的打分、softmax、乘 V 全部在片上完成，\(n\times n\) 的分数矩阵从不落地。这就是高性能内核的核心技艺：选择分块大小，安排数据在寄存器、共享内存、L2 之间的流动，用异步拷贝把下一块数据的读取与当前块的计算重叠起来，再把能融合的操作都融合进去。编译器自动做的主要也是融合（下文「软件栈」）。

低精度：为什么位数减半，算力翻倍

H100 的 FP8 算力是 BF16 的 2 倍；Blackwell（B200）又加入 FP4，算力再翻倍；2026 年的 Rubin 宣称单卡 NVFP4 推理算力 50 PFLOPS。为什么位数越少，算力越高？先看乘法器本身（浮点数的格式见的浮点数一节）：

\[ \text{乘法器面积} \ \propto\ (\htmlClass{sym-m}{m} + 1)^2 \]
浮点乘法的主体是两个尾数相乘，硬件上是一个 \((m+1)\times(m+1)\) 位的整数乘法器（\(m\) 位尾数加上隐含的 1），面积和功耗大约与位数的平方成正比。同样的芯片面积，位数越少，能放的乘法器越多。
\(m\)
尾数位数：BF16 为 7，FP16 为 10，FP8（E4M3）为 3，FP4（E2M1）为 1
BF16 的乘法器约 \(8^2 = 64\) 单位面积，FP8 约 \(4^2 = 16\)，FP4 约 \(2^2 = 4\)：位数减半，乘法器面积降到约四分之一。这与 Horowitz 的能耗估算一致：8 位整数乘法 0.2 pJ，32 位 3 pJ，位宽 4 倍、能耗约 15 倍。可实际芯片每降一档只给出 2 倍的提升，原因见下一张卡和推导。
\[ \text{每周期乘加数} \ \propto\ \frac{\htmlClass{sym-B}{\text{每周期送进张量核心的字节数}}}{\htmlClass{sym-b}{b}} \]
张量核心一条指令读入的操作数，按字节算是固定的。每个数的字节数 \(b\) 减半，同样的字节装下两倍的数，乘加数就翻倍。

Hopper 的矩阵乘指令沿内积方向一次处理 8 个 TF32、16 个 BF16 或 32 个 FP8，乘上每个数的字节数都是 32 字节。对应的 H100 稠密算力是 495、989、1979 TFLOPS，比例正好 1 : 2 : 4。B200 的 TF32、BF16、FP8、FP4 是 1.1、2.25、4.5、9 PFLOPS，同样每降一档翻一倍。
位数减半，为什么吞吐翻倍而不是翻四倍

第 1 步，乘法器的面积。两个浮点数相乘 = 尾数相乘 + 指数相加 + 规格化与舍入。尾数带上隐含的 1 共 \(p = m+1\) 位。\(p\times p\) 的整数乘法先生成 \(p^2\) 个部分积位，再用加法器树把它们压缩成结果，元件数大致与 \(p^2\) 成正比。指数加法只与指数位数成正比，是小头。

第 2 步，用能耗验证。Horowitz（2014，45 纳米）的估算：8 位整数乘法 0.2 pJ、32 位 3 pJ，位宽 4 倍、能耗 15 倍，接近 \(4^2 = 16\)；16 位浮点乘法约 1 pJ、32 位约 4 pJ，尾数 11 位对 24 位，\((24/11)^2\approx 4.8\)。平方律大致成立。照此推算，BF16、FP8、FP4 的乘法器面积之比是 64 : 16 : 4。

第 3 步，为什么不是 4 倍。张量核心不只有乘法器。一次 \(k\) 维内积的 \(k\) 个乘积要对齐指数再加起来，加法器树和累加器为了控制误差保持较宽的格式，不随输入位数平方缩小。更关键的是数据通路：寄存器文件和共享内存每个周期能送出的字节数是固定的。Hopper 的矩阵乘指令沿内积方向一次处理 8 个 TF32、16 个 BF16 或 32 个 FP8，都是 32 字节。字节数不变，一条指令里的乘加数就与 \(1/b\) 成正比。

第 4 步，对照实际数字。H100 的 TF32、BF16、FP8 稠密算力 495、989、1979 TFLOPS；B200 的 TF32、BF16、FP8、FP4 为 1.1、2.25、4.5、9 PFLOPS。每降一档正好翻倍，符合“吞吐 ∝ 1/字节数”，而不是乘法器面积的平方律。还有一个对照：FP16 的尾数比 BF16 多 3 位，乘法器约大一倍（121 对 64），两者在 H100 上的算力却完全相同，因为它们都占 2 字节。数的个数翻倍、每个乘法器缩到四分之一，乘法器的总面积反而减半。

第 5 步，换成能耗看。一次 16 位乘法约 1 pJ，从 DRAM 读 64 位要 1.3–2.6 nJ。只要数据得从显存来，运算本身的能耗几乎可以忽略；位数减半，真正省下的是一半的搬运。

这个推导告诉我们：低精度的收益主要不在乘法器变小，而在“每个字节能换多少次运算”：位数减半，同样的数据通路每拍送进两倍的数，算力翻倍，要搬的字节也减半。累加器则不能跟着变窄：乘法的误差是一次性的，加法的误差会沿着内积一路积累。

最后一点有实际的教训。DeepSeek-V3 的报告写到，在 H800 上实测 FP8 矩阵乘法的累加只保留约 14 位精度，内积长度 4096 时最大相对误差接近 2%；他们只好每 128 个元素把部分和搬到 CUDA 核心上用 FP32 累加。Hopper 的张量核心也只支持整个张量一个缩放因子，更细的分块缩放要在 CUDA 核心上补做。Blackwell 的张量核心原生支持微缩放格式（每 16 或 32 个数共享一个缩放因子，如 MXFP4、NVFP4），缩放在张量核心内部完成。怎样让模型在 4 位下不掉点，是第 章的主题。

另外两种设计：脉动阵列与全片上存储

脉动阵列（TPU）。GPU 用很多个小张量核心，再靠软件分块获得复用。Google 的 TPU 走另一条路：用一个大的脉动阵列（systolic array）做矩阵乘法。阵列是 \(N\times N\) 个乘加单元组成的网格（TPU v2 到 v5p 为 \(128\times128\)，Trillium 和 Ironwood 为 \(256\times256\)），每个单元预先存好一个权重；输入数据从左边一拍一拍地流入、每拍右移一格，部分和从上往下流、每拍下移一格并加上本单元的乘积。数据在相邻单元之间直接传递，不经过寄存器或缓存，像心脏一拍一拍把血泵出去，所以叫“脉动”。

\[ \text{利用率} = \frac{\htmlClass{sym-M}{M}}{M + 2\htmlClass{sym-N}{N} - 2} \]
一批 \(M\) 行输入流过 \(N\times N\) 的阵列。最后一行进入之后，还要再走 \(2N-2\) 拍才能从右下角出来；在开头“填充”和结尾“排空”的这些拍里，阵列只有一部分单元在干活。

阵列每拍做 \(N^2\) 次乘加，只从边上读入 \(N\) 个数、写出 \(N\) 个数：每个读进来的数被用 \(N\) 次。这和上一节分块的结论（每个数被用 \(T\) 次）是同一件事，只不过复用由导线实现，而不是由软件安排。好处是能效高；代价是只擅长规整的大矩阵乘法，遇到小矩阵、小批量就要补零或空转。GPU 用 SIMT 加张量核心，更通用，编程生态也更成熟。

脉动阵列：数据怎样被复用，以及为什么怕小批量

第 1 步，摆放。计算 \(Y = XW\)，\(X\) 是 \(M\times N\)（\(M\) 个 token），\(W\) 是 \(N\times N\)。单元 \((i,j)\) 存放 \(w_{ij}\)（权重驻留，weight-stationary）。第 \(r\) 个 token 的第 \(i\) 个分量 \(x_{ri}\) 从第 \(i\) 行左端进入，每拍右移一格；输出 \(y_{rj}\) 的部分和从第 \(j\) 列顶端出发，每拍下移一格，经过每个单元时加上 \(x_{ri}w_{ij}\)。

第 2 步，对齐时间。让 \(x_{ri}\) 在第 \(r + i\) 拍进入阵列（第 \(i\) 行比第 0 行晚 \(i\) 拍，即“斜着”送入），它在第 \(r+i+j\) 拍到达第 \(j\) 列。\(y_{rj}\) 的部分和在第 \(r + j\) 拍从第 \(j\) 列顶端出发，第 \(r+j+i\) 拍到达第 \(i\) 行。两者在单元 \((i,j)\) 的同一拍相遇：

\[ t_{ij}(r) = r + i + j \]

部分和走完 \(N\) 行，就是 \(y_{rj} = \sum_i x_{ri}w_{ij}\)，在第 \(r + j + N - 1\) 拍从底部离开。斜着送入正是为了让这两股数据流对得上。

第 3 步，复用。稳态下每拍有 \(N^2\) 个单元在做乘加，只从左边读入 \(N\) 个数、从底部写出 \(N\) 个数。每个输入被同一行的 \(N\) 个单元依次使用，每个权重被全部 \(M\) 个 token 使用，中间结果从不离开阵列。按“每搬一个数做几次乘加”算，是 \(N^2/(2N) = N/2\)，和分块推导里 \(T\times T\) 块的 \(T/2\) 完全一样：脉动阵列就是用导线固定下来的分块。

第 4 步，利用率。最后一个 token（\(r = M-1\)）在第 \(M-1+2(N-1)\) 拍到达右下角单元，全部算完共需 \(M + 2N - 2\) 拍。有用的乘加 \(MN^2\) 次，阵列能提供 \(N^2(M+2N-2)\) 次：

\[ \text{利用率} = \frac{MN^2}{N^2\,(M + 2N - 2)} = \frac{M}{M + 2N - 2} \]

这里忽略了把新权重装进阵列的时间（约 \(N\) 拍），实际硬件用双缓冲在计算的同时装下一组权重。

第 5 步，代入。\(N = 128\)，单用户解码 \(M = 1\)：\(1/255\approx 0.4\%\)。\(M = 256\)：50%。\(M = 2048\)：89%。\(N\) 加大到 256，同样的 \(M = 2048\) 只有 80%。

这个推导告诉我们：阵列越大，复用越高（\(N/2\)），能效越好；但填充和排空的时间（\(2N-2\) 拍）也越长，要更大的批才能填满。TPU 把阵列从 128 加大到 256，单元数变成四倍、复用翻倍，代价是对小矩阵、小批量更不友好，而这正是解码最常见的形状。GPU 用很多个小张量核心加软件分块，在这一点上更灵活。

全片上存储（Groq、Cerebras）。既然解码受限于显存带宽，那就干脆不用显存。Groq 的第一代 LPU（14 纳米）把权重全部放在片上 SRAM 里：每颗 230 MB，带宽 80 TB/s，是 H100 显存的 24 倍；执行顺序完全由编译器静态排定，单用户的生成速度极快。代价是容量：放下一个 70B 模型要几百颗芯片。Cerebras 走得更远：整片晶圆做成一颗芯片，WSE-3 有 44 GB 片上 SRAM、约 90 万个核心、21 PB/s 的片上带宽。

2025 年 12 月，NVIDIA 与 Groq 达成技术授权和人才交易（据报道约 200 亿美元）。2026 年 3 月 NVIDIA 发布 Groq 3 LPX 机柜：256 颗 LPU，每颗 500 MB SRAM、150 TB/s，整柜 128 GB SRAM，8 月宣布全面量产。它与 Vera Rubin NVL72 配合的一种方式，是第 章讲的注意力与 FFN 分离（AFD），只不过两半放在了两种芯片上：解码时，注意力（要读每个用户各自的 KV 缓存，数据大、复用低）留在 GPU 上用 HBM 算；FFN 和 MoE 专家（所有用户共享同一份权重）放到 LPU 的 SRAM 上算；每层只交换一次中间激活。Google 2026 年 4 月发布的推理芯片 TPU 8i 也把片上 SRAM 提高到 384 MB（上一代的 3 倍）。用 Roofline 的话说：HBM 管容量，SRAM 管带宽，各自放最适合它的那部分数据。

推理会被专用芯片接管吗

专用派
推理的工作负载比训练简单、规模更大，专为它设计的芯片（TPU、Trainium、Groq、Cerebras、各种 ASIC）能效和成本都更好。Anthropic 在 2025 年 10 月宣布将使用多达 100 万颗 Google TPU；Google 在 2026 年第一次把 TPU 分成训练（8t）和推理（8i）两种芯片；据估算，NVIDIA 在数据中心加速器中的收入份额从 2023 年的九成以上降到 2026 年的八成左右。

模型结构每年都在变（混合注意力、MoE、新的低精度格式），专用芯片的设计周期跟不上；GPU 的软件生态（CUDA、各种内核库、推理框架）让新模型第一时间就能跑得好。NVIDIA 也在吸收专用设计的优点：把 Groq 的 LPU 做成 GPU 机柜旁边的协处理器。

推理本身在分化：预填充吃算力，解码的注意力吃 HBM 的带宽和容量，解码的 FFN 吃 SRAM 带宽。2026 年的趋势不是“专用芯片取代 GPU”，而是一个推理系统里同时有几种芯片、各管一段（第 章的预填充与解码分离是第一步）。大型模型公司普遍多种芯片并用；决定因素往往不是峰值算力，而是软件栈的成熟度和供应量。

互连：一个域里放多少卡

大模型一张卡放不下：一个 1 万亿参数的 MoE 用 FP8 存要 1 TB，H100 只有 80 GB。模型要切到很多张卡上（第 章的五种切分），卡之间就要不停地交换数据。卡与卡之间有两种网络：

  • 扩展域（scale-up domain）：用 NVLink（NVIDIA 的 GPU 间专用链路）和 NVLink 交换机连起来的一组 GPU，可以像读写自己的显存一样直接读写彼此的显存，每卡每秒几百 GB 到几 TB。H100 时代一个域是一台 8 卡服务器；GB200 NVL72 把一个机柜的 72 张卡连成一个域（整柜 130 TB/s）。TPU 用芯片间互连（ICI）组成环面，一个 Ironwood 集群 9216 颗芯片。
  • 横向扩展网络（scale-out network）：域与域之间用 InfiniBand 或以太网（RDMA）连接，每卡每秒 50–100 GB，延迟也高得多。

同一张卡，NVLink 比网卡快一个数量级。哪种切法放在哪种网络上，取决于它要多少通信、能不能被计算掩盖。最依赖带宽的是张量并行：

\[ \frac{t_{\text{通信}}}{t_{\text{计算}}} = \frac{(\htmlClass{sym-t}{t}-1)\,\htmlClass{sym-b}{b}\,\htmlClass{sym-P}{P}}{6\,\htmlClass{sym-d}{d}\,\htmlClass{sym-BW}{\text{BW}}} \]
张量并行把每层的矩阵乘法切到 \(t\) 张卡上，每层前向要做两次全规约。通信与计算之比只取决于卡数、硬件的“算力 ÷ 带宽”和模型宽度，和批大小、序列长度无关。
\(t\)
张量并行的卡数
\(b\)
激活值每个数的字节数（BF16 为 2）
\(P\)
每张卡的算力
\(d\)
模型的隐藏维度
\(\text{BW}\)
每张卡单方向的通信带宽
H100（BF16 峰值 989 TFLOPS），\(d = 8192\)，\(t = 8\)：走 NVLink（每方向 450 GB/s），\(7\times2\times989\times10^{12}/(6\times8192\times450\times10^9)\approx 0.63\)，通信可以和计算重叠、藏起来；换成 50 GB/s 的网卡是 5.6，通信是计算的 5 倍多。所以张量并行只在一个 NVLink 域里用。
张量并行与专家并行：通信占比由什么决定

张量并行，第 1 步，计算。一个 Transformer 层约有 \(12d^2\) 个权重：注意力的 Q、K、V、O 四个 \(d\times d\) 矩阵，加上 FFN 的约 \(8d^2\)。处理 \(m\) 个 token 的前向计算约 \(2\times 12d^2\times m = 24md^2\) 次运算，切到 \(t\) 张卡上，每张卡耗时 \(t_{\text{计算}} = 24md^2/(tP)\)。

第 2 步，通信。Megatron 式的张量并行，每层前向做两次全规约（注意力之后、FFN 之后各一次），每次的数据是 \(m\) 个 token 的激活，\(S = mdb\) 字节。用第 章的环形全规约公式，每次耗时 \(\frac{2(t-1)}{t}\cdot\frac{S}{\text{BW}}\)，两次合计 \(t_{\text{通信}} = \frac{4(t-1)\,mdb}{t\,\text{BW}}\)。

第 3 步，相除。\(m\) 和 \(1/t\) 都消掉了：

\[ \frac{t_{\text{通信}}}{t_{\text{计算}}} = \frac{4(t-1)\,mdb\,/\,(t\,\text{BW})}{24md^2\,/\,(tP)} = \frac{(t-1)\,b\,P}{6\,d\,\text{BW}} \]

批大小和序列长度都不出现：token 多了，计算和通信同比例增加。比值随卡数线性增长、随模型宽度 \(d\) 下降，系数是硬件的 \(P/\text{BW}\)。

专家并行，第 1 步，通信。MoE 层里每个 token 被路由到 \(k\) 个专家，这些专家多半在别的卡上。每个 token 要把 \(d\) 维的激活发给 \(k\) 个专家（分发，dispatch），算完再收回来（合并，combine），通信量 \(kd\,(b_1 + b_2)\) 字节，\(b_1\)、\(b_2\) 是两段各自的每数字节数。

第 2 步，计算。每个专家是一个 SwiGLU 小 FFN，三个 \(d\times d_e\) 的矩阵，每个 token 在每个专家上做 \(6dd_e\) 次运算，共 \(6kdd_e\)。负载均衡时，每张卡发出和收到的数据量相当：

\[ \frac{t_{\text{通信}}}{t_{\text{计算}}} = \frac{kd\,(b_1+b_2)\,/\,\text{BW}}{6kd\,d_e\,/\,P} = \frac{(b_1 + b_2)\,P}{6\,d_e\,\text{BW}} \]

这次连 \(k\) 和 \(d\) 都消掉了，只剩每个专家的中间维度 \(d_e\)。（这里假设所有专家都在别的卡上，是上限。）

第 3 步，代入 DeepSeek-V3。\(d_e = 2048\)，分发用 FP8（\(b_1 = 1\)）、合并用 BF16（\(b_2 = 2\)），H800 的 FP8 峰值约 1979 TFLOPS，跨机 InfiniBand 每卡 50 GB/s：\(3\times1979\times10^{12}/(6\times2048\times50\times10^9)\approx 9.7\)。走 NVLink（报告里的 160 GB/s）是 3.0。

这个推导告诉我们：张量并行的通信占比由“卡数 × 硬件的算力带宽比 ÷ 模型宽度”决定，所以它只能放在一个高速域里，而且切不了太多份；专家并行的占比由“算力带宽比 ÷ 专家宽度”决定，专家切得越细，越需要高带宽的域。两个比值都不随批大小改善，只能靠更快的链路、更大的域，或者把通信和计算重叠起来藏住。

专家并行的结论值得多看一眼：比值与专家个数、每个 token 激活几个专家、隐藏维度都无关，只和每个专家的中间维度 \(d_e\) 有关。细粒度专家（第 章）把 \(d_e\) 做小，通信相对计算就变重。DeepSeek-V3 的 \(d_e = 2048\)，在 H800 上跨机按峰值算比值约 9.7。他们的应对是一套组合：限制每个 token 最多发往 4 台机器，机内转发走 NVLink（160 GB/s，约为 InfiniBand 的 3.2 倍），用 132 个 SM 里的 20 个专门做通信，再让一批数据的通信和另一批的计算重叠。NVL72 让 72 张卡之间都走 NVLink，同样的专家并行不必跨网卡。这是“宽专家并行”（第 章）在 2025–26 年成为大规模 MoE 推理标配的硬件原因。

这也是“一个域里有多少卡”成为芯片竞争焦点的原因：域越大，越多的切分可以留在高速链路内。华为在单芯片落后的情况下把域做得更大：CloudMatrix 384（2025，384 颗昇腾 910C 用光互连连成一个域），计划中的 Atlas 950 SuperPoD 有 8192 颗昇腾 950DT；AWS 的 Trainium3 UltraServer 一个域 144 颗；Google 的 TPU 8t 一个超级集群 9600 颗。代价是功耗和故障域：一个 GB200 NVL72 机柜约 120 千瓦（据报道），必须液冷；域里任何一张卡出问题，都会拖累整个域上的任务。

V100（2017）：张量核心。卡在哪：Horowitz 估算，处理器执行一条指令的取指、译码、调度开销约 70 pJ，而一次运算只要几 pJ；用 SIMT 一对一对地做乘加，大部分能量花在“管理”上。改了什么：一条张量核心指令完成一个 \(4\times4\times4\) 的小矩阵乘加（64 次乘加），管理开销被分摊到几十次运算上，峰值从 FP32 的 15.7 TFLOPS 跳到 FP16 的 125 TFLOPS。代价：FP16 范围小，训练要做损失缩放；拐点从约 17 跳到 139，很多以前不在意的操作突然变成访存受限。引出：数据格式和数据通路成了瓶颈。

A100（2020）：换格式、改数据通路。卡在哪：FP16 训练容易溢出；原来的 FP32 代码用不上张量核心；数据要先从显存读进寄存器、再写进共享内存，寄存器不够用。改了什么：BF16（8 位指数，和 FP32 范围相同）；TF32（8 位指数、10 位尾数，FP32 代码不改一行就能用张量核心，156 TFLOPS，是普通 FP32 的 8 倍）；异步拷贝把数据从显存直接送进共享内存；L2 加大到 40 MB；2:4 结构化稀疏（每 4 个权重里恰好 2 个为零时，跳过零让算力账面翻倍）；MIG 把一张卡切成最多 7 个独立的小 GPU，给小模型推理用。代价：稀疏在大模型上几乎没人用（见演进史的支线）。引出：GPT-3 之后模型规模暴涨，算力需求先于带宽增长。

H100（2022）：FP8 和“搬运工”。卡在哪：每个 SM 的张量核心吞吐又翻倍，靠线程逐个算地址、搬数据已经喂不饱它。改了什么：FP8 与 Transformer Engine（根据每个张量最近的最大绝对值自动选缩放因子，逐层在 FP8 和 16 位之间选择）；TMA 让一个线程发一条指令就搬一整块；矩阵乘指令改成异步、直接从共享内存取数；线程块簇让最多 16 个 SM 互相读写共享内存；NVLink 到 900 GB/s。代价：编程复杂度陡增。FlashAttention-2 在 H100 上只能用到 35% 的算力，FlashAttention-3 用上异步和线程束分工后到 75%（740 TFLOPS）；FP8 的累加精度和缩放粒度也不够细（上文 DeepSeek-V3 的经历）。引出：更大的 MoE 和更低的精度。

B200 / GB200（2024–25）：两颗芯片、四位数、一个机柜。卡在哪：单颗芯片的面积已经接近光刻机一次曝光的上限（约 26 mm × 33 mm）；分块缩放只能在软件里补；万亿参数的 MoE 在 8 卡的域里放不下，专家并行要跨网卡。改了什么：两颗芯片封装成一个 GPU（2080 亿晶体管，芯片之间 10 TB/s）；FP4，以及张量核心内部的微缩放；每个 SM 加 256 KB 专放累加器的张量内存，把寄存器腾出来（分块推导里的容量约束）；两个 SM 合作做一次矩阵乘；NVLink 5 到 1.8 TB/s，NVL72 把域扩大到 72 卡。代价：整柜约 120 千瓦，必须液冷；BF16 算力涨了 2.3 倍、带宽涨了 2.4 倍，拐点没再升高，但解码依旧受带宽限制。

Rubin（2026）：带宽和异构。每卡 288 GB HBM4、22 TB/s（据报道，NVIDIA 把原定的约 13 TB/s 提高到了 22 TB/s），NVLink 6 每卡 3.6 TB/s，厂商公布的 NVFP4 推理算力 50 PFLOPS。2026 年 2 月出样，下半年开始量产交付。同一个平台第一次加入了非 GPU 的 LPX 机柜（上文）：光靠 HBM，解码的带宽不够，连 NVIDIA 自己的路线图也承认了这一点。

别家的取舍

同样的几个量，不同的公司押在不同的项上：

  • Google TPU：大脉动阵列，加上芯片间互连组成的巨大扩展域（Ironwood 一个集群 9216 颗，每颗 192 GB HBM3E、7.4 TB/s、FP8 4614 TFLOPS）。2026 年 4 月的第八代第一次分成两种芯片：训练用的 TPU 8t（一个超级集群 9600 颗）和推理用的 TPU 8i（288 GB HBM、384 MB SRAM，换用一种直径更小的网络拓扑来加速 MoE 的全对全通信）。代价是灵活性，软件主要经过 XLA（JAX、PyTorch/XLA）。
  • AWS Trainium：Trainium3（2025-12，3 纳米）每颗 FP8 2.52 PFLOPS、144 GB HBM3E、4.9 TB/s，一个 UltraServer 144 颗。走自研的 Neuron 软件栈，主要服务 AWS 自己和大客户。
  • 华为昇腾：单芯片落后，就把域做大（CloudMatrix 384、Atlas 950 SuperPoD）；昇腾 950 按预填充和解码分成两款（950PR：128 GB、1.6 TB/s；950DT：144 GB、4 TB/s），使用自研 HBM。出口管制的背景见第 章。
  • Groq、Cerebras：押在片上 SRAM 的带宽上，见上文「全片上存储」。

软件栈：从算法到指令

同一块芯片，软件写得好坏，性能可以差一倍以上（FlashAttention-2 和 -3 在 H100 上是 35% 对 75%）。从下往上，抽象程度一层层提高：

  • 线程级：CUDA（2006）。程序员写“一个线程做什么”，自己管理共享内存、同步、线程束的分工。新硬件的特性（TMA、异步矩阵乘、张量内存）最先只能在这一层用上；CUTLASS / CuTe 是 NVIDIA 在这一层提供的矩阵乘法模板库。
  • 分块级：分块级编程（tile-based programming）让人写“一个线程块对几个小块做什么”，线程映射、共享内存分配、流水线由编译器处理。代表是 OpenAI 的 Triton（2021），它让人用 Python 写内核，代码量比 CUDA 少一个数量级。2024–26 年又出现了一批：ThunderKittens、TileLang、CuTe DSL，以及 NVIDIA 在 CUDA 13.1（2025-12）里推出的 CUDA Tile（cuTile）。这一层通常能接近手写的性能，但对最新硬件特性的支持要慢一步。
  • 图级：深度学习编译器拿到整个计算图（整个模型的前向和反向），做算子融合、内存规划，再为目标硬件生成代码。XLA 是 JAX 和 TPU 的编译器；PyTorch 2.0（2023）的 torch.compile 默认用 TorchInductor 后端，把融合后的逐元素和归约操作生成 Triton 内核，矩阵乘法则默认调用 cuBLAS。TVM、MLIR 是更通用的编译器基础设施。
  • 库：cuBLAS（矩阵乘法）、cuDNN、NCCL（通信），以及 FlashAttention、DeepSeek 开源的 FlashMLA、DeepGEMM（FP8 矩阵乘法）、DeepEP（专家并行通信）等专用内核。

规律是：硬件的新特性先出现在最底层，库和手写内核先用上，分块语言随后追上，编译器最后才能自动用好。一个新架构从发布到软件栈“吃满”，往往要一两年。这正是下面这个争论的核心。

CUDA 的护城河还在吗

护城河派
近二十年积累的 CUDA 生态（库、工具、开发者、论文代码）是 NVIDIA 最大的优势：新模型、新算法几乎总是先在 CUDA 上实现和优化，其他硬件要追赶适配。新硬件特性先在 CUDA 这一层开放，也让 NVIDIA 的新卡总是最先被用满。
松动派
大多数开发者已经不直接写 CUDA，而是通过 PyTorch、编译器和 Triton 工作，这些层可以接到其他硬件上；Gemini、Claude 的大规模训练与推理已在 TPU 上进行；中国厂商在出口管制下建立了华为昇腾 CANN 等完整的替代栈，DeepSeek 等公司在国产芯片上部署前沿模型。
现在怎么看
对最大的几家公司，护城河已经变浅：它们有能力为多种硬件优化自己的软件栈。对中小团队和新算法的快速试验，CUDA 仍是阻力最小的路径。护城河从“只能用 CUDA”变成了“在 CUDA 上最省事”。

常见误解

  • TFLOPS 越高，生成越快。单用户的解码受显存带宽限制，算力大多闲着；生成速度主要看带宽和模型的字节数。
  • 显存越大越好。显存容量决定能放下多大的模型和多长的上下文，带宽才决定能跑多快；Apple 芯片显存大但带宽较低，大模型能放下但生成不快。
  • 不同芯片的 TOPS 可以直接比较。要看是稠密还是稀疏（稀疏数字通常是稠密的两倍）、什么精度（INT8 与 FP4 不可比），以及实际内核能达到多少。
  • 同样的计算量，耗时就一样。FlashAttention 与朴素注意力计算量相同，速度差几倍；决定速度的是数据搬运和复用。
  • TPU 只能跑 TensorFlow。JAX 和 PyTorch（通过 XLA）都能在 TPU 上运行，Gemini 和部分 Claude 模型都在 TPU 上训练和服务。

NVIDIA 推出 CUDA（2006），让 GPU 可以做通用计算；AlexNet（2012）用两块游戏显卡训练，赢得 ImageNet。
代价
GPU 原本为图形设计：每次乘加都要一条完整的指令，能量大多花在取指、译码和搬运操作数上。
引出
能否为矩阵乘法专门设计电路？
2016–2017

TPU 与张量核心：把矩阵乘法做成电路

卡在哪
深度学习的算力需求爆炸，通用 GPU 的指令开销让能效上不去。
怎么解决
Google TPU v1（2015 年投入使用，2017 年发表）用 \(256\times256\) 的 INT8 脉动阵列做推理；NVIDIA V100（2017）加入张量核心，一条指令做一块小矩阵乘加。
代价
只有矩阵乘法变快了，拐点陡升，其他操作相对变慢；FP16 训练需要损失缩放。
引出
数据格式和数据通路成为新的瓶颈。
被淘汰Nervana 与第一波深度学习专用芯片
Intel 2016 年收购 Nervana，打算做训练专用芯片；2019 年底又收购 Habana，2020 年初停掉了 Nervana 的产品线。早期专用芯片的共同问题是：硬件按当时的网络（卷积、LSTM）设计，等芯片做出来，模型已经变成 Transformer，软件栈也来不及成熟。留下的教训是：专用芯片要足够“通用于矩阵乘法”，还要有能跟上模型变化的编译器。
2020

A100：BF16、TF32 与异步拷贝

卡在哪
FP16 训练易溢出；FP32 代码用不上张量核心；数据要绕道寄存器才能进共享内存。
怎么解决
BF16 与 TF32；异步拷贝直达共享内存；40 MB 的 L2；2:4 结构化稀疏；MIG 切分。
代价
稀疏的账面算力很少兑现；带宽增长跟不上算力。
引出
Transformer 的规模化需要更低的精度和更聪明的数据搬运。
没成主流2:4 结构化稀疏
每 4 个权重里恰好 2 个为零，张量核心跳过零，算力翻倍。但把稠密模型剪成这种格式通常要再训练来恢复精度；在大语言模型上，同样的成本花在量化（第 章）和 MoE（第 章）上收益更大。它留下的痕迹是规格表上的“稀疏”算力：数字是稠密的两倍，比较芯片时要先除以 2。
2022–2023

H100、FlashAttention 与 Triton：“IO 感知”成为设计原则

卡在哪
大模型训练和推理越来越受显存带宽与通信限制；张量核心翻倍后靠线程搬数据喂不饱。
怎么解决
H100 引入 FP8、Transformer Engine、TMA 与线程块簇；FlashAttention（2022）把“减少显存读写”变成算法设计的核心原则；Triton（2021）降低内核开发门槛。
代价
要用满新硬件，内核越来越难写；GPU 供不应求，成为大模型发展的瓶颈。
引出
继续压低精度，扩大互连域。
仍在发展Triton 与分块级语言
Triton 证明了一个折中：不写线程级代码，也能接近手写内核的性能。TorchInductor 把它当作默认的 GPU 代码生成后端；2024–26 年 ThunderKittens、TileLang、CuTe DSL、CUDA Tile 沿着同一方向发展。它也给了其他硬件一个切入点：Triton 内核可以编译到 AMD 等不止一种 GPU 上。
2024–2025

FP4、机柜级互连与专用芯片崛起

卡在哪
万亿参数的 MoE 需要更多显存、更快的通信；推理成本成为主要开支。
怎么解决
Blackwell 的双芯片、原生 FP4 与 NVL72 机柜；TPU Ironwood 专为推理设计；DeepSeek 在 H800 上用限制路由、通信与计算重叠等办法把专家并行做到大规模，并开源 FP8 内核与通信库；Groq、Cerebras 的高速推理云；NVIDIA 与 Groq 的交易。
代价
功耗与散热成为数据中心的硬约束（单机柜上百千瓦）。
引出
解码仍然卡在带宽上；多种硬件并存，软件栈的可移植性变得关键。
在出口管制下发展国产 AI 芯片与超节点
美国对高端 GPU 的出口管制（第 章）促使中国厂商加速自研：华为昇腾（CANN 软件栈）、百度昆仑、阿里平头哥等。华为的策略是用更大的扩展域弥补单芯片的差距：CloudMatrix 384（2025）、Atlas 950 SuperPoD（8192 颗）；2026 年的昇腾 950 使用自研 HBM。
2026

HBM4、SRAM 层与异构推理

卡在哪
算力增长远快于带宽，解码的访存成为主要瓶颈。
怎么解决
HBM4 把单卡带宽推到约 22 TB/s；NVIDIA 的 LPX 用 SRAM 承担解码里的 FFN（注意力与 FFN 分离）；Google 把 TPU 分成训练和推理两种芯片，8i 的 SRAM 加到 384 MB；昇腾 950 按预填充和解码分成两款。
代价
系统复杂度转移到调度软件上；芯片、HBM、先进封装和电力的供应链成为 AI 发展的硬约束（第 章）。
引出
在给定硬件上，怎样用更少的位数表示模型？（第 章）
被淘汰Graphcore IPU：早了几年的“权重放在片上”
Graphcore 的 IPU（2020 年的 GC200：7 纳米、1472 个核心、900 MB 片上存储）比 Groq 更早押注片上存储。它赶上的却是模型从几亿参数涨到几千亿参数的那几年：900 MB 很快装不下一个模型，访问片外存储又要经过网关芯片。2024 年 7 月被软银收购（据报道约 5 亿美元，远低于约 28 亿美元的峰值估值）。2026 年 SRAM 以另一种形式回来：不是一颗芯片装下模型，而是几百颗芯片组成机柜级的 SRAM 池，只负责解码里最吃带宽的那部分。
争论解码该放在 HBM 还是 SRAM
SRAM 派：解码每生成一个 token 都要把权重读一遍，带宽就是速度；LPU 的 150 TB/s 对 Rubin 的 22 TB/s，差 7 倍。HBM 派：SRAM 每 GB 贵得多、占面积，128 GB 的 SRAM 要 256 颗芯片；长上下文的 KV 缓存动辄几百 GB，只能放在 HBM 里。2026 年的折中是注意力与 FFN 分离，两种存储各放最适合的数据。这个折中在大规模部署中能否在成本上胜过“只用 GPU”，还要看实际数据。

自测

1. 一块芯片的峰值算力 2000 TFLOPS、带宽 8 TB/s，拐点算术强度是多少？单用户用 BF16 解码一个 70B 稠密模型，每个 token 至少要多长时间？
拐点 \(2000/8 = 250\) FLOPs/字节。权重 140 GB，每个 token 至少读一遍：\(140/8000\approx 17.5\) ms，即最多约 57 token/s，与算力无关。
2. 解码时把 64 个用户的请求拼成一批，算术强度大约提高到多少？在上题的芯片上，这时是访存受限还是计算受限？
每读一次权重服务 64 个 token，强度从约 1 提高到约 64（BF16 下 \(I\approx 2m/b = m\)）。仍低于拐点 250，仍是访存受限，但吞吐量提高了约 64 倍。批大小超过约 250 才会转为计算受限。
3. 用分块矩阵乘法，FP8（每数 1 字节）下要达到 H100 FP8 的拐点（约 590 FLOPs/字节），分块边长 \(T\) 至少要多大？一个 SM 放得下吗？
强度 \(= T/b = T\)，需要 \(T\ge 590\) 左右（以数为单位）。这么大的 FP32 累加器要 \(590^2\times 4\approx 1.4\) MB，远超一个 SM 256 KB 的寄存器。按平方根定律，单个 SM 撑不起这个强度，实际依靠 L2 缓存、线程块簇里多个 SM 共享读入来进一步提高复用。
4. 张量并行：H100（BF16 989 TFLOPS），\(d = 8192\)，切 8 张卡。分别走 NVLink（每方向 450 GB/s）和 InfiniBand（50 GB/s），通信与计算之比是多少？换成 B200（2.25 PFLOPS）和 NVLink 5（每方向 900 GB/s），这个比值变大还是变小？
按 \((t-1)bP/(6d\,\text{BW})\)：NVLink 上 \(7\times2\times989\times10^{12}/(6\times8192\times450\times10^{9})\approx 0.63\)；InfiniBand 上约 5.6。B200 + NVLink 5：\(7\times2\times2.25\times10^{15}/(6\times8192\times900\times10^9)\approx 0.71\)，略微变大：算力涨了 2.3 倍，链路只涨了 2 倍。NVIDIA 让 NVLink 和算力大致同步增长，所以这个比值几代都在 1 附近；即使在 NVL72 里，张量并行通常也只切到 8 卡左右，更大的域主要留给专家并行。
