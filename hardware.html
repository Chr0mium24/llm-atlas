芯片、内核与编译器：算力为什么常常用不满

前面讲的 FlashAttention、MLA、MoE 的专家并行、FP4，最后都要落到芯片上。这一章先拆开一块 GPU，看它的计算单元和存储层次；然后用 Roofline 模型解释一个贯穿全书的现象：大模型的很多计算其实在“等数据”而不是“算数据”；接着讲分块矩阵乘法、低精度为什么能翻倍算力、TPU 的脉动阵列和全 SRAM 芯片的思路；最后是把算法变成指令的软件栈，以及 2026 年的芯片格局。

第 章的 FlashAttention 说明了一个事实：计算量完全相同，只换一个顺序，就能快好几倍。瓶颈不在算力，而在数据搬运。理解这一点，需要看清硬件是怎样组织的。

拆开一块 GPU

GPU 的设计目标是吞吐量：同时做海量相同的简单运算，而不是像 CPU 那样尽快完成一串复杂的指令。以 NVIDIA H100 为例：

  • 计算单元：132 个流式多处理器（SM），每个包含若干普通的 CUDA 核心和 4 个张量核心。张量核心是专门做小矩阵乘加（如 \(16\times 8\times 16\)）的电路，一个时钟周期完成上千次乘加，大模型几乎全部的算力都来自它。BF16 稠密算力约 989 TFLOPS，FP8 翻倍。
  • 存储层次：每个 SM 有寄存器和约 228 KB 的共享内存（片上 SRAM，极快但极小）；全芯片共享 50 MB 的 L2 缓存；芯片外紧挨着封装的是 80 GB 的 HBM（高带宽显存），带宽约 3.35 TB/s。越靠近计算单元越快、越小。
  • 互连：NVLink 把同一台机器（或同一个机柜）里的 GPU 高速连起来，H100 每卡 900 GB/s；跨机柜用 InfiniBand 或以太网，慢一个数量级以上。

关键的数字是两个“速度”的比：H100 每秒能做约 \(10^{15}\) 次运算，却只能从显存读 \(3.35\times 10^{12}\) 字节。每读一个字节，必须做约 300 次运算，才能让计算单元不闲着。大模型的很多环节远达不到这个比例。

Roofline：算得快还是搬得快

判断一段计算受限于算力还是带宽，看它的算术强度：每从显存读写一个字节，做多少次运算。Roofline 模型把它画成一条“屋顶线”：

\[ \text{可达到的性能} = \min\Big(\htmlClass{sym-P}{P_{\text{峰值}}},\ \ \htmlClass{sym-I}{I}\times \htmlClass{sym-BW}{\text{BW}}\Big),\qquad I = \frac{\text{FLOPs}}{\text{读写的字节数}} \]
算术强度低时，性能等于“强度 × 带宽”，随强度线性上升，叫访存受限；强度超过拐点 \(P/\text{BW}\) 后，性能封顶于峰值算力，叫计算受限。
\(P_{\text{峰值}}\)
芯片的峰值算力（FLOPS）
\(\text{BW}\)
显存带宽（字节 / 秒）
\(I\)
这段计算的算术强度（FLOPs / 字节）
H100 的拐点：\(989\times 10^{12}/3.35\times 10^{12}\approx 295\) FLOPs/字节。生成时单个用户每步要读出全部权重，每个 BF16 权重（2 字节）只参与一次乘加（2 FLOPs），强度约 1，只能用到峰值算力的约 0.3%。一个 8B 模型用 FP8 存储（8 GB），每生成一个 token 至少要读 8 GB，速度上限约 \(3.35\text{ TB/s}/8\text{ GB}\approx 420\) token/s，无论算力多强。

这解释了推理系统的许多设计（第 章）：预填充（一次处理整个提示，几千个 token 共用一次权重读取）强度高、计算受限；解码（一次生成一个 token）强度低、访存受限，所以要把很多用户的请求拼成一批，让一次权重读取服务 \(B\) 个 token，强度约提高到 \(B\)。量化（第 章）减少要读的字节数，在访存受限时几乎直接换来同比例的加速。下面的估算器把这些因素放在一起：

意外：芯片的算力涨得比“喂数据”的速度快得多

原以为
每一代新芯片算力翻倍，模型就能跑快一倍。
实际发现
Gholami 等（2024）统计了二十年的硬件：峰值算力约每 2 年增长 3 倍，显存带宽只增长约 1.6 倍，芯片间互连约 1.4 倍。二十年间算力增长了约 6 万倍，显存带宽只增长了约 100 倍。这就是“内存墙”。
为什么
晶体管变小让计算电路越来越便宜，但把数据送到芯片的引脚数、信号速率和封装面积增长慢得多。HBM 把显存堆叠在芯片旁边，已经是为了带宽付出的高昂代价。
现在怎么看
算术强度低的操作（解码、注意力、归一化、逐元素运算）的占比越来越重要。软件上的对策是提高数据复用（分块、算子融合、FlashAttention）、减少数据量（量化、MLA）；硬件上的对策是更大的片上存储（下文的 Groq、Cerebras）和更快的 HBM（2026 年的 HBM4）。

分块：怎样让矩阵乘法达到峰值

矩阵乘法是少数能达到峰值的运算，因为它天然有数据复用：\(n\times n\) 的矩阵相乘做 \(n^3\) 次乘加，却只需读 \(2n^2\) 个数。但要真正兑现这种复用，必须让读进来的数据在片上被反复使用，而不是用一次就丢、下次再从显存读。办法是分块：

\[ I_{\text{分块}} = \frac{2n^3}{\big(2n^3/\htmlClass{sym-T}{T}\big)\times b} = \frac{\htmlClass{c-new}{T}}{b} \]
一次在片上计算输出矩阵的一个 \(T\times T\) 区域：沿着内积方向，每读入 A 的一列小块和 B 的一行小块，就做 \(T^2\) 次乘加，结果一直留在片上累加。每个读入的数被用了 \(T\) 次，总读入量从 \(2n^3\) 降到 \(2n^3/T\)，算术强度与 \(T\) 成正比。
\(T\)
分块边长，受片上存储容量限制
\(b\)
每个数的字节数
不分块（\(T = 1\)，每次乘加都从显存读两个数）：BF16 下强度只有 0.5，H100 只能用到峰值的约 0.2%。\(T = 128\)：强度 64；再加上 L2 缓存和多个 SM 之间的复用，实际的大矩阵乘法能达到峰值的 70–80%。

这就是高性能内核的核心技艺：选择分块大小、安排数据在寄存器、共享内存、L2 之间的流动，让张量核心不断有数据可算，同时用异步拷贝把下一块数据的读取与当前块的计算重叠起来。FlashAttention 是同一个思路在注意力上的应用；把多个小操作合并成一个内核（算子融合），避免中间结果写回显存，也是同一个原则。

低精度：为什么位数减半，算力翻倍

H100 的 FP8 算力是 BF16 的 2 倍；Blackwell（B200）又加入 FP4，算力再翻倍；2026 年的 Rubin 宣称单卡 FP4 推理算力 50 PFLOPS。为什么位数越少，算力越高？

\[ \text{乘法器面积} \ \propto\ (\htmlClass{sym-m}{m} + 1)^2 \]
浮点乘法的主体是两个尾数相乘，硬件上是一个 \((m+1)\times(m+1)\) 位的整数乘法器（\(m\) 位尾数加上隐含的 1），面积和功耗大约与位数的平方成正比。同样的芯片面积，位数越少，能放的乘法器越多。
\(m\)
尾数位数：BF16 为 7，FP8（E4M3）为 3，FP4（E2M1）为 1
BF16 的乘法器约 \(8^2 = 64\) 单位面积，FP8 约 \(4^2 = 16\)，FP4 约 \(2^2 = 4\)。理论上同面积可多放 4 倍、16 倍的乘法器。实际芯片只给出 2 倍、4 倍的提升，因为累加器（通常保持较高精度）、数据通路和寄存器文件也占面积，而且带宽同样要跟上。

低精度的代价是表示范围和精度。2024 年后的方案是“微缩放”格式（MXFP4、NVFP4）：每 16 或 32 个数共享一个缩放因子，用很少的位数存储每个数，同时保留足够的动态范围。怎样让模型在低精度下不掉点，是第 章的主题。

另外几种芯片设计

脉动阵列（TPU）。Google 的 TPU 用脉动阵列做矩阵乘法：一个 \(128\times 128\)（新一代为 \(256\times 256\)）的乘加单元网格，权重预先放进每个单元，输入数据像脉搏一样一拍一拍地从一侧流入，部分和沿着另一个方向流动累加。每个数据在阵列中被相邻单元依次使用，几乎不需要读写寄存器或缓存，能效极高，代价是灵活性：只擅长规整的大矩阵乘法。GPU 则用 SIMT（单指令多线程）加张量核心，更通用、编程生态更成熟。

全片上存储（Groq、Cerebras）。既然解码受限于显存带宽，那就干脆不用显存。Groq 的 LPU 把模型权重全部放在片上 SRAM 中（每颗芯片数百 MB），带宽高出 HBM 一个数量级，执行完全确定，单用户的生成速度极快；代价是一颗芯片放不下多少参数，一个大模型要用数百颗芯片。Cerebras 走得更远：整片晶圆做成一颗芯片（WSE-3 有 44 GB 片上 SRAM、约 90 万个核心）。2025 年底 NVIDIA 与 Groq 达成授权和人才交易，2026 年的 Vera Rubin 平台据报道纳入了基于 Groq 技术的推理芯片，说明“低延迟解码”已被视为一个独立的硬件市场。

推理会被专用芯片接管吗

专用派
推理的工作负载比训练简单得多、规模更大，专为它设计的芯片（TPU、Trainium、Groq、Cerebras、各种 ASIC）能效和成本都更好。Anthropic 在 2025 年 10 月宣布将使用多达 100 万颗 Google TPU；据估算，NVIDIA 在数据中心加速器中的收入份额从 2023 年的九成以上降到 2026 年的八成左右。
通用派
模型结构每年都在变（混合注意力、MoE、新的低精度格式），专用芯片的设计周期跟不上；GPU 的软件生态（CUDA、各种内核库、推理框架）让新模型第一时间就能跑得好。NVIDIA 也在吸收专用设计的优点（纳入 Groq 技术、推出面向长上下文预填充的专门芯片）。
现在怎么看
大型模型公司普遍走向多种芯片并用：用 GPU 做研究和训练的主力，用 TPU、Trainium 或自研芯片承担大规模推理。决定因素往往不是峰值算力，而是软件栈的成熟度和供应量。

互连。大模型一张卡放不下，张量并行和专家并行（第 章）要求卡之间频繁、大量地交换数据。NVIDIA 的 NVL72 机柜用 NVLink 把 72 张 GPU 连成一个高速域；TPU 用芯片间互连组成三维环面，一个 Ironwood 集群可达 9216 颗芯片。“一个高速域里能放多少芯片”，决定了能多高效地运行万亿参数的 MoE。

软件栈：从算法到指令

同一块芯片，软件写得好坏，性能可以差几倍。从上到下：

  • 框架：PyTorch、JAX 让研究者用张量运算写模型。
  • 编译器：XLA（JAX 和 TPU 的编译器）、PyTorch 的 torch.compile 把整个计算图拿到手，做算子融合、内存规划，再为目标硬件生成代码；TVM、MLIR 是更通用的编译器基础设施。
  • 内核语言：CUDA 是 NVIDIA GPU 的底层编程模型，需要手动管理线程、共享内存和同步；CUTLASS 提供矩阵乘法的模板库；Triton（OpenAI, 2021）让人用 Python 以“分块”为单位写内核，由编译器处理线程级细节，大大降低了门槛。2024–26 年又出现了一批分块级的编程模型（ThunderKittens、TileLang、CuTe DSL，以及 NVIDIA 自己的 CUDA Tile）。
  • 库与框架：cuBLAS、cuDNN、NCCL（通信），以及 FlashAttention、DeepSeek 开源的 FlashMLA、DeepGEMM（FP8 矩阵乘法）、DeepEP（专家并行通信）等专用内核。

CUDA 的护城河还在吗

护城河派
近二十年积累的 CUDA 生态（库、工具、开发者、论文代码）是 NVIDIA 最大的优势：新模型、新算法几乎总是先在 CUDA 上实现和优化，其他硬件要追赶适配。
松动派
大多数开发者已经不直接写 CUDA，而是通过 PyTorch、编译器和 Triton 工作，这些层可以接到其他硬件上；Gemini、Claude 的大规模训练与推理已在 TPU 上进行；中国厂商在出口管制下建立了华为昇腾 CANN 等完整的替代栈，DeepSeek 等公司在国产芯片上部署前沿模型。
现在怎么看
对最大的几家公司，护城河已经变浅：它们有能力为多种硬件优化自己的软件栈。对中小团队和新算法的快速试验，CUDA 仍是阻力最小的路径。护城河从“只能用 CUDA”变成了“在 CUDA 上最省事”。

常见误解

  • TFLOPS 越高，生成越快。单用户的解码受显存带宽限制，算力大多闲着；生成速度主要看带宽和模型的字节数。
  • 显存越大越好。显存容量决定能放下多大的模型和多长的上下文，带宽才决定能跑多快；Apple 芯片显存大但带宽较低，大模型能放下但生成不快。
  • 不同芯片的 TOPS 可以直接比较。要看是稠密还是稀疏（稀疏数字通常翻倍）、什么精度（INT8 与 FP4 不可比），以及实际内核能达到多少。
  • 同样的计算量，耗时就一样。FlashAttention 与朴素注意力计算量相同，速度差几倍；决定速度的是数据搬运和复用。
  • TPU 只能跑 TensorFlow。JAX 和 PyTorch（通过 XLA）都能在 TPU 上运行，Gemini 和部分 Claude 模型都在 TPU 上训练和服务。

自测

1. 一块芯片的峰值算力 2000 TFLOPS、带宽 8 TB/s，拐点算术强度是多少？单用户用 BF16 解码一个 70B 稠密模型，每个 token 至少要多长时间？
拐点 \(2000/8 = 250\) FLOPs/字节。权重 140 GB，每个 token 至少读一遍：\(140/8000\approx 17.5\) ms，即最多约 57 token/s，与算力无关。
2. 解码时把 64 个用户的请求拼成一批，算术强度大约提高到多少？在上题的芯片上，这时是访存受限还是计算受限？
每读一次权重服务 64 个 token，强度从约 1 提高到约 64（BF16 下每字节约 64 FLOPs）。仍低于拐点 250，仍是访存受限，但吞吐量提高了约 64 倍。批大小超过约 250 才会转为计算受限。
3. 用分块矩阵乘法，FP8（每数 1 字节）下要达到 H100 FP8 的拐点（约 590 FLOPs/字节），分块边长 \(T\) 至少要多大？
强度 \(= T/b = T\)，需要 \(T\ge 590\) 左右（以数为单位）。单个 SM 的片上存储放不下这么大的块，实际依靠 L2 缓存和多个 SM 共享读入的数据来进一步提高复用。
