第 8 章 · 效率

长上下文：KV cache、FlashAttention 与线性注意力

2023 年主流模型的上下文是 4K–8K token，2026 年的 Kimi K3、DeepSeek V4 是 1M。智能体要读整个代码仓库、几百轮工具调用记录、几小时的视频，都需要很长的上下文。障碍有两个：注意力计算是 O(n²)，生成时要缓存的 K/V 随长度线性增长。

KV cache：生成时最占显存的东西

自回归生成时，第 t 步的新 token 要和前面所有 token 做注意力。前面 token 的 K、V 每一步都一样，没必要重算，就缓存下来，这就是 KV cache。它的大小：

KV 字节数 / token = 2 (K 和 V) × 层数 L × KV 头数 × 头维度 × 每个数的字节数Llama 3 70B（80 层，8 个 KV 头，头维度 128，BF16）：每 token 320 KB；128K 上下文 ≈ 40 GB，单个请求就要这么多

减小 KV cache 的思路有四类：减少 KV 头（MQA、GQA）、压缩到低维（MLA）、只存最近的（滑动窗口）、换成固定大小的状态（线性注意力 / SSM）。2025–26 年的模型通常把几种组合起来，比如 Kimi K3 用 69 层 KDA 线性注意力加 24 层 Gated MLA。

  • MQA（2019）：所有 Q 头共享 1 组 K/V。省得最多，但质量有损。
  • GQA（2023）：Q 头分组，每组共享一组 K/V（如 64 个 Q 头配 8 个 KV 头）。现在的默认选择。
  • MLA（DeepSeek-V2, 2024）：把 K/V 压到一个 512 维的潜向量（另加 64 维给 RoPE），计算时再升维。缓存很小，效果却不比 MHA 差。DeepSeek-V3/V4、Kimi K2/K3 都在用。
  • 滑动窗口 / 局部-全局交替：大部分层只看最近 w 个 token，少数层看全部（Gemma 3 是 5:1）。
  • KV cache 量化：把 K/V 存成 FP8 或 4-bit（第 9 章）。llama.cpp 的 --cache-type-k q4_0 就是这个。

FlashAttention：计算一样，只是换个顺序

朴素实现会把 n×n 的分数矩阵完整写进显存（HBM），再读出来做 softmax，再读出来乘 V。GPU 的瓶颈往往不在算力，而在 显存读写。FlashAttention（2022）把 Q、K、V 切成小块，放进片上 SRAM 里算完，n×n 矩阵从不写回显存。难点在 softmax 需要整行的最大值和总和。办法是 在线 softmax：一边扫描一边维护当前最大值 m 和归一化因子 l，遇到更大的值时，把之前累积的结果乘一个修正系数。

FlashAttention 的结果和朴素实现在数学上完全一致，不是近似，只是让注意力的显存从 O(n²) 降到 O(n)，速度提升 2–4 倍。FA2（2023）改进了并行划分，FA3（2024）针对 Hopper 的异步与 FP8，2025 年后的 FA4 和各家的 Blackwell 内核继续沿这个方向优化。Ring Attention / 上下文并行 把同一个序列切到多张卡上，K/V 块在卡之间环形传递，用来训练百万级上下文。

线性注意力：把历史压进固定大小的状态

softmax 注意力相当于一个 只增不减的记忆：每个 token 的 K/V 都原样保存，查询时逐一比对。线性注意力 去掉 softmax，把记忆变成一个固定大小的矩阵 S（dk×dv），每来一个 token 就写进去：

线性注意力：St = St−1 + vtktᵀ　　DeltaNet：St = St−1 + βt(vt − St−1kt)ktᵀ　　读取：ot = Stqt Gated DeltaNet 再乘一个衰减 αt；Kimi Delta Attention（KDA）把 α 变成逐通道的 Diag(αt)，可以分别控制每个维度的遗忘

这样每步生成的代价是常数，显存也是常数，像 RNN 一样。问题是固定大小的矩阵 容量有限：存的东西一多就会互相干扰。Delta rule 的改进是，写入前先读出当前存的值，只写“差值”，相当于覆盖而不是叠加；门控 / 衰减 则让模型主动遗忘不再需要的旧信息。下面的演示把 N 对随机的 (key, value) 依次写进 d×d 的状态，再逐个查询，看能取回多少：

纯线性注意力在“精确回忆”（比如从长文中找出某个电话号码）上始终不如 softmax 注意力。所以 2025–26 年的主流做法是 混合：大部分层用线性注意力（便宜，负责局部和摘要），每隔几层插一层全注意力（负责精确检索）。Qwen3-Next、Kimi Linear 用约 3:1，Kimi K3 是 69:24。Kimi 报告称在百万 token 下 KV cache 减少约 75%，解码吞吐最高提升约 6 倍。

另一条路线是 稀疏注意力：保留 softmax，但每个 query 只看挑出来的 top-k 个 token。DeepSeek V3.2 的 DSA 用一个轻量的“闪电索引器”给所有 token 快速打分再选 top-k；V4 的 CSA 先把每 4 个 token 的 KV 压成 1 条再做稀疏选择，HCA 压得更狠但保持稠密注意力。据其报告，百万上下文时 V4-Pro 的单 token 推理 FLOPs 只有 V3.2 的 27%，KV cache 只有 10%。

长上下文真的“用得上”吗

标称上下文长度不等于有效长度。大海捞针（needle in a haystack）只测单点检索，太简单；RULER、多跳推理、长文档问答等更难的测试显示，很多模型在标称长度的一半处就明显退化（俗称 “context rot”）。工程上，智能体系统会配合 上下文工程：压缩历史、外部记忆、检索、子智能体分工，不把所有东西都塞进上下文。
