混合专家（MoE）：参数很多，每次只用一小部分

2026 年的前沿开源模型几乎都是 MoE：Kimi K3 总参数 2.8 万亿，每个 token 只激活 1040 亿；DeepSeek V4-Pro 是 1.6 万亿总参数、490 亿激活。MoE 让模型的容量（能存多少知识）和每个 token 的计算量不再绑在一起。这一章讲 MoE 的结构、路由器怎样选专家、为什么负载均衡这么难、细粒度专家与共享专家，以及一个常被讲错的问题：专家们到底在分工什么。最后是 MoE 给部署带来的特殊问题，和 2026 年出现的另一种“稀疏”。

第二部分说过，损失随参数量和算力按幂律下降，第三部分的模型越做越强也越来越大。但每个 token 的计算量直接决定训练成本和推理速度。能不能让参数继续增加，而每个 token 的计算量不变？这是第四部分的第一个结构性改进。

  • softmax、top-k：第 、 章
  • 规模定律、总参数与激活参数：第 章

把一个大 MLP 拆成很多个专家

第 章讲过，MLP 占了 Transformer 约三分之二的参数，而且每个 token 独立计算，可以看成一张巨大的键值记忆表。混合专家（Mixture of Experts, MoE）把一个大 MLP 换成 \(E\) 个小 MLP，每个叫一个专家，再加一个很小的路由器：每个 token 进来时，路由器给每个专家打分，只把它送给得分最高的 \(k\) 个专家，输出按门控权重加权求和：

\[ \mathbf y = \sum_{i\,\in\,\htmlClass{c-new}{\operatorname{TopK}(\mathbf g)}} \htmlClass{sym-g}{g_i(\mathbf x)}\ \htmlClass{sym-Ei}{\operatorname{Expert}_i(\mathbf x)},\qquad \mathbf g(\mathbf x) = \operatorname{softmax}\big(\mathbf x\,\htmlClass{sym-Wr}{W_r}\big) \]
路由器是一个 \(d\times E\) 的线性层，给 \(E\) 个专家各打一个分。只有分数最高的 \(k\) 个专家被计算，其余 \(E-k\) 个完全不参与。参数量约是 \(E\) 个专家的总和，每个 token 的计算量约是 \(k\) 个专家。
\(W_r\)
路由器的权重，\(d\times E\)，参数量相对专家可以忽略
\(g_i\)
第 \(i\) 个专家的门控权重（被选中的几个通常再归一化为和 1）
\(\operatorname{Expert}_i\)
第 \(i\) 个专家，就是一个普通的（通常较小的）SwiGLU MLP
DeepSeek-V3：每层 256 个路由专家选 8 个，外加 1 个所有 token 都走的共享专家。总参数 6710 亿，每个 token 激活 370 亿，约 5.5%。它的单 token 计算量接近一个 37B 的稠密模型，知识容量却接近一个大得多的模型。

为什么要这样？第 章的规模定律说参数越多损失越低，但稠密模型的计算量与参数量成正比。MoE 的规模定律研究（Clark 等, 2022；Krajewski 等, 2024；Apple 的 Abnar 等, 2025）发现，在相同的训练算力下，MoE 能达到明显更低的损失，而且模型越大，最优的稀疏度越高：激活参数占比越来越小。这就是为什么 2024 年以后的前沿模型从 8 选 2 一路走到几百选十几。

负载均衡：最难的工程问题

路由器是和模型一起训练的，它很容易“偏心”：某几个专家早期表现稍好，就被分到更多 token，于是学得更好，又被分到更多 token。最终少数专家被挤爆，其余专家几乎收不到 token、得不到训练，叫路由坍缩。分布式训练时，每个专家在每张卡上还有固定的容量上限，超出的 token 会被直接丢弃（只走残差连接）。所以必须让负载尽量均匀。经典做法是加一个辅助损失（Switch Transformer, 2021）：

\[ \mathcal L_{\text{aux}} = \alpha\cdot E\sum_{i=1}^{E} \htmlClass{sym-f}{f_i}\,\htmlClass{sym-P}{P_i} \]
\(f_i\) 是实际被分给专家 \(i\) 的 token 比例，\(P_i\) 是路由器给专家 \(i\) 的平均概率。两者都均匀（都等于 \(1/E\)）时，求和项最小，乘以 \(E\) 后为 1；负载越集中，这一项越大。
\(f_i\)
这一批 token 中被分给专家 \(i\) 的比例（离散的计数，不可导）
\(P_i\)
路由器给专家 \(i\) 的平均概率（可导，梯度通过它传给路由器）
\(E = 4\)。均匀时 \(4\times 4\times(0.25\times 0.25) = 1\)。若 \(f = (0.7, 0.1, 0.1, 0.1)\)，\(P = (0.6, 0.13, 0.13, 0.14)\)：\(4\times(0.42 + 0.013 + 0.013 + 0.014) = 1.84\)。梯度会压低专家 1 的概率 \(P_1\)，因为它乘的 \(f_1\) 最大。

辅助损失的问题是它与主任务目标冲突：为了均衡，路由器被迫把一些 token 送给并不合适的专家。\(\alpha\) 太小压不住坍缩，太大又伤害模型质量。DeepSeek-V3（2024-12）提出无辅助损失的均衡：给每个专家一个偏置 \(b_i\)，只在“选哪几个专家”时加到分数上，不参与加权求和；每一步训练后，负载过高的专家把偏置调低，过低的调高。这样均衡完全不经过梯度，不干扰主目标。下面的模拟器演示这个方法：

2026 年的 Kimi K3 进一步在潜空间里做路由（Stable LatentMoE），用分位数均衡，并把超出容量的 token“软丢弃”而不是硬丢弃。

细粒度专家与共享专家

DeepSeekMoE（2024）提出了两个后来被普遍采用的设计：

\[ \binom{16}{2} = 120 \qquad\longrightarrow\qquad \binom{64}{8} \approx \htmlClass{c-new}{4.4\times 10^9} \]
细粒度专家：把每个专家切成更小的几份，专家数和每次选择的个数同比例增加。总参数和计算量都不变，但可能的专家组合数从 120 种暴增到 44 亿种，每个 token 能得到更精确的“定制组合”。
16 个专家选 2 个，切成每份四分之一大小：64 个小专家选 8 个。每个 token 计算的专家总参数量与原来相同。2024 年后的模型普遍采用细粒度设计：DeepSeek-V3 256 选 8，Kimi K2 384 选 8，Qwen3-Next 512 选 10，Kimi K3 896 选 16。

共享专家：另设一两个所有 token 都会经过的专家，负责通用的知识和模式（语法、常见词），这样每个路由专家就不必各自重复学一遍这些通用内容，可以更专注。

专家们到底在分工什么

“混合专家”这个名字容易让人想象：一个专家管数学，一个管历史，一个管代码。事实远没有这么清晰，而且这个问题在 2025–26 年有了不少新的研究。

MoE 的专家是“领域专家”吗

早期观察
Mixtral（2023）的论文专门检查过：没有发现按主题（数学、生物、哲学）分配专家的明显规律，专家更多按语法和 token 类型分工，比如 Python 中的 self、缩进、某些标点总被送给同一个专家。这让“领域专家”的想象破灭，“专家只是 token 级的分工”成了流行说法。
2026 年的新证据
“The Expert Strikes Back”（ICML 2026）发现，细粒度 MoE 的专家比稠密模型 MLP 中的神经元单义性更强：它们既不是“生物学”这样的大领域专家，也不只是处理某类 token，而是细粒度的任务专家，比如专门负责闭合 LaTeX 的括号。另有几项研究发现，存在一小组与领域无关、承担大部分路由的“核心专家”，外围只有少数专家对领域敏感；按语言分工的专家确实存在。MoE Lens 发现，在 DeepSeekMoE 中，权重最高的那一个专家基本决定了下一个 token。
反方
“专家专门化的神话”（2026）认为，所谓的专门化只是隐藏状态几何结构的反映：路由器把向量空间中相近的 token 送到同一个专家，这不等于专家拥有某种领域专长；早期研究用的输入太短（不到 100 token），结论不可靠。
现在怎么看
“数学专家、历史专家”的想象不对，“专家只是 token 级分工”也过于简单。更准确的说法是：细粒度 MoE 的专家形成了细粒度、相对可解释的功能分工，外加一组通用的核心专家。Mixtral 分工不明显，可能因为它是从稠密模型“改造”来的（每个专家初始化成同一个 MLP 的副本）。这些分工也有实际用处：只微调与任务相关的专家（ESFT, 2024），效果接近全参数微调而代价小得多。

MoE 在参数层面分工，第 章的多教师蒸馏（MOPD）在训练流程层面分工，两者可以互相对照：一个让同一个模型内部的不同参数负责不同的事，一个让不同的老师模型负责不同的领域，最后合进一个学生。

部署：省计算，不一定省显存

MoE 带来一个关键的不对称：显存要装下全部参数，但每个 token 的计算只与激活参数有关。一个 671B 的 MoE 模型，每个 token 的计算量相当于 37B 的稠密模型，显存却要能放下 671B 个参数（第 章的量化在这里格外重要：Kimi K3 的专家权重用 MXFP4 存储，因为专家占了绝大部分参数）。

更微妙的是批大小的影响。单个 token 只用 \(k\) 个专家，可一批 token 加起来，几乎会用到所有专家：

\[ \text{被用到的专家比例} = 1 - \Big(1 - \frac{\htmlClass{sym-k}{k}}{\htmlClass{sym-E}{E}}\Big)^{\htmlClass{sym-B}{B}} \]
每个 token 不选某个专家的概率是 \(1 - k/E\)，\(B\) 个 token 都不选它的概率是这个数的 \(B\) 次方。批越大，没被用到的专家越少。
\(k\)
每个 token 选的专家数
\(E\)
专家总数
\(B\)
一批同时处理的 token 数
\(k = 8\)，\(E = 256\)：\(B = 1\) 时只用 3% 的专家；\(B = 64\) 时用到 \(1 - (31/32)^{64}\approx 87\%\)；\(B = 256\) 时超过 99%。

所以 MoE 在两种场景下的特性截然不同。服务端大批量推理时，所有专家都必须常驻显存，每步都要读，于是用专家并行把专家分散到许多张卡上，每层做两次全对全通信（把 token 发给专家所在的卡，再收回来），通信常常成为瓶颈（第 、 章）。本地单用户推理时，每个 token 只读少数专家，可以把大部分专家放在 CPU 内存里，只把注意力和共享部分放进显存；Apple 芯片的统一内存容量大、带宽够用，也很适合跑 MoE（第 章）。

2026：另一种稀疏

MoE 是“条件计算”：按输入选择算哪些参数。2026 年 1 月，DeepSeek 的 Engram 论文提出了另一个稀疏的维度，“条件记忆”：把第 章的 n-gram 思想现代化，为每个层建一张巨大的 n-gram 嵌入表，按当前位置前面的几个 token 直接查表（\(O(1)\) 的查找，不需要计算），再与隐藏状态融合。论文在总参数和计算量都相同的条件下，把一部分专家的参数挪给查找表，知识、推理、代码和长上下文检索都有提升，并发现了一条 U 形的规模定律：参数在“计算”（专家）和“记忆”（查找表）之间有一个最优分配。查找按 token 编号确定，可以提前预取，把 1000 亿参数的表放在 CPU 内存里只损失不到 3% 的速度。

同月，美团 LongCat 团队的研究得出类似结论：在高稀疏度下，扩大 n-gram 嵌入比增加专家更划算，但给嵌入的参数比例过高又会变差。这条线说明 MoE 的专家里有相当一部分容量在做“记住固定搭配”这类本可以查表完成的事。据第三方分析，DeepSeek V4 本身没有采用 Engram，它会不会进入下一代前沿模型还有待观察。

常见误解

  • MoE 的专家就是“数学专家”“代码专家”这样的领域专家。见上面的争议框：分工是细粒度的功能分工，不是学科分工。
  • 激活 37B 的 MoE，部署起来和 37B 的稠密模型一样省。计算量相近，但显存要放下全部 671B 参数；大批量时每步还要读几乎所有专家。
  • MoE 每次只用一个专家。Switch Transformer 是 top-1，现代模型通常每个 token 选 8–16 个，外加共享专家。
  • 专家越多越好。细粒度有收益，但专家太多会增加路由和通信开销、加剧负载均衡问题；最优稀疏度随模型规模变化。
  • MoE 只是工程技巧，不影响能力。在相同训练算力下，MoE 的损失明显更低，这是 2024 年后前沿模型普遍采用它的原因。

演进史

1991–2017

从专家混合到稀疏门控

卡在哪
一个网络要处理各种各样的输入，不同输入可能需要不同的处理方式。
怎么解决
Jacobs、Jordan 等（1991）提出专家混合：多个网络加一个门控网络。Shazeer 等（2017）在 LSTM 层之间加入稀疏门控的 MoE 层，只激活少数专家，训练出 1370 亿参数的模型。
代价
负载不均、训练不稳定、分布式实现复杂。
引出
能否和 Transformer 结合并扩展到更大规模？
2020–2022

MoE + Transformer：GShard 与 Switch

卡在哪
稠密模型的训练成本随参数线性增长。
怎么解决
GShard（2020）把 MoE 引入 Transformer，训练 6000 亿参数的翻译模型；Switch Transformer（2021）用 top-1 路由简化设计，达到 1.6 万亿参数；ST-MoE（2022）加入路由 z-loss 稳定训练。
代价
训练不稳定、微调困难，MoE 主要停留在谷歌内部。
引出
开源界能否用好 MoE？
未成主流专家选择 token、Soft MoE
“专家选择”路由（2022）让每个专家挑自己要处理的 token，天然均衡，但在自回归生成时会“偷看”同一批中后面的 token，不适合语言模型的推理。Soft MoE（2023）把 token 加权混合后送给专家，在视觉任务上效果好，同样不适用于因果生成。
2023–2024

开源 MoE：Mixtral 与 DeepSeekMoE

卡在哪
开源模型受限于算力，稠密模型做不大。
怎么解决
Mixtral 8×7B（2023-12）让开源 MoE 进入主流；DeepSeekMoE（2024-01）提出细粒度专家与共享专家；DeepSeek-V3（2024-12）以 671B / 37B、无辅助损失均衡和 FP8 训练，以很低的成本达到前沿水平。
代价
部署需要大量显存和复杂的专家并行。
引出
能做多大、多稀疏？
仍在使用从稠密模型“改造”出 MoE
把一个训练好的稠密模型的 MLP 复制成多个专家，再继续训练（2022 年提出）。省下从头训练的成本，但专家起点相同，分工往往不明显（Mixtral 可能就是这样）。
2025

超大、超稀疏

卡在哪
继续扩大知识容量，同时控制推理成本。
怎么解决
Kimi K2（1T / 32B，384 选 8）；Qwen3 MoE；Llama 4；gpt-oss 以 MXFP4 发布专家权重；Qwen3-Next（80B 总参数只激活约 3B）。
代价
通信与显存成为主要瓶颈；量化专家几乎成为必须。
引出
除了“条件计算”，还有别的稀疏方式吗？
2026

万亿级 MoE 与条件记忆

卡在哪
专家越来越多，路由和均衡越来越难；专家容量中有一部分在做“记忆”。
怎么解决
DeepSeek V4（1.6T / 49B）、Kimi K3（2.8T / 104B，896 选 16，潜空间路由）；Engram 与 n-gram 嵌入扩展提出“条件记忆”这一新的稀疏维度；专家专门化的可解释性研究给出更细致的图景。
代价
模型越来越依赖专门的推理系统和硬件。
引出
参数的问题解决了一部分，另一个瓶颈是序列长度：注意力的平方代价（第 章）。

自测

1. 一个 MoE 层有 64 个专家，每个专家参数量为 \(P\)，每个 token 选 4 个，另有 1 个共享专家。这一层的总参数和每个 token 激活的参数各是多少（忽略路由器）？
总参数 \(65P\)；激活参数 \(5P\)，约 7.7%。
2. 用 Switch 的辅助损失，\(E = 2\)，某批 token 中 \(f = (0.9, 0.1)\)，\(P = (0.8, 0.2)\)。\(E\sum f_iP_i\) 是多少？均匀时是多少？
\(2\times(0.72 + 0.02) = 1.48\)；均匀时 \(2\times(0.25 + 0.25) = 1\)。
3. Kimi K3 的设置为 896 选 16。单用户推理（\(B = 1\)）时每步用到多少比例的专家？批大小 128 时呢？
\(B = 1\)：\(16/896\approx 1.8\%\)。\(B = 128\)：\(1 - (1 - 16/896)^{128} = 1 - (0.98214)^{128}\approx 1 - 0.099 = 90\%\)。
