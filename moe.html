混合专家（MoE）：参数很多，每次只用一小部分

2026 年的前沿开源模型几乎都是 MoE：Kimi K3 总参数 2.8 万亿，每个 token 只激活 1040 亿；DeepSeek V4-Pro 是 1.6 万亿总参数、490 亿激活。MoE 让模型的容量（能存多少知识）和每个 token 的计算量不再绑在一起。这一章先用一个 4 个专家的玩具把路由手算一遍，再讲三个绕不开的问题：负载为什么会坍缩、怎样均衡（从辅助损失到“给专家定价”）、专家切多细才合适；然后是一个常被讲错的问题：专家们到底在分工什么；最后是专家并行的通信账、MoE 给部署带来的特殊问题，和 2026 年出现的另一种“稀疏”。

第二部分说过，损失随参数量和算力按幂律下降，第三部分的模型越做越强也越来越大。但每个 token 的计算量直接决定训练成本和推理速度。能不能让参数继续增加，而每个 token 的计算量不变？这是第四部分的第一个结构性改进。

把一个大 MLP 拆成很多个专家

第 章讲过，MLP 占了 Transformer 约三分之二的参数，而且每个 token 独立计算，可以看成一张巨大的键值记忆表。混合专家（Mixture of Experts, MoE）把一个大 MLP 换成 \(E\) 个小 MLP，每个叫一个专家，再加一个很小的路由器：每个 token 进来时，路由器给每个专家打分，只把它送给得分最高的 \(k\) 个专家，输出按门控权重加权求和：

\[ \mathbf y = \sum_{i\,\in\,\htmlClass{c-new}{\operatorname{TopK}(\mathbf g)}} \htmlClass{sym-g}{g_i(\mathbf x)}\ \htmlClass{sym-Ei}{\operatorname{Expert}_i(\mathbf x)},\qquad \mathbf g(\mathbf x) = \operatorname{softmax}\big(\mathbf x\,\htmlClass{sym-Wr}{W_r}\big) \]
路由器是一个 \(d\times E\) 的线性层，给 \(E\) 个专家各打一个分。只有分数最高的 \(k\) 个专家被计算，其余 \(E-k\) 个完全不参与。参数量约是 \(E\) 个专家的总和，每个 token 的计算量约是 \(k\) 个专家。

\(g_i\)

\(\operatorname{Expert}_i\)
第 \(i\) 个专家，就是一个普通的（通常较小的）SwiGLU MLP
DeepSeek-V3：每层 256 个路由专家选 8 个，外加 1 个所有 token 都走的共享专家。总参数 6710 亿，每个 token 激活 370 亿，约 5.5%。它的单 token 计算量接近一个 37B 的稠密模型，知识容量却接近一个大得多的模型。

为什么要这样？第 章的规模定律说参数越多损失越低，但稠密模型的计算量与参数量成正比。MoE 的规模定律研究发现，在相同的训练算力下，MoE 能达到明显更低的损失，而且模型越大，最优的稀疏度越高：激活参数占比越来越小（详见下面「规模定律」一节）。这就是为什么 2024 年以后的前沿模型从 8 选 2 一路走到几百选十几。

打分 → 选 top-k → 重新归一化

第一步，softmax 把分数变成概率：\(e^2\approx 7.39\)、\(e^1\approx 2.72\)、\(e^0 = 1\)，总和 12.11，所以每一行的概率都是 \((0.610,\ 0.225,\ 0.083,\ 0.083)\) 的某种排列。第二步，每个 token 只保留概率最高的 2 个专家。这种由 token 自己挑专家的方式叫 top-k 路由（token choice）。第三步，把留下的两个概率重新归一化成门控权重：

数负载：谁被挤爆了

把 12 次分配（6 个 token × 2）按专家数一数：专家 1 收到 5 次，专家 2、3 各 3 次，专家 4 只有 1 次。记专家 \(i\) 收到的分配比例为 \(f_i\)，6 个 token 给专家 \(i\) 的平均概率为 \(P_i\)：

\[ \begin{aligned} \mathbf f &= \tfrac{1}{12}(5,\ 3,\ 3,\ 1) = (0.417,\ 0.25,\ 0.25,\ 0.083) \\ \mathbf P &= (0.394,\ 0.218,\ 0.282,\ 0.106) \end{aligned} \] 完全均匀时两者都是 (0.25, 0.25, 0.25, 0.25)

\(f\) 是数出来的，\(P\) 是概率的平均。两者看起来差不多，但有一个本质区别：\(f\) 由“选谁”这个离散决定给出，参数稍微动一点，\(f\) 通常一点都不变；\(P\) 是参数的光滑函数，可以求导。「负载均衡」一节会用到这个区别。

容量：超出的 token 被丢掉

真实系统里，每个专家每批最多处理多少 token 要事先定好：输入缓冲区要预先分配；专家放在不同的卡上时，每张卡收发多少数据也要提前约定。这个上限叫容量，用容量因子（capacity factor）\(c\) 表示它是平均负载的几倍：

\[ \htmlClass{sym-C}{C} = \Big\lfloor \htmlClass{sym-c}{c}\cdot\frac{\htmlClass{sym-k}{k}\,\htmlClass{sym-T}{T}}{\htmlClass{sym-E}{E}} \Big\rfloor \]

玩具里取 \(c = 1.0\)：\(C = \lfloor 12/4\rfloor = 3\)。按 t1 到 t6 的顺序处理，专家 1 收下 t1、t2、t3 之后就满了，t4 和 t6 送来的那一份被丢掉：t4 只剩专家 4 那份（权重 0.269），t6 只剩专家 3 那份（0.731）。\(c = 1.5\) 时 \(C = 4\)，只丢 t6 那一份。

这种丢弃叫丢 token（token dropping）。被丢掉的那一份不经过任何专家，只靠残差连接把输入原样传下去。它不只是负载不均的后果：哪怕路由器对每个专家一视同仁，随机波动也会让某些专家超载。

随机路由也会丢 token：容量因子要留多少余量

第 1 步，负载的分布。假设路由完全随机且均匀：每次分配独立地以 \(1/E\) 的概率落到某个专家。一个专家收到的分配数 \(L\) 服从二项分布 \(\operatorname{Binomial}(kT,\ 1/E)\)，均值 \(\lambda = kT/E\)，\(E\) 大时方差约为 \(\lambda\)（近似泊松分布）。

第 2 步，相对波动。标准差除以均值是 \(\sqrt\lambda/\lambda = 1/\sqrt\lambda\)。每个专家平均分到的 token 越少，负载的相对波动越大。

第 3 步，丢弃比例。容量 \(C = c\lambda\)，丢掉的比例是超出部分的期望除以均值：

\[ \text{丢弃比例} = \frac{\mathbb E\big[(L - C)^+\big]}{\lambda},\qquad (x)^+ = \max(x, 0) \]

第 4 步，\(c = 1\) 的特例。用正态近似 \(L\approx\mathcal N(\lambda,\lambda)\)，\(\mathbb E[(L-\lambda)^+] = \sqrt\lambda\cdot\mathbb E[Z^+] = \sqrt{\lambda/2\pi}\)，于是丢弃比例 \(\approx 1/\sqrt{2\pi\lambda}\approx 0.4/\sqrt\lambda\)。容量恰好等于平均值时，总有约一半的专家超载。

第 5 步，代入数字（用二项分布精确计算）。\(\lambda = 8\)（例如一批 256 个 token、256 选 8）：\(c = 1.0\) 丢 13.9%，\(c = 1.25\) 丢 5.3%，\(c = 2\) 丢 0.08%。\(\lambda = 128\)（一批 4096 个 token）：\(c = 1.0\) 丢 3.5%，\(c = 1.25\) 只丢 0.01%，此时容量比均值高 \((c-1)\sqrt\lambda = 2.8\) 个标准差。

这个推导告诉我们：容量因子要盖住约 \(1/\sqrt\lambda\) 的随机波动，再加上路由器本身的偏心。每个专家分到的 token 越少（批小、专家多、切得细），需要的余量越大，而余量就是空转的算力和显存。所以后来的方向是不丢 token：MegaBlocks（2022-11）用块稀疏矩阵乘法处理不等长的专家输入，取消容量限制；DeepSeek-V3 训练和推理都不丢 token，前提是负载本身足够均匀。

参数账：总参数与激活参数

设每个专家有 \(P\) 个参数。玩具这一层存了 \(4P\) 个参数，每个 token 只用到 \(2P\) 个。每个 token 实际参与计算的参数叫激活参数（activated parameters）：它决定每个 token 的计算量（前向约 2 × 激活参数次运算）；总参数决定要占多少显存。和一个 \(2P\) 参数的稠密 MLP 相比，计算量相同，参数多了一倍。

放到 DeepSeek-V3 上算一遍：每个专家是中间维度 2048 的 SwiGLU，参数 \(3\times 7168\times 2048\approx 4400\) 万；58 个 MoE 层 × 256 个路由专家 ≈ 6540 亿，占全部 6710 亿参数的 97%。每个 token 在每层用 8 个路由专家加 1 个共享专家，58 层合计约 230 亿；再加上注意力、嵌入和前 3 层的稠密 MLP 约 140 亿，就是公布的 370 亿激活参数。真实模型里 \(E\) 是几百、\(k\) 是 8–16、一批有几千到几万个 token，但每一步的算法和玩具完全一样。下面把玩具一步步走一遍，最后一步预告了「无辅助损失均衡」一节的做法：

负载均衡：为什么会坍缩

玩具里专家 1 被挤爆，只是因为这一批 token 恰好偏爱它。训练中情况更糟，因为这种偏爱会自我强化：专家 1 收到更多 token，得到更多梯度更新，学得更快；它变得更好，路由器就更愿意选它；于是它收到更多 token。没被选中的专家既得不到 token，也得不到梯度，停在初始状态。最终少数专家被挤爆，其余专家几乎闲置，这叫路由坍缩。它同时伤害两件事：质量（大部分参数白白闲置，超载的专家还在丢 token）和速度（专家分布在不同的卡上时，每一步都要等最忙的那张卡）。

经典的对策是在损失里加一项负载均衡辅助损失（auxiliary load-balancing loss，Switch Transformer, 2021）：

\[ \mathcal L_{\text{aux}} = \htmlClass{sym-alpha}{\alpha}\cdot E\sum_{i=1}^{E} \htmlClass{sym-f}{f_i}\,\htmlClass{sym-P}{P_i} \]
\(f_i\) 是实际被分给专家 \(i\) 的比例，\(P_i\) 是路由器给专家 \(i\) 的平均概率。两者都均匀（都等于 \(1/E\)）时求和项最小，乘以 \(E\) 后为 1；负载越集中，这一项越大。
\(\alpha\)
辅助损失的系数，Switch 用 0.01
\(f_i\)
这一批分配中给了专家 \(i\) 的比例（离散的计数，不可导）
\(P_i\)
路由器给专家 \(i\) 的平均概率（可导，梯度通过它传给路由器）
玩具里 \(E = 4\)：\(4\times(0.417\times 0.394 + 0.25\times 0.218 + 0.25\times 0.282 + 0.083\times 0.106) = 1.19\)；完全均匀时是 \(4\times 4\times 0.25\times 0.25 = 1\)。
辅助损失：为什么乘的是 f·P，梯度往哪推

第 1 步，为什么不能只用 \(f\)。\(f_i\) 由 top-k 这个离散选择决定。参数稍微动一点，排名通常不变，\(f_i\) 也不变，所以它对参数是分段常数，几乎处处梯度为 0。

第 2 步，为什么不能只用 \(P\)。比如最小化 \(E\sum_i P_i^2\)。\(P\) 均匀不等于负载均匀。反例：每个 token 的概率都是 \((0.26, 0.25, 0.25, 0.24)\)，\(P\) 几乎完全均匀，\(E\sum P_i^2 \approx 1.0008\)；可如果 \(k = 1\)，所有 token 都去了专家 1。

第 3 步，乘起来。\(f\) 告诉我们“谁真的超载了”（当常数用，不求导），\(P\) 提供可导的把手。记 \(P_i = \frac1T\sum_t p_{t,i}\)，softmax 的导数是 \(\partial p_{t,i}/\partial z_{t,j} = p_{t,i}(\delta_{ij} - p_{t,j})\)。对 token \(t\) 的第 \(j\) 个 logit 求导：

\[ \begin{aligned} \frac{\partial \mathcal L_{\text{aux}}}{\partial z_{t,j}} &= \frac{\alpha E}{T}\sum_i f_i\,p_{t,i}\,(\delta_{ij}-p_{t,j}) \\ &= \frac{\alpha E}{T}\,p_{t,j}\,\big(f_j - \bar f_t\big),\qquad \bar f_t = \sum_i p_{t,i}\,f_i \end{aligned} \]

\(\bar f_t\) 是“这个 token 眼中的平均负载”。梯度下降沿负方向走：负载高于 \(\bar f_t\) 的专家，logit 被压低；低于的被抬高；力度还要乘上 \(p_{t,j}\)。

第 4 步，代入玩具。t1 的 \(p = (0.610, 0.225, 0.083, 0.083)\)，\(\bar f = 0.610\times0.417 + 0.225\times0.25 + 0.083\times0.25 + 0.083\times0.083 = 0.338\)。\(p_j(f_j - \bar f) = (+0.048,\ -0.020,\ -0.007,\ -0.021)\)：专家 1 被压低，其余三个被抬高，专家 4 和专家 2 抬得最多。上面第 2 步的反例里，\(\bar f = 0.26\)，专家 1 的那一项是 \(0.26\times 0.74 = 0.19\)，梯度很大，虽然损失值只有 1.04。

第 5 步，为什么均匀时最小。路由大致按概率走时 \(f\approx P\)，损失约为 \(E\sum_i P_i^2\)。由柯西–施瓦茨不等式，\(\sum_i P_i^2 \ge (\sum_i P_i)^2/E = 1/E\)，所以 \(E\sum_i P_i^2\ge 1\)，等号当且仅当所有 \(P_i = 1/E\)。另一方面，\(f\) 完全均匀时第 3 步的括号对每个 token 都是 0，梯度消失。

这个推导告诉我们：辅助损失借 \(P\) 把“负载”这个不可导的量，变成了作用在每个 token 的 logit 上的一股力。这股力与主任务无关：它压低超载专家在所有 token 上的分数，而且对最想去这个专家的 token（\(p_{t,j}\) 大）压得最狠。\(\alpha\) 太小压不住正反馈，太大就扭曲了路由器学到的偏好。下一节的方法正是为了绕开这一点。

无辅助损失均衡：给每个专家一个“价格”

DeepSeek-V3（2024-12）采用的无辅助损失均衡（auxiliary-loss-free load balancing）换了个思路：不改路由器的分数，只改“选谁”。

\[ \begin{aligned} S_t &= \operatorname{TopK}\big(\htmlClass{sym-s}{\mathbf s_t} + \htmlClass{c-clip}{\htmlClass{sym-b}{\mathbf b}},\ k\big),\qquad g_{t,i} = \frac{\htmlClass{sym-s}{s_{t,i}}}{\sum_{j\in S_t} s_{t,j}} \\ \htmlClass{sym-b}{b_i} &\leftarrow b_i + \htmlClass{sym-gamma}{\gamma}\cdot\operatorname{sign}\big(\htmlClass{sym-cbar}{\bar c} - \htmlClass{sym-ci}{c_i}\big) \end{aligned} \]

玩具里取 \(\mathbf b = (-0.6,\ 0,\ 0,\ +0.6)\)：t3 的分数变成 \((0.4, 2, 0, 0.6)\)，第二选择从专家 1 换成专家 4；t6 同理；其余 4 个 token 的选择不变。负载从 \((5, 3, 3, 1)\) 变成 \((3, 3, 3, 3)\)。门控仍按原来的概率算：t3 选中专家 2（0.610）和专家 4（0.083），权重 \(0.610/0.693 = 0.881\) 和 0.119。

偏置不经过梯度，所以主任务的梯度一点没变；它只改变了少数“边缘” token 的去向。Wang 等（2024-08）在 1B 和 3B 模型上对比：辅助损失法的验证困惑度为 9.56 / 7.97，最大超载（MaxVio，最忙专家比平均多出的比例）0.72 / 0.52；无辅助损失法的困惑度为 9.50 / 7.92，MaxVio 都是 0.04。DeepSeek-V3 另外只保留了一个系数 0.0001 的序列级辅助损失，防止单条序列内部极端不均。下面这个模拟器把镜头拉近到偏置这一个机制：初始路由器故意偏向前几个专家，看 token 怎样随偏置调整换到别的专家：

偏置为什么不扭曲梯度：它是专家的“价格”

第 1 步，把均衡写成分配问题。令 \(x_{t,i}\in\{0,1\}\) 表示 token \(t\) 是否分给专家 \(i\)。我们想要总分最高，同时每个 token 选 \(k\) 个、每个专家不超过容量 \(C\)：

\[ \max_{x}\ \sum_{t,i} x_{t,i}\,s_{t,i}\qquad\text{s.t.}\quad \sum_i x_{t,i} = k,\qquad \sum_t x_{t,i}\le C \]

第 2 步，给容量约束定价。给每个专家的容量约束一个拉格朗日乘子 \(\lambda_i\ge 0\)，可以理解为专家 \(i\) 的“价格”。把约束放进目标：

\[ \sum_{t,i} x_{t,i}\,\big(s_{t,i} - \lambda_i\big) + \sum_i \lambda_i C \]

价格固定时，第二项是常数，第一项对每个 token 独立：每个 token 各自选 \(s_{t,i} - \lambda_i\) 最大的 \(k\) 个专家。这正是 \(\operatorname{TopK}(\mathbf s_t + \mathbf b)\)，其中 \(b_i = -\lambda_i\)。

第 3 步，价格怎么调。对偶问题的次梯度是 \(c_i - C\)，所以价格沿 \(\lambda_i \leftarrow \lambda_i + \eta\,(c_i - C)\) 更新：超载的专家涨价，空闲的降价。DeepSeek 的规则 \(b_i \leftarrow b_i + \gamma\operatorname{sign}(\bar c - c_i)\) 是它只看方向、步长固定的版本。

第 4 步，控制论的视角。偏置把每一步的误差 \(\bar c - c_i\)（的符号）累加起来，是一个积分控制器。稳态时 \(b_i\) 不再漂移，意味着 \(\operatorname{sign}(\bar c - c_i)\) 的平均为 0：每个专家一半时间略超载、一半时间略空闲，负载在平均值附近小幅摆动。\(\gamma\) 大，追得快但摆得大；\(\gamma\) 小，摆得小但可能追不上主任务对分数的改变（演示里把 \(\gamma\) 调到 0.005 可以看到坍缩只被部分阻止）。DeepSeek-V3 在训练末期把 \(\gamma\) 设为 0，等于把价格冻结下来，推理时沿用。

第 5 步，为什么不扭曲梯度。门控 \(g\) 只用 \(s\)，不用 \(b\)；\(b\) 也不在损失里。所以损失对路由器参数的梯度里没有任何均衡项，\(s\) 仍然只反映“哪个专家对这个 token 更好”。价格只决定排在边缘的 token 去哪：加上价格后排名会翻转的，正是两个候选专家分数最接近、对它来说去哪都差不多的 token。辅助损失则对超载专家在所有 token 上的分数都施压。

这个推导告诉我们：无辅助损失均衡不只是一个技巧，它是“带容量约束的最优分配”的对偶解法。同一个视角也解释了后来的变体：Kimi K3（2026-07）的分位数均衡直接从这一批的分数分布里算出让每个专家恰好收到 \(kT/E\) 个 token 的那个价格，一步到位，而不是每步挪 \(\gamma\)；美团 LongCat-Flash（2025-09）用 PID 控制器调偏置，让每个 token 平均激活的参数量稳定在目标值附近。

专家数到了近千个，固定步长的偏置也开始吃力。Kimi K3 的报告说，896 个专家已经超出了这种更新方式表现良好的范围，于是改用上面推导末尾提到的分位数均衡：每一步把每个专家的偏置设成恰好让它收到目标数量 token 的分位数，分位数用全局批上的直方图估计，只需一次全规约。

均衡算在哪一批上，决定专家能不能专门化

发现
Qwen 团队（Qiu 等, 2025-01，ACL 2025）指出，常见实现在每个 micro-batch（一张卡一次前向处理的那几条序列）里统计 \(f_i\)。大模型训练时一个 micro-batch 往往只有几条序列，均衡几乎变成了“序列级”的：一段代码里的 token 也被要求平均分给所有专家，专家没法专攻代码。
证据
把 \(f_i\) 在整个全局批上汇总（多一次通信）后，3.4B、15B、43B 三个规模上困惑度和下游任务都变好：3.4B（激活 0.6B）模型的困惑度从 8.167 降到 8.038，MMLU 从 41.63 升到 43.48。出现了明显偏向特定领域的专家（如数学数据上的某些专家被选中的频率超过 0.2），micro-batch 均衡时没有一个超过 0.15。无辅助损失法同样是全局批版本更好。
解释
均衡约束的统计单位越小，约束越强。要求每条序列都均匀，等于禁止按内容分工。我们想要的是“在整个语料上每个专家都有活干”，不是“每段文字都用遍所有专家”。
现在怎么看
Qwen3 的 MoE 采用了全局批均衡；DeepSeek-V3 的偏置按全局批的负载更新，序列级损失的系数只有 0.0001。“均衡”要在速度（每一步每张卡的负载）和分工（语料级的偏好）之间取舍，统计的粒度就是那个旋钮。

路由器的数值稳定：z-loss

负载之外，大规模 MoE 还有一个特有的不稳定来源：路由器的 logit 会越长越大。softmax 对所有 logit 同加一个常数不变，主损失根本不管 logit 的整体大小；可 logit 一大，概率就接近独热，路由在两个专家之间来回突变。更直接的问题出在数值精度上：BF16 只有 7 位尾数（浮点数，），数值越大，相邻两个可表示数之间的间隔越大。ST-MoE（2022-02）的办法是加一项路由 z-loss：

\[ \mathcal L_z = \frac{\htmlClass{sym-cz}{c_z}}{T}\sum_{t=1}^{T}\Big(\htmlClass{sym-lse}{\log\sum_{j=1}^{E} e^{z_{t,j}}}\Big)^2 \]
对每个 token，把它全部路由 logit 的 log-sum-exp（大约等于其中最大的那个 logit）平方，再取平均。它几乎不管概率的形状，主要惩罚 logit 的整体大小。
\(c_z\)
系数，ST-MoE 用 0.001
\(\log\sum_j e^{z_{t,j}}\)
log-sum-exp，softmax 的归一化常数取对数
玩具里 t1 的 logit \((2, 1, 0, 0)\)：log-sum-exp = 2.49，平方 6.2。整体加 100 变成 \((102, 101, 100, 100)\)：softmax 完全不变，log-sum-exp = 102.49，平方约 1.05 万，z-loss 会把它们一起往下拉。
logit 大了为什么会出事，z-loss 怎样把它拉回来

第 1 步，精度。BF16 有 7 位尾数，指数为 \(e\) 时相邻可表示数的间隔是 \(2^{e-7}\)。logit 约为 2 时间隔 1/64，舍入误差最多 1/128，对应 \(e^z\) 的相对误差 \(e^{1/128}-1\approx 0.8\%\)；logit 约为 100 时间隔 0.5，舍入误差最多 0.25，\(e^z\) 的误差是 \(e^{0.25}-1\approx 28\%\)。同一个 softmax，整体平移之后，路由概率的噪声大了 30 多倍。

第 2 步，梯度。log-sum-exp 对 \(z_j\) 的导数正是 softmax：\(\partial \log\sum_i e^{z_i}/\partial z_j = p_j\)。记 \(\ell_t = \log\sum_j e^{z_{t,j}}\)，则

\[ \frac{\partial \mathcal L_z}{\partial z_{t,j}} = \frac{2c_z}{T}\,\ell_t\,p_{t,j} \]

第 3 步，这股力推向哪里。所有 logit 一起往下，最大的那个降得最多。沿“全体加同一个常数”的方向，它把 logit 拉到 \(\ell_t\approx 0\) 附近；这个方向上主损失本来就不管（softmax 不变），所以不和主任务冲突。在“拉开差距”的方向上它也有一点压力（\(p\) 大的降得多），让概率不至于过早变成独热。

第 4 步，代入玩具。t1：\(2\ell\,p = 2\times 2.49\times(0.610, 0.225, 0.083, 0.083) = (3.04,\ 1.12,\ 0.41,\ 0.41)\)，再乘 \(c_z/T\)。

这个推导告诉我们：路由器的不稳定，很大一部分是“softmax 的平移自由度 + 低精度”的组合问题。Switch 的办法是让路由器单独用 FP32 计算（选择性精度），ST-MoE 的办法是用 z-loss 消掉这个自由度，两者常一起使用。ST-MoE 用它稳定训练了 2690 亿参数的 ST-MoE-32B。规模再大，问题会换个地方出现：Kimi K3（2026-07）在 2.8 万亿参数上遇到专家内部激活值爆炸，在专家输出后加了 RMSNorm，并把 SwiGLU 换成两个因子都有上界的 SiTU-GLU。

细粒度专家与共享专家

DeepSeekMoE（2024-01）提出了两个后来被普遍采用的设计。第一个是细粒度专家：

\[ \binom{16}{2} = 120 \qquad\longrightarrow\qquad \binom{64}{8} \approx \htmlClass{c-new}{4.4\times 10^9} \]
细粒度专家：把每个专家切成更小的几份，专家数和每次选择的个数同比例增加。总参数和计算量都不变，但可能的专家组合数从 120 种暴增到 44 亿种，每个 token 能得到更精确的“定制组合”。
16 个专家选 2 个，切成每份四分之一大小：64 个小专家选 8 个。每个 token 计算的专家总参数量与原来相同。2024 年后的模型普遍采用细粒度设计：DeepSeek-V3 256 选 8，Kimi K2 384 选 8，Qwen3-Next 512 选 10，Kimi K3 896 选 16。

第二个是共享专家：另设一两个所有 token 都会经过的专家，负责通用的知识和模式（语法、常见词），这样每个路由专家就不必各自重复学一遍这些通用内容，可以更专注。共享专家不经过路由，也不参与负载均衡，在专家并行时可以放在每张卡本地计算。

这两个设计都不是免费的。细粒度的收益有上限（下一节），代价落在通信上：同样的激活参数切成更多份，每个 token 要发往的专家数 \(k\) 成比例增加，而全对全通信量与 \(k\) 成正比（「专家并行」一节）。共享专家要不要用，各家也不一致，见演进史里的支线。

规模定律：多稀疏、多细才合适

给定算力，MoE 应该多稀疏（总专家数与激活专家数之比 \(E/k\) 多大）、专家切多细？这一节的几项研究结论并不完全一致，分歧多半出在实验设定上。

先把“细”量化。Krajewski 等（2024-02）把粒度（granularity）定义为 \(G = d_{\text{ff}}/d_{\text{expert}}\)：标准 MLP 的中间维度除以单个专家的中间维度。\(G\) 增大时每个 token 选的专家数同比例增加，激活参数不变，正是 DeepSeekMoE 的细粒度切分。他们在第 章的规模定律里加入了粒度：

\[ \mathcal L(N, D, G) = c + \Big(\htmlClass{c-new}{\frac{\htmlClass{sym-gg}{g}}{G^{\htmlClass{sym-gamma2}{\gamma}}}} + a\Big)\frac{1}{\htmlClass{sym-N}{N}^{\alpha}} + \frac{b}{\htmlClass{sym-D}{D}^{\beta}} \]
和普通的规模定律一样有参数项和数据项，只是参数项的系数多了一块随粒度下降的部分 \(g/G^\gamma\)：切得越细，同样多的参数越“值钱”，但这部分收益按幂律递减。
\(N\)
参数量
\(D\)
训练 token 数
\(g\)
粒度能带来的最大改进幅度（拟合值 2.1）
\(\gamma\)
粒度收益衰减的指数（拟合值 0.58）
用论文拟合值（64 个专家，\(a = 18.1\)，\(\alpha = 0.115\)）：\(G\) 从 1 增到 8，系数从 \(2.1 + 18.1 = 20.2\) 变成 \(0.63 + 18.1 = 18.73\)，参数项小了 7.3%。要让 \(G = 1\) 的写法达到同样的参数项，参数量得乘 \((20.2/18.73)^{1/0.115}\approx 1.93\)。再从 8 增到 32，只多换来约 1.18 倍。

几项研究的结论可以归成三条：

  • 越大越该稀疏。Apple 的 Abnar 等（2025-01）在固定训练算力下发现，最优稀疏度随模型规模上升，对大模型趋近于 1（激活比例趋近于 0）。但在阅读理解（SQuAD、CoQA）这类任务上，同样预训练损失下更稠密的模型更好，他们推测原因是推理时每个 token 的计算更多。
  • 收益递减。Kimi K2（2025-07）固定激活参数、只增加专家总数：要达到同样的验证损失，稀疏度 48 比 8、16、32 分别省 1.69、1.39、1.15 倍算力。稀疏度每翻一倍大约省 20% 算力，显存和通信却按倍数涨。K2 最终选了 384 选 8。
  • 效率杠杆主要看激活比例。蚂蚁 Ling 团队（2025-07，ICLR 2026）定义效率杠杆（efficiency leverage, EL）：稠密模型要达到同样效果所需的算力，除以 MoE 所需的算力。300 多个模型（最大 28B）的实验显示，EL 主要由激活比例和训练总算力决定，两者都呈幂律；粒度只是一个非线性的调节项，在他们的定义下最优约为 8–12；共享专家留 1 个最好。按此设计的 Ling-mini-beta 只有 0.85B 激活参数，在 1T token 上追平了 6.1B 的稠密模型，算力省 7 倍以上。他们还发现 MoE 需要明显更大的批大小，因为每个专家只用到批里一部分 token 来更新。
细粒度为什么有效、为什么有上限

第 1 步，组合数。\(E\) 选 \(k\) 有 \(\binom{E}{k}\) 种组合，\(\log_2\binom{E}{k}\) 比特可以看成路由能为一个 token 写下的“地址”长度。16 选 2：120 种，6.9 比特；64 选 8：44 亿种，32 比特；256 选 8：\(4.1\times 10^{14}\)，48.5 比特；896 选 16：\(7.2\times 10^{33}\)，112 比特。\(E\gg k\) 时 \(\log_2\binom{E}{k}\approx k\log_2(eE/k)\)；粒度把 \(E\)、\(k\) 同乘 \(G\)，\(E/k\) 不变，地址长度大约随 \(G\) 线性增长。

第 2 步，为什么有用。一个 token 的输出是 \(k\) 个专家输出的加权和，等于为这个 token 临时拼出一个 MLP。组合越多，不同 token 能拿到的“定制 MLP”越多。16 选 2 只有 120 种拼法，大量不同的 token 只能共用同一种。

第 3 步，为什么递减。地址空间指数增长，可要学的东西受限于数据量和每个专家的学习量：每个专家只看到约 \(k/E\) 比例的 token（粒度变化时这个比例不变），单个专家却越来越小，越难单独学好一个功能。Krajewski 的拟合里收益按 \(G^{-0.58}\) 衰减，Ling 发现粒度存在最优区间。

第 4 步，代价。激活参数不变、粒度乘 \(G\)：\(k\to Gk\)，\(d_e\to d_e/G\)。每个 token 要发往的专家数、全对全通信量、路由排序的开销都乘 \(G\)；每个专家的矩阵变窄，矩阵乘法更碎，GPU 利用率下降。NVIDIA 的 LatentMoE（2026-01）从这里入手：先把 token 投影到更小的维度 \(\ell\) 再发给专家，通信和专家权重读取都乘 \(\ell/d\)，省下的预算用来把专家数和 \(k\) 一起放大 \(d/\ell\) 倍。Nemotron 3 Super 用 \(\ell = 1024\)、512 选 22；Kimi K3 用 \(\ell = d/2 = 3584\)、896 选 16。

这个推导告诉我们：细粒度买的是组合的多样性，付的是通信和碎片化。最优粒度是两者的平衡点：只看损失，它随算力上升（Krajewski 的表里从约 8 涨到 64）；算上部署成本，它又被往回拉。

MoE 的优势会随规模消失吗

主张
DeepMind 的 Clark 等（2022-02）用统一的规模定律拟合了三种路由算法，结论是路由的收益随基础模型变大而缩小：对表现最好的 S-BASE，稠密参数超过约 9370 亿后路由不再有帮助。他们的实用建议之一是“训练 13 亿参数以下的模型时用路由”。
反方
Krajewski 等（2024-02）指出，Clark 的所有模型不论大小都只训练了 1300 亿 token。让训练 token 数随算力一起优化之后，MoE 在所有规模上都优于稠密模型，而且差距随规模扩大：\(10^{20}\) FLOPs 时，计算最优的 MoE 相当于 20 倍算力的稠密模型，超过 \(10^{25}\) FLOPs 时超过 40 倍。Clark 的论文自己也写明，这个临界值“高度依赖训练 token 数”。
现在怎么看
2024 年后的前沿模型用实践回答了这个问题：激活比例从 Mixtral 的约 28% 降到 Kimi K3 的约 3.7%。争论转到了“稀疏到什么程度”：收益递减（K2 的数据）、部署成本（显存和通信），以及某些任务需要更多每 token 计算（Abnar），共同决定了今天几百选十几的格局。规模定律的结论依赖“训练多少 token”这类隐含设定，这一点和第 章 Kaplan 与 Chinchilla 的分歧如出一辙。

专家们到底在分工什么

“混合专家”这个名字容易让人想象：一个专家管数学，一个管历史，一个管代码。事实远没有这么清晰，而且这个问题在 2025–26 年有了不少新的研究。

MoE 的专家是“领域专家”吗

早期观察
Mixtral（2023）的论文专门检查过：没有发现按主题（数学、生物、哲学）分配专家的明显规律，专家更多按语法和 token 类型分工，比如 Python 中的 self、缩进、某些标点总被送给同一个专家。这让“领域专家”的想象破灭，“专家只是 token 级的分工”成了流行说法。
2026 年的新证据
“The Expert Strikes Back”（ICML 2026）发现，细粒度 MoE 的专家比稠密模型 MLP 中的神经元单义性更强：它们既不是“生物学”这样的大领域专家，也不只是处理某类 token，而是细粒度的任务专家，比如专门负责闭合 LaTeX 的括号。另有几项研究发现，存在一小组与领域无关、承担大部分路由的“核心专家”，外围只有少数专家对领域敏感；按语言分工的专家确实存在。MoE Lens 发现，在 DeepSeekMoE 中，权重最高的那一个专家基本决定了下一个 token。
反方
“专家专门化的神话”（2026）认为，所谓的专门化只是隐藏状态几何结构的反映：路由器把向量空间中相近的 token 送到同一个专家，这不等于专家拥有某种领域专长；早期研究用的输入太短（不到 100 token），结论不可靠。
现在怎么看
“数学专家、历史专家”的想象不对，“专家只是 token 级分工”也过于简单。更准确的说法是：细粒度 MoE 的专家形成了细粒度、相对可解释的功能分工，外加一组通用的核心专家。Mixtral 分工不明显，可能因为它是从稠密模型“改造”来的（每个专家初始化成同一个 MLP 的副本）。负载均衡的统计方式也会影响分工（见上面全局批均衡的争议框）。这些分工也有实际用处：只微调与任务相关的专家（ESFT, 2024），效果接近全参数微调而代价小得多。

MoE 在参数层面分工，第 章的多教师蒸馏（MOPD）在训练流程层面分工，两者可以互相对照：一个让同一个模型内部的不同参数负责不同的事，一个让不同的老师模型负责不同的领域，最后合进一个学生。

专家并行：token 要“出差”去找专家

一个 671B 的 MoE 放不进一张卡。最自然的切法是专家并行（expert parallelism, EP；第 章的并行方式之一）：注意力等稠密部分每张卡各放一份，按数据并行处理不同的 token；每层的专家分散到 \(G\) 张卡上，每张卡只放 \(E/G\) 个。一个 token 在哪张卡上，它选中的专家多半在别的卡上，所以每个 MoE 层要做两次全对全通信（all-to-all）：先把每个 token 的隐藏向量发到它选中的专家所在的卡（dispatch），专家算完再把结果发回原来的卡（combine）。和数据并行的全规约不同，全对全里每两张卡之间传多少数据都不一样，由这一步的路由结果决定。

\[ \begin{aligned} \text{每 token 每层的通信} &\approx \htmlClass{sym-k}{k}\,\htmlClass{sym-d}{d}\,(\htmlClass{sym-bb}{b_{\text{发}} + b_{\text{收}}}) \\ \frac{\text{专家计算}}{\text{通信}} &= \frac{k\cdot 6\,d\,d_e}{k\,d\,(b_{\text{发}}+b_{\text{收}})} = \frac{6\,\htmlClass{sym-de}{d_e}}{b_{\text{发}}+b_{\text{收}}} \end{aligned} \]
每个 token 的 \(d\) 维向量要发给 \(k\) 个专家、再收回 \(k\) 份结果。专家对它做的运算是 \(k\) 个 SwiGLU，每个前向 \(2\times 3\,d\,d_e\) 次。两者一除，\(k\) 和 \(d\) 都约掉了：每传一个字节能换来多少计算，只由专家的中间维度决定。
\(k\)
每个 token 选的专家数
\(d\)
隐藏维度
\(b_{\text{发}}, b_{\text{收}}\)
每个数的字节数。DeepSeek-V3 发出用 FP8（1 字节），收回用 BF16（2 字节）
\(d_e\)
专家的中间维度
DeepSeek-V3：\(d = 7168\)，\(k = 8\)，每 token 每层发收共 \(8\times 7168\times 3\approx 17.2\) 万字节（168 KiB）；计算 \(8\times 6\times 7168\times 2048\approx 7.0\) 亿次；比值 \(6\times 2048/3 = 4096\) FLOP/字节。一张 989 TFLOPS 的卡配 50 GB/s 的跨节点网络，要 \(989\times10^{12}/50\times10^{9}\approx 1.98\) 万 FLOP/字节才能让通信藏在计算后面，差了约 5 倍。

这正是 DeepSeek-V3 报告里说的：跨节点的专家并行让训练的“计算与通信之比约为 1:1”。他们的对策有三件。节点受限路由：每个 token 最多发往 4 个节点（按每个节点内得分最高的几个专家之和挑节点）；跨节点走 50 GB/s 的 IB，到了节点内再经 160 GB/s 的 NVLink 转发，同一节点上的几个专家只占一份 IB 流量。通信与计算重叠：DualPipe 调度让一部分 micro-batch 通信时，另一部分在计算。专用通信内核：只用 20 个 SM 就能跑满 IB 和 NVLink，后来开源为 DeepEP。推理时也一样：DeepSeek-V3 的解码阶段用 320 张卡做专家并行（第 章）。

通信、计算、读权重：各自怎样随批大小和粒度变化

第 1 步，通信。每张卡上有 \(n\) 个 token，每个发出 \(k\) 份 \(d\) 维向量，约 \(1 - 1/G\) 的比例去往别的卡。发出 \(n\,k\,d\,b_{\text{发}}(1-1/G)\) 字节，收回 \(n\,k\,d\,b_{\text{收}}(1-1/G)\) 字节。通信时间与 \(n\)、\(k\)、\(d\) 都成正比。

第 2 步，计算。平均而言，每张卡要算的分配数也是 \(n\,k\)，每份 \(6\,d\,d_e\) 次运算，计算时间与 \(n\,k\,d\,d_e\) 成正比。所以“计算 ÷ 通信” \(= 6d_e/(b_{\text{发}}+b_{\text{收}})\)，与 \(n\)、\(k\)、\(d\) 都无关。批再大，也改变不了通信相对计算有多贵。

第 3 步，读权重。每张卡放 \(E/G\) 个专家，每个 \(3\,d\,d_e\) 个参数，每一步都要从 HBM 把用到的专家读一遍。每个专家分到 \(\lambda = kT/E\) 个 token（\(T = Gn\) 是全组的 token 数），FP8 权重每读 1 字节做 \(2\lambda\) 次运算，这就是它的算术强度。H100 的 Roofline 拐点约为 \(989/3.35\approx 295\) FLOP/字节，对应 \(\lambda\approx 148\)。DeepSeek-V3 的 \(E/k = 32\)，所以整个专家并行组一步要凑够 \(148\times 32\approx 4700\) 个 token，专家才不再受显存带宽限制；同样条件下的稠密模型只要约 148 个。这就是 Ling 团队观察到“MoE 要更大批”的系统层面的原因。

第 4 步，粒度。激活参数不变、粒度乘 \(G\)：\(k\to Gk\)，\(d_e\to d_e/G\)。通信乘 \(G\)，计算不变，“计算 ÷ 通信”除以 \(G\)。潜空间路由把发出去的向量从 \(d\) 维压到 \(\ell\) 维，通信乘 \(\ell/d\)：Kimi K3 的 \(k\cdot\ell = 16\times 3584\)，恰好等于 DeepSeek-V3 的 \(k\cdot d = 8\times 7168\)。

这个推导告诉我们：专家并行的成本结构是“通信 \(\propto k\,d\)，计算 \(\propto k\,d\,d_e\)，读权重 \(\propto E\,d\,d_e\)”。增大批只能摊薄读权重的开销，摊不薄通信。要降通信，只能少发（节点受限路由）、发小（FP8、潜空间），或者藏起来（重叠）。这也是细粒度不能无限做下去的系统原因。

部署：省计算，不一定省显存

MoE 带来一个关键的不对称：显存要装下全部参数，但每个 token 的计算只与激活参数有关。一个 671B 的 MoE 模型，每个 token 的计算量相当于 37B 的稠密模型，显存却要能放下 671B 个参数（第 章的量化在这里格外重要：Kimi K3 的专家权重用 MXFP4 存储，因为专家占了绝大部分参数）。

更微妙的是批大小的影响。单个 token 只用 \(k\) 个专家，可一批 token 加起来，几乎会用到所有专家：

\[ \text{被用到的专家比例} = 1 - \Big(1 - \frac{\htmlClass{sym-k}{k}}{\htmlClass{sym-E}{E}}\Big)^{\htmlClass{sym-B}{B}} \]
每个 token 不选某个专家的概率是 \(1 - k/E\)，\(B\) 个 token 都不选它的概率是这个数的 \(B\) 次方。批越大，没被用到的专家越少。
\(k\)
每个 token 选的专家数
\(E\)
专家总数
\(B\)
一批同时处理的 token 数
\(k = 8\)，\(E = 256\)：\(B = 1\) 时只用 3% 的专家；\(B = 64\) 时用到 \(1 - (31/32)^{64}\approx 87\%\)；\(B = 256\) 时超过 99%。

所以 MoE 在两种场景下的特性截然不同。服务端大批量推理时，所有专家都必须常驻显存，每步都要读，于是用上一节的专家并行把专家分散到几十上百张卡上，通信常常成为瓶颈（第 、 章）。本地单用户推理时，每个 token 只读少数专家，可以把大部分专家放在 CPU 内存里，只把注意力和共享部分放进显存；Apple 芯片的统一内存容量大、带宽够用，也很适合跑 MoE（第 章）。

2026：另一种稀疏

MoE 是“条件计算”：按输入选择算哪些参数。2026 年 1 月，DeepSeek 的 Engram 论文提出了另一个稀疏的维度，条件记忆：把第 章的 n-gram 思想现代化，为每个层建一张巨大的 n-gram 嵌入表，按当前位置前面的几个 token 直接查表（\(O(1)\) 的查找，不需要计算），再与隐藏状态融合。论文在总参数和计算量都相同的条件下，把一部分专家的参数挪给查找表，知识、推理、代码和长上下文检索都有提升，并发现了一条 U 形的规模定律：参数在“计算”（专家）和“记忆”（查找表）之间有一个最优分配。查找按 token 编号确定，可以提前预取，把 1000 亿参数的表放在 CPU 内存里只损失不到 3% 的速度。

同月，美团 LongCat 团队的研究得出类似结论：在高稀疏度下，扩大 n-gram 嵌入比增加专家更划算，但给嵌入的参数比例过高又会变差。这条线说明 MoE 的专家里有相当一部分容量在做“记住固定搭配”这类本可以查表完成的事。据第三方分析，DeepSeek V4 本身没有采用 Engram，它会不会进入下一代前沿模型还有待观察。

常见误解

  • MoE 的专家就是“数学专家”“代码专家”这样的领域专家。见上面的争议框：分工是细粒度的功能分工，不是学科分工。
  • 激活 37B 的 MoE，部署起来和 37B 的稠密模型一样省。计算量相近，但显存要放下全部 671B 参数；大批量时每步还要读几乎所有专家，而且要凑够约 32 倍的批才能让专家不受显存带宽限制。
  • 专家越多、切得越细越好。收益递减：K2 的实验里稀疏度每翻一倍只省约 20% 算力；细粒度让每个 token 要发往的专家数成比例增加，通信随之上涨。最优稀疏度和粒度随模型规模和部署条件变化。
  • 负载越均衡越好，最好每一批、每条序列都均匀。速度需要每一步的负载均匀，但在太小的单位上强求均匀会阻止专家按内容分工。全局批均衡比 micro-batch 均衡效果更好（见“意外”框）。
  • MoE 只是工程技巧，不影响能力。在相同训练算力下，MoE 的损失明显更低（计算最优时相当于稠密模型 20 倍以上的算力），这是 2024 年后前沿模型普遍采用它的原因。

演进史

1991–2017

稀疏门控：让“只算一部分”在 GPU 上划算

卡在哪
Jacobs、Jordan 等（1991）早就提出“多个专家网络 + 门控网络”，但门控是稠密的，每个专家都要算。按样本走不同分支的条件计算，在擅长大块稠密矩阵乘的 GPU 上跑不快。
怎么解决
Shazeer 等（2017-01）的稀疏门控 MoE 层：带可学习噪声的 top-k 门控，只算选中的专家；把一批里去同一个专家的样本拼成一个大矩阵乘；再加两个平衡损失（按重要性、按负载）。插在 LSTM 层之间，做到 1370 亿参数。
代价
噪声项、两个平衡损失、分布式实现都很复杂；训练不稳定；只用在 LSTM 上。
引出
能不能放进 Transformer，并扩展到上千张芯片？
被淘汰不用学的路由：哈希层与 BASE
Hash Layers（Roller 等, 2021-06）按 token 编号的哈希值固定分配专家，天然均衡；BASE Layers（Lewis 等, 2021-03）把路由解成线性分配问题，强制每个专家收到同样多的 token。Clark 等（2022）的比较里，基于 BASE 的 S-BASE 表现最好，哈希最差。它们证明了“均衡可以由分配算法直接保证”，但哈希不看内容，精确分配又要在整批上求解，最终被“可学习的 top-k + 均衡机制”取代。DeepSeek 的偏置法可以看成这种分配思想的在线近似版本（见「偏置是专家的价格」推导）。

卡在哪

卡在哪

top-1 路由，通信和专家计算减半；辅助损失简化为 \(\alpha E\sum_i f_iP_i\)；容量因子 1.0–1.25；路由器单独用 FP32 计算。做到 1.6 万亿参数，预训练速度比同算力的 T5 快 7 倍。

2023-12 → 2024-01

Mixtral 与 DeepSeekMoE：开源、细粒度、共享专家

卡在哪
8 选 2 这样的粗专家组合太少，各专家还在重复学通用知识；开源界缺少好用的大 MoE。
怎么解决

能不能不靠辅助损失均衡，并在几百个专家上把通信控制住？
仍在使用从稠密模型“升级改造”出 MoE
升级改造（sparse upcycling, Komatsuzaki 等, 2022-12）把训练好的稠密模型的 MLP 复制成 \(E\) 份作为专家初始值，再加上路由器继续训练。论文报告只多花原预训练约 50% 的算力，就明显超过继续训练的稠密模型。代价是专家起点相同，分工要靠后续训练慢慢分化（Mixtral 分工不明显可能与此有关）；OLMoE（2024-09）发现，从零训练的同规模 MoE 在 5000 亿 token 后追上升级改造的版本，6000 亿 token 后反超。所以它适合预算有限、想复用旧模型的场景，不是前沿大模型的默认做法。
争论要不要共享专家
DeepSeekMoE 认为共享专家能减少路由专家之间的冗余，DeepSeek、Kimi 系列一直保留（K3 每层 2 个）。OLMoE（2024-09）的消融里，在 32 选 4 的设置下把一个专家改成共享专家，组合数从 35960 种降到 4495 种，效果略差。Qwen3（2025-04）的 MoE 去掉了共享专家，Qwen3-Next（2025-09）又加回 1 个；Ling 的规模定律实验建议保留 1 个。结论依赖规模和其它设定，目前多数大模型保留 1–2 个。
2024-12

DeepSeek-V3：无辅助损失均衡与节点受限路由

卡在哪

怎么解决

2025–2026

超稀疏、潜空间路由与条件记忆

卡在哪
稀疏度继续提高时，通信与 \(k\cdot d\) 成正比地上涨；近千个专家时固定步长的偏置更新不再可靠；专家容量中有一部分在做“记住固定搭配”。
怎么解决
Kimi K2（2025-07，384 选 8，1T / 32B）；Qwen3-Next（2025-09，512 选 10 + 1 共享，80B 只激活约 3B）；LatentMoE（NVIDIA, 2026-01）把发给专家的向量压到潜空间，省下的预算用来增加专家和 \(k\)；Kimi K3（2026-07，896 选 16，潜空间宽度 \(d/2\)，分位数均衡，2.8T / 104B）；Engram 把一部分参数挪给查找表。
代价
额外的投影矩阵和新的稳定性问题（K3 要加 RMSNorm 和有界激活函数）；模型越来越依赖专门的推理系统和超节点硬件。
引出
参数的问题解决了一部分，另一个瓶颈是序列长度：注意力的平方代价（第 章）。
分支每个 token 的计算量也可以变：零计算专家
美团 LongCat-Flash（2025-09，560B）在专家池里加入“零计算专家”：选中它就原样返回输入，不做任何计算。于是简单的 token 少算、难的 token 多算，每个 token 激活 186 亿到 313 亿参数，平均约 270 亿；平均值由一个 PID 控制器调节的偏置来稳住，和 DeepSeek 的偏置法同属“用价格控制负载”的思路。想法来自 MoE++（2024）。它还用跨层的捷径连接让上一层的稠密计算和本层的全对全通信重叠。

自测

1. 一个 MoE 层有 64 个专家，每个专家参数量为 \(P\)，每个 token 选 4 个，另有 1 个共享专家。这一层的总参数和每个 token 激活的参数各是多少（忽略路由器）？
总参数 \(65P\)；激活参数 \(5P\)，约 7.7%。
2. 用 Switch 的辅助损失，\(E = 2\)，某批 token 中 \(f = (0.9, 0.1)\)，\(P = (0.8, 0.2)\)。\(E\sum f_iP_i\) 是多少？均匀时是多少？对一个概率为 \((0.8, 0.2)\) 的 token，辅助损失的梯度会把两个 logit 往哪推？
\(2\times(0.72 + 0.02) = 1.48\)；均匀时 \(2\times(0.25 + 0.25) = 1\)。这个 token 眼中的平均负载 \(\bar f = 0.8\times 0.9 + 0.2\times 0.1 = 0.74\)。\(p_j(f_j-\bar f)\) 为 \(0.8\times 0.16 = +0.128\) 和 \(0.2\times(-0.64) = -0.128\)：梯度下降压低专家 1 的 logit、抬高专家 2 的。
3. 路由完全随机均匀，每个专家平均分到 \(\lambda = 32\) 次分配，容量因子取 1.0。用正态近似估计丢弃比例。要把丢弃降到 1% 以下，大致需要多大的容量因子？
\(c = 1\) 时丢弃比例 \(\approx 0.4/\sqrt{\lambda} = 0.4/5.66\approx 7\%\)（二项分布精确值 7.0%）。\(c = 1.25\) 时容量比均值高 \(0.25\times 32/\sqrt{32}\approx 1.4\) 个标准差，精确计算的丢弃约 0.7%，已经低于 1%。
4. Kimi K3 每个 token 选 16 个专家，比 DeepSeek-V3 多一倍，隐藏维度同为 7168。按同样的精度（发 FP8、收 BF16），它每 token 每层的全对全通信量是多少？为什么没有翻倍？
K3 的路由专家工作在宽度 \(\ell = 3584\) 的潜空间，发出去的是 3584 维的向量：\(16\times 3584\times 3 = 172032\) 字节，即 168 KiB，与 DeepSeek-V3 的 \(8\times 7168\times 3\) 完全相同。\(k\) 翻倍、每份宽度减半，通信量不变。
