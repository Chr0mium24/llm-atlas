注意力：每个位置都去“查”其它位置

2017 年的论文标题是《Attention Is All You Need》：去掉循环网络，只用注意力处理序列。注意力做的事情可以用一句话说清：每个位置发出一个“查询”，和所有位置的“标签”比较相关度，按相关度把各位置的“内容”加权平均，作为自己的新表示。这一章从它要解决的问题讲起，把这句话变成公式，逐步代入数字算一遍，再讲多头、因果掩码、训练出来的典型注意力模式，以及它的平方级代价。

上一章结束时，每个 token 都有了一个嵌入向量，但它们彼此独立：“它”不知道自己指的是谁，“bank”在“河岸”和“银行”两种句子里是同一个向量。需要一种机制，让每个位置根据上下文改写自己的表示。

注意力之前：循环网络的瓶颈

2017 年之前，处理序列的主力是循环神经网络（RNN，及其改进版 LSTM）：从左到右一个 token 一个 token 地读，每读一个，就用它更新一个固定大小的“记忆”向量：

\[ \htmlClass{sym-h}{\mathbf h_t} = \tanh\big(\htmlClass{sym-W}{W}\,\htmlClass{sym-h}{\mathbf h_{t-1}} + \htmlClass{sym-U}{U}\,\htmlClass{sym-x}{\mathbf x_t}\big) \]
新的记忆，由旧的记忆和当前 token 混合后经过一个非线性函数得到。整句话读完，所有信息都压在最后一个 \(\mathbf h\) 里。
\(\mathbf h_t\)
读完第 \(t\) 个 token 后的隐藏状态（记忆），大小固定
\(\mathbf x_t\)
第 \(t\) 个 token 的嵌入
\(W\)
记忆到记忆的权重矩阵，每一步共用
\(U\)
输入到记忆的权重矩阵

这个设计有三个问题：

  1. 信息瓶颈。一整句、一整段的信息都要挤进一个几百维的向量，前面的内容会被后面的冲淡。
  2. 不能并行。第 \(t\) 步依赖第 \(t-1\) 步的结果，训练时 GPU 只能一步步串行地算，序列越长越慢。
  3. 远距离信息传不过来。反向传播时，第 \(T\) 步的梯度要经过 \(T-1\) 次连乘才能到达第 1 步，每次乘一个雅可比矩阵，范数小于 1 就指数级衰减，叫梯度消失。LSTM 用门控缓解了它，但没有根治。

2014 年，Bahdanau 等人给机器翻译模型加了一个补丁：解码器每生成一个词，不再只看那个压缩过的向量，而是回头对输入句子的每一个位置算一个相关度，按相关度加权平均。这就是注意力。它让模型可以直接“看”到任意远的位置，瓶颈和远距离问题一起解决了。2017 年的 Transformer 把这个思路推到底：干脆去掉循环，序列内部也只用注意力，即自注意力（self-attention）。

Q、K、V：一次“软”的字典查询

普通的字典查询是精确匹配：给一个键，返回唯一对应的值。注意力把它变成软匹配：查询和每个键都算一个相似度，按相似度把所有值混合起来。每个 token 的向量 \(\mathbf x\) 乘上三个可学习的矩阵，得到三个角色不同的向量：

  • query \(\mathbf q = \mathbf x W_Q\)：我在找什么样的信息；
  • key \(\mathbf k = \mathbf x W_K\)：我这里有什么样的信息，供别人匹配；
  • value \(\mathbf v = \mathbf x W_V\)：如果被选中，我交出去的内容。

对位置 \(i\)，注意力的输出是：

\[ \htmlClass{sym-o}{\mathbf o_i} = \sum_{j} \htmlClass{c-adv}{\htmlClass{sym-a}{a_{ij}}}\, \htmlClass{c-dir}{\htmlClass{sym-v}{\mathbf v_j}},\qquad \htmlClass{sym-a}{a_{ij}} = \operatorname{softmax}_j\!\Big(\frac{\htmlClass{sym-q}{\mathbf q_i}\cdot \htmlClass{sym-k}{\mathbf k_j}}{\sqrt{\htmlClass{sym-dk}{d_k}}}\Big) \]
位置 \(i\) 拿自己的 query 和每个位置的 key 做点积，除以 \(\sqrt{d_k}\)，softmax 成和为 1 的权重，再用权重把所有位置的 value 加权平均。
\(\mathbf o_i\)
位置 \(i\) 的输出：它从上下文中收集到的信息
\(a_{ij}\)
注意力权重：位置 \(i\) 分给位置 \(j\) 多少注意力，对 \(j\) 求和为 1
\(\mathbf q_i\)
位置 \(i\) 的 query
\(\mathbf k_j\)
位置 \(j\) 的 key
\(\mathbf v_j\)
位置 \(j\) 的 value
\(d_k\)
query 和 key 的维度，例如 128
\(d_k = 2\)，\(\mathbf q = (1, 0)\)，两个位置的 key 是 \((1,0)\) 和 \((0,1)\)，value 是 \((1,0)\) 和 \((0,1)\)。分数 \(1/\sqrt2 \approx 0.71\) 和 \(0\)；softmax：\(e^{0.71}\approx 2.03\)，\(e^0 = 1\)，权重 \(0.67, 0.33\)；输出 \(\mathbf o = 0.67\,(1,0) + 0.33\,(0,1) = (0.67,\ 0.33)\)。
第 1 步：query 和每个 key 做点积，得到相关度分数。
第 2 步：除以 \(\sqrt{d_k}\)，把分数缩放到合适的量级（下一节解释为什么）。
第 3 步：对所有位置 \(j\) 做 softmax，分数变成和为 1 的权重。
第 4 步：用权重把所有 value 加权平均，就是输出。

把所有位置的 query、key、value 分别排成矩阵 \(Q, K, V\)（每行一个位置），所有位置可以一次算完：

\[ \operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\Big(\frac{\htmlClass{sym-QK}{QK^\top}}{\sqrt{d_k}}\Big)\,V \]
\(QK^\top\) 一次算出所有位置两两之间的分数，得到一个 \(n\times n\) 的矩阵；按行 softmax，再乘 \(V\)。整个过程只有矩阵乘法，非常适合 GPU 并行。
\(QK^\top\)
\(n\times n\) 的分数矩阵，第 \(i\) 行第 \(j\) 列是 \(\mathbf q_i\cdot\mathbf k_j\)

下面两个演示：第一个把一个位置的计算拆成 7 步、代入真实数字；第二个可以拖动 query 和 key，直观地感受“软查询”。

Q 和 K 其实是一个低秩双线性形式

把 \(\mathbf q_i = \mathbf x_i W_Q\)、\(\mathbf k_j = \mathbf x_j W_K\) 代入分数：

\[ \mathbf q_i\cdot\mathbf k_j = \mathbf x_i\,W_Q W_K^\top\,\mathbf x_j^\top = \mathbf x_i\,W_{QK}\,\mathbf x_j^\top,\qquad W_{QK} = W_Q W_K^\top \in \mathbb R^{d\times d} \]

所以分数是两个 token 向量之间的一个双线性函数，由一个 \(d\times d\) 矩阵决定。\(W_Q, W_K\) 都是 \(d\times d_k\)，它们的乘积秩最多是 \(d_k\)。用两个窄矩阵相乘，而不是直接学一个 \(d\times d\) 的矩阵，等于强制这个双线性形式是低秩的：参数从 \(d^2\) 降到 \(2 d d_k\)，计算也更省（先各自投影到 \(d_k\) 维再点积）。

同理，value 和输出投影可以合成 \(W_{OV} = W_V W_O\)，它决定“被看到的位置把什么信息写回来”。可解释性研究常把一个注意力头拆成这两个电路分析：\(W_{QK}\) 决定看哪里，\(W_{OV}\) 决定搬什么（第 章）。

这个推导告诉我们：Q 和 K 不是两种独立的“东西”，而是一个“相关度函数”的两半；分开写是为了低秩和计算效率。也因为 \(W_{QK}\) 不必对称，“A 关注 B”和“B 关注 A”可以不同。

为什么要除以 √d

假设 query 和 key 的每一维都是独立的、均值 0、方差 1 的随机数。点积是 \(d_k\) 项乘积的和：

\[ \operatorname{Var}(\mathbf q\cdot\mathbf k) = \sum_{m=1}^{d_k}\operatorname{Var}(q_m k_m) = \sum_{m=1}^{d_k}\mathbb E[q_m^2]\,\mathbb E[k_m^2] = d_k \]
每一项的方差是 1，\(d_k\) 项相加，方差就是 \(d_k\)：点积的典型大小是 \(\sqrt{d_k}\)。除以 \(\sqrt{d_k}\) 正好把方差拉回 1。
\(d_k = 128\)：不缩放时点积的标准差约 \(\sqrt{128}\approx 11.3\)。16 个分数里最大的往往比次大的高出好几，softmax 后最大的那个权重接近 100%。缩放后标准差为 1，权重分布平缓得多。

为什么分数太大是坏事？softmax 饱和成接近独热的分布后，它对输入几乎不再敏感，梯度接近 0，训练就卡住了（推导见下）。下面的演示直接比较缩放与不缩放：

softmax 饱和时梯度为什么会消失

设 \(\mathbf p = \operatorname{softmax}(\mathbf z)\)。对 \(p_i = e^{z_i}/\sum_m e^{z_m}\) 求偏导：

\[ \frac{\partial p_i}{\partial z_j} = \frac{\delta_{ij}e^{z_i}\sum_m e^{z_m} - e^{z_i}e^{z_j}}{\big(\sum_m e^{z_m}\big)^2} = p_i\,(\delta_{ij} - p_j) \]

（\(\delta_{ij}\) 在 \(i = j\) 时为 1，否则为 0。）如果分布接近独热，某个 \(p_1\approx 1\)、其余 \(\approx 0\)：对角项 \(p_1(1 - p_1)\approx 0\)，其余项 \(p_i p_j \approx 0\)。整个雅可比矩阵接近零，分数的微小变化几乎不改变权重，反向传过来的梯度也就几乎为零。

这个推导告诉我们：注意力的分数必须控制在合适的量级。除以 \(\sqrt{d_k}\) 只保证初始化时没问题；训练过程中分数仍可能越变越大，这是大模型训练不稳定的一个来源。2023 年以后的模型普遍加了额外的保护：在点积前对 q、k 做归一化（QK-Norm），对分数做软截断（Gemma 2 的 logit soft-capping），或者在优化器里直接限制 \(W_Q, W_K\) 的尺度（Kimi K2 的 QK-Clip）。

多头注意力

一个注意力头只能给出一组权重，也就是一种“关注方式”。但一个词往往同时需要几种信息：它的主语是谁、前一个词是什么、前文有没有出现过它。多头注意力把 \(d\) 维切成 \(h\) 份，每份是一个独立的头，有自己的 \(W_Q, W_K, W_V\)，各算各的，结果拼起来再乘一个输出矩阵：

\[ \operatorname{MultiHead}(X) = \big[\,\htmlClass{sym-hd}{\text{head}_1};\ \dots;\ \text{head}_h\,\big]\,\htmlClass{sym-WO}{W_O},\qquad \text{head}_m = \operatorname{Attention}(XW_Q^{(m)},\ XW_K^{(m)},\ XW_V^{(m)}) \]
\(h\) 个头各自用一套小矩阵做注意力，输出拼接成 \(d\) 维，再用 \(W_O\) 混合。
\(\text{head}_m\)
第 \(m\) 个头的输出，维度 \(d_h = d/h\)
\(W_O\)
输出投影，\(d\times d\)，把各头的结果混在一起
Llama 3 8B：\(d = 4096\)，\(h = 32\)，每头 \(d_h = 128\)。每个头的 \(W_Q^{(m)}\) 是 \(4096\times 128\)，32 个头拼起来正好是 \(4096\times 4096\)：参数量和“一个 4096 维的大头”完全相同，只是被分成了 32 种独立的关注方式。

训练好的模型里，不同的头确实学会了不同的分工，下面会看到几种典型的模式。

因果掩码、编码器与解码器

GPT 这类模型的任务是预测下一个 token（第 章），第 \(i\) 个位置只能看到前 \(i\) 个 token，否则就是偷看答案。做法是在 softmax 之前给分数矩阵加一个因果掩码：

\[ A = \operatorname{softmax}\!\Big(\frac{QK^\top}{\sqrt{d_k}} + \htmlClass{sym-M}{M}\Big),\qquad \htmlClass{sym-M}{M_{ij}} = \begin{cases} 0 & j \le i\\ -\infty & j > i \end{cases} \]
右上三角（“后面的位置”）的分数被设成负无穷，softmax 之后权重恰好为 0，前面位置的权重重新归一化。
\(M\)
掩码矩阵：允许看的位置为 0，不允许看的为 \(-\infty\)
第 2 个位置原本的分数是 \((1.2,\ 0.4,\ 2.0)\)。加上掩码 \((0, 0, -\infty)\) 后变成 \((1.2,\ 0.4,\ -\infty)\)，softmax 得 \((0.69,\ 0.31,\ 0)\)：第 3 个位置被完全屏蔽。

掩码带来一个重要的好处：训练时整段文本一次输入，每个位置都在预测自己的下一个 token，\(n\) 个预测在一次前向计算里并行完成。这是 Transformer 训练效率远高于 RNN 的原因之一。

不加掩码、每个位置能看到全部上下文的叫编码器（BERT 就是这样，擅长理解）；加掩码的叫解码器（GPT 系列，擅长生成）。如果 query 来自一个序列、key 和 value 来自另一个序列，叫交叉注意力：原始 Transformer 的解码器用它读取输入句子，文生图模型用它让图像的每个位置去“查”提示词（第 章）。

训练出来的注意力模式

可解释性研究（Anthropic 等, 2021–2022）在训练好的模型里找到了一些分工清晰的头。下面的演示按规则构造出这几种模式，可以输入自己的句子，悬停查看每一行在看哪里：

其中两种值得单独说：

  • 归纳头（induction head）：“上次见到 A 后面跟着 B，这次又见到 A，就去看 B，预测下一个是 B”。它要两层配合：前一层的“前一个 token 头”先把“我前面是谁”写进每个位置，后一层的归纳头再用这个信息去匹配。Olsson 等（2022）发现，归纳头在训练中会在某个时刻突然形成，同一时刻模型的上下文学习（in-context learning，看几个示例就学会新任务）能力也出现跃升。few-shot 提示之所以有效，很大程度上靠这种机制。
  • 注意力汇（attention sink）：很多头会把大量权重放在第一个 token 上，哪怕它只是一个“开始”标记。softmax 的权重和必须为 1，一个头“没什么要看”的时候，多出来的权重总得有个去处。StreamingLLM（2023）利用这一点：做滑动窗口推理时保留开头几个 token，模型就不会崩。

注意力汇是缺陷还是功能

一种看法
它是 softmax 的副作用，浪费了注意力，还和某些通道里异常巨大的激活值（massive activations）同时出现，给量化和长上下文外推带来麻烦。Qwen 团队的门控注意力（Gated Attention, NeurIPS 2025 最佳论文）在注意力输出后加一个按头、按输入变化的 sigmoid 门，注意力汇随之消失，训练更稳、可以用更大的学习率、长上下文外推更好，已用于 Qwen3-Next。
另一种看法
它是模型学会的一种“隐式门控”：一个头不需要时，把权重倒进汇里，等于自动关掉。2026 年的多项研究（如 NYU 的 “The Spike, the Sparse and the Sink”）发现，注意力汇与巨量激活的同时出现主要源于 Pre-Norm 结构，两者分工不同；也有研究认为注意力汇是为了缓冲第一个 token 上过大的梯度。
现在怎么看
两种看法并不矛盾：注意力汇是模型在“权重必须和为 1”这个约束下找到的变通办法。显式地提供门控之后，模型就不再需要它。各研究对“巨量激活是不是注意力汇的直接原因”仍有分歧。

注意力权重能不能当作“解释”

主张
权重大的位置就是模型“认为重要”的位置，可以直接用来解释模型的决定。
反方
Jain 与 Wallace（2019）发现，常常可以找到完全不同的注意力分布，而模型输出几乎不变；而且注意力只是众多层、众多头中的一个环节，value 向量的大小、后续的 MLP 都会改变最终影响。
现在怎么看
单个头的权重可以提示“信息从哪里流过来”，但不能等同于因果解释。要确认某个位置的作用，需要做干预实验（改掉它看输出怎么变），这是第 章的方法。

代价：平方级的计算与显存

自注意力要为每一对位置算一个分数。设序列长度为 \(n\)、隐藏维度为 \(d\)，一层里注意力部分和线性层（Q/K/V/O 投影加 MLP）的计算量分别约为：

\[ \underbrace{4\,n^2 d}_{\text{注意力：}QK^\top\ \text{和}\ AV} \quad\text{vs}\quad \underbrace{24\,n\,d^2}_{\text{线性层：投影}\ 8nd^2\ +\ \text{MLP}\ 16nd^2} \]
注意力的计算量随 \(n\) 的平方增长，线性层随 \(n\) 线性增长。两者在 \(n = 6d\) 时相等；序列再长，注意力就成了主要开销。
\(d = 4096\)：\(n = 6\times 4096 \approx 2.5\) 万 token 时两者相当。到 \(n = 100\) 万，注意力的计算量是线性层的 \(10^6/(6\times 4096) \approx 40\) 倍。显存方面，一个头的 \(n\times n\) 分数矩阵在 \(n = 128\text{K}\) 时就有约 \(1.7\times 10^{10}\) 个数，BF16 下约 34 GB。

后面几章讲的大部分技术，都在想办法绕开这个平方：

  • FlashAttention：结果完全相同，但分块计算，不把 \(n\times n\) 矩阵写进显存，显存从 \(O(n^2)\) 降到 \(O(n)\)（第 章）。
  • KV cache 与 GQA、MLA：生成时缓存历史的 K、V，并压缩它们的大小（第 章）。
  • 线性注意力与状态空间模型：Mamba、DeltaNet、Kimi Delta Attention，把历史压进固定大小的状态，代价降为 \(O(n)\)；2025–26 年的主流是和普通注意力按约 3:1 混合使用。
  • 稀疏注意力：每个 query 只看挑出来的少量位置，例如 DeepSeek V3.2 的 DSA 和 V4 的 CSA / HCA。

常见误解

  • 注意力权重越大，说明这个词越重要。权重只说明信息从哪个位置流过来，不等于因果上的重要性；还要看 value 和后续层。见上面的争议框。
  • 多头注意力的参数是单头的 \(h\) 倍。每个头的维度是 \(d/h\)，\(h\) 个头加起来和一个 \(d\) 维的头参数相同。多头改变的是表达方式，不是参数量。
  • 注意力能看到整个上下文，所以长文本没有问题。能看到不等于能用好：长文本中间位置的信息常被忽略（lost in the middle），而且计算量随长度平方增长（第 章）。
  • Transformer 天然知道词的顺序。注意力本身对顺序不敏感，把输入打乱，每个位置的输出只会跟着换位置。顺序信息要另外注入，即下一章的位置编码。

演进史

2014-09

Bahdanau 注意力：翻译时回头看原句

卡在哪
编码器把整句压成一个固定向量，句子一长，翻译质量就急剧下降。
怎么解决
解码器每生成一个词，都对输入的每个位置算相关度，加权取信息。
代价
主体仍是 RNN，训练依旧串行、很慢。
引出
既然注意力已经能看到所有位置，还需要循环吗？
变体Luong 注意力（2015）
用点积代替 Bahdanau 的小网络来算相关度，更简单更快。“点积打分”这一做法被 Transformer 沿用。
2017-06

Transformer：只用注意力

卡在哪
RNN 无法并行训练，长距离依赖难以学习。
怎么解决
完全去掉循环：多头缩放点积注意力 + MLP 堆叠，配合位置编码；训练时所有位置并行计算。
代价
计算和显存随序列长度平方增长；注意力本身不知道顺序，需要额外的位置编码。
引出
这个能并行、能扩展的结构，能不能在海量无标注文本上预训练？
被取代卷积序列模型（ConvS2S, 2017）
同年 Facebook 用卷积代替循环，也能并行。但卷积的感受野随层数缓慢扩大，远距离依赖需要很多层；注意力一层就能连接任意两个位置，最终胜出。
2018–2020

预训练：编码器与解码器分道

卡在哪

争论注意力权重能否作为解释
2019 年的 “Attention is not Explanation” 和 “Attention is not not Explanation” 两篇论文针锋相对。现在的共识是：权重只能提示信息流向，因果结论需要干预实验。

自测

1. \(d_k = 2\)，\(\mathbf q = (1, 0)\)，\(\mathbf k_1 = (1, 0)\)，\(\mathbf k_2 = (0, 1)\)，\(\mathbf v_1 = (1, 0)\)，\(\mathbf v_2 = (0, 1)\)。手算注意力输出。
分数 \(1/\sqrt2 \approx 0.707\) 和 \(0\)。softmax：\(e^{0.707}\approx 2.03\)、\(e^0 = 1\)，权重 \(2.03/3.03 \approx 0.67\)、\(0.33\)。输出 \(0.67\,\mathbf v_1 + 0.33\,\mathbf v_2 = (0.67,\ 0.33)\)。
2. 为什么把一个 4096 维的注意力拆成 32 个 128 维的头，参数量不变？
每个头的 \(W_Q^{(m)}\) 是 \(4096\times 128\)，32 个头合起来是 \(4096\times 4096\)，和一个完整的 \(W_Q\) 一样大；\(W_K, W_V, W_O\) 同理。变化在于分数被分成 32 组独立计算、各自 softmax，于是可以同时关注不同的位置。
3. \(d = 4096\) 的模型，序列多长时注意力的计算量开始超过线性层？到 32K 时注意力大约是线性层的几倍？
两者相等时 \(4n^2d = 24nd^2\)，即 \(n = 6d \approx 24{,}576\)。\(n = 32{,}768\) 时比值是 \(n/(6d) = 32768/24576 \approx 1.33\) 倍。
