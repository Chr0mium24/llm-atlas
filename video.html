视频生成：从“动起来的图”到带声音的多镜头影片

视频生成比图像难在三点：时间上要连贯（同一个人不能每帧换脸），运动要合理（物理、因果），数据量巨大（5 秒 720p 就是一亿多个像素）。2024 年 Sora 用“时空 patch + DiT”给出了可规模化的答案；到 2026 年，主流模型能直接生成带同步音频的多镜头视频。本章回答四件事：一段视频的账怎么算、怎么省，帧与帧怎样保持一致，以及怎样把生成变成边算边播的实时流。

上一章的图像生成在潜空间里对一张图去噪。视频多了一个时间维度：数据量乘以帧数，而且相邻帧之间必须保持一致。这一章所有的技术选择都围绕这两点展开。

  • 扩散与流匹配、CFG、“完美的去噪器只会背书”：第 章

从零开始：一段 5 秒的视频在模型眼里有多大

这一节只讲视频比图像多出来的部分。图像章的流水线（VAE 压缩、切 patch、DiT 去噪、解码）原样保留，只多了一根时间轴。用一个贯穿全章的例子把多出来的代价算清楚：一只红球用 5 秒从画面左边滚到右边，720p（1280×720），每秒 24 帧。先算它有多大，再看时间轴能压掉多少（时间冗余、因果 VAE），最后算注意力那一笔。

一段视频就是一个四维数组

一张彩色图是一个 \(H\times W\times 3\) 的数组：高、宽、红绿蓝三个颜色通道。视频再多一维时间：\(T\times H\times W\times 3\)，\(T\) 是帧数。红球的视频取 \(T = 121\) 帧（5 秒 × 24 帧，再加 1 帧，后面会看到为什么要多 1 帧）：

  • 像素数：\(121\times 1280\times 720\approx 1.1\times 10^8\)，一亿一千万个；乘上 3 个颜色通道，约 3.3 亿个数。
  • 同样分辨率的一张图只有 92 万个像素，约 276 万个数。视频是它的 121 倍。

直接对 3.3 亿个数做扩散，每一步去噪都要处理这么多数，还要做几十步，完全不可行。和图像一样，第一步是压缩。

相邻帧几乎一样：时间冗余

红球每秒移动 \(1280/5 = 256\) 个像素，每帧只移动约 10.7 个像素。相邻两帧之间，变化的只有球边缘的一小圈，画面里 99% 以上的像素几乎不变。这种“下一帧大部分可以从上一帧猜出来”的性质叫时间冗余（temporal redundancy）。传统视频编码（H.264 等）就靠它：原始的 1080p、24 帧每秒视频约每秒 1.2 Gbit，网络上的流媒体通常只有每秒几 Mbit，压缩了两三百倍，主要压的是时间维度。

所以对视频来说，时间方向比空间方向更“便宜”压缩：连续 4 帧压成 1 帧，丢掉的信息很少。那为什么生成模型的 VAE 在时间上只压 4 倍（LTX-Video 为 8 倍），远不到两三百倍？因为 H.264 输出的是变长码流，靠运动补偿和“只记差异”压缩，没法拿来去噪；扩散要生成的是一个形状固定的张量，每个位置都要能被直接画出来。时间压得越狠，一个潜帧要代表的运动越多，快速运动越难还原。

3D 因果 VAE：先把 4 帧压成 1 帧

图像模型用 VAE 把每边压缩 8 倍（第 章）。视频模型用的是它的三维版：卷积核同时跨越时间和空间，在空间上每边压缩 \(f_s\) 倍，在时间上压缩 \(f_t\) 倍。压缩后的每一“帧”叫潜帧（latent frame）。

主流做法还要求它是3D 因果 VAE（causal 3D VAE）：编码第 \(t\) 帧时只看第 \(t\) 帧和它之前的帧，不看之后的。这样第一帧没有任何“之前”，只能单独编码；之后每 \(f_t\) 帧编成一个潜帧：

\[ \htmlClass{sym-Nt}{N_t} = 1 + \frac{\htmlClass{sym-T}{T} - 1}{\htmlClass{sym-ft}{f_t}} \]
第一帧单独占一个潜帧，后面每 \(f_t\) 帧压成一个。所以帧数通常取“\(f_t\) 的整数倍再加 1”。
\(N_t\)
潜帧数
\(T\)
原始帧数
\(f_t\)
时间压缩倍数，主流为 4（LTX-Video 为 8）
红球：\(T = 121\)，\(f_t = 4\)：\(N_t = 1 + 120/4 = 31\)。Wan 的 5 秒、16 帧每秒视频取 81 帧，得到 21 个潜帧；HunyuanVideo 取 129 帧，得到 33 个。这就是这些奇怪帧数的来历。

“第一帧单独编码”有一个直接的好处：一张图片就是只有 1 帧的视频，编码结果和视频的第一个潜帧完全同分布。于是同一个模型可以把图片和视频混在一起训练，这叫图像视频联合训练（joint image-video training）。图片数据比视频多得多、题材更广，模型从图片里学外观和概念，从视频里学运动。

压缩到底有多狠，用一个潜变量“换”多少个像素值来衡量：

\[ \htmlClass{sym-r}{r} = \frac{3\,\htmlClass{sym-ft}{f_t}\,\htmlClass{sym-fs}{f_s}^{2}}{\htmlClass{sym-C}{C}} \]
一个潜向量覆盖 \(f_t\) 帧、\(f_s\times f_s\) 个像素、3 个颜色通道，用 \(C\) 个数来表示。\(r\) 越大，压得越狠，token 越少，细节越难还原。

\(f_t\)

\(f_s\)

\(C\)
每个潜向量的通道数
Wan 2.1 的 VAE：4×8×8、\(C = 16\)：\(r = 3\cdot 4\cdot 64/16 = 48\)。Wan 2.2 的 5B 版：4×16×16、\(C = 48\)：\(r = 64\)。LTX-Video：8×32×32、\(C = 128\)：\(r = 192\)。红球用 Wan 2.1 的设置：3.3 亿个数压成 \(31\times 90\times 160\times 16\approx 714\) 万个，约 47 倍（略小于 48，因为第一帧单独占了一个潜帧）。
因果 VAE 为什么能让“第一帧当图像”

第 1 步，因果卷积。沿时间方向的卷积核长度为 \(k\)（常为 3）。普通卷积在序列两头各补 \((k-1)/2\) 帧，第 \(t\) 帧的输出看 \(t-1, t, t+1\)；因果卷积只在开头补 \(k-1\) 帧，输出只看 \(t-2, t-1, t\)。叠多少层都一样：第 \(t\) 帧的特征只依赖第 \(0,\dots,t\) 帧。

第 2 步，时间下采样。编码器里有两次步长为 2 的时间下采样，总共 4 倍。在因果结构下，帧被分成 \(\{0\},\{1,2,3,4\},\{5,\dots,8\},\dots\) 这样的组：第 0 个潜帧只由第 0 帧决定，第 \(j\) 个潜帧由第 \(4j-3\) 到 \(4j\) 帧（以及更早的帧）决定。帧数 \(T = 1 + 4m\) 时正好得到 \(1 + m\) 个潜帧。

第 3 步，图像是特例。把一张图当作 \(T = 1\) 的视频送进去，编码器执行的计算和处理视频第 0 帧时完全一样，得到的潜变量也就和视频的第 0 个潜帧同分布。去噪网络看到的图片是“\(N_t = 1\) 的视频”，时间方向的注意力只有一帧可看，不需要任何特殊处理。

第 4 步，对比非因果的情形。如果用对称卷积，第 0 个潜帧会混入第 1–3 帧的信息。单独一张图没有“后面的帧”，只能用补零或复制代替，它的潜变量就和视频第一帧的潜变量分布不同，图片和视频只能分开处理。图生视频（给定第一帧）也会变麻烦：给定的图编码出来，并不是模型在视频里见过的那种第一帧。

第 5 步，附带的好处。因果结构还让编码可以分块进行：Wan 的 VAE 每次只处理 4 帧，把前一块的特征缓存起来供下一块使用，于是能编码任意长度的视频而显存不随长度增长。用因果 3D 卷积、首帧单独编码的做法由 MAGVIT-v2（2023-10）的视频分词器定型（更早的 Phenaki 用时间上因果的注意力做过类似的事），之后 CogVideoX、HunyuanVideo、Wan 都沿用了。

这个推导告诉我们：VAE 做成因果的，首要目的不是“实时”，而是让图片成为视频的特例：一个模型、两种数据，图生视频也顺带得到了。代价是第一帧的压缩率比其它帧低 4 倍，帧数必须凑成 \(4m+1\)。

切 patch：变成 token

和图像的 DiT 一样，潜视频再切成小块，每块一个 token。视频的小块叫时空 patch（spacetime patch），通常在时间上取 1 个潜帧、空间上取 2×2。不同时长、分辨率、宽高比的视频，都变成一串长度不一的 token：

\[ \htmlClass{sym-n}{n} = \htmlClass{sym-Nt}{N_t}\times\frac{H}{\htmlClass{sym-fs}{f_s}\,\htmlClass{sym-p}{p}}\times\frac{W}{f_s\,p} = N_t\times \htmlClass{sym-Ns}{N_s} \]
潜帧数 × 每个潜帧的 token 数。token 数与时长成正比，与面积成正比。

整段视频的 token 数
\(N_t\)

\(f_s\)
VAE 的空间压缩倍数：Wan 2.1 为 8，Seedance 1.0 为 16
\(p\)
patch 边长，常为 2；压缩更狠的 VAE 常取 1
\(N_s\)
每个潜帧的 token 数
红球：\(31\times\frac{720}{16}\times\frac{1280}{16} = 31\times 45\times 80 = 111{,}600\) 个 token。同样分辨率的一张图只有 3600 个，视频是它的 31 倍。换成 Wan 2.2 5B 的 4×16×16 VAE 再切 2×2（相当于每个 token 管 32×32 个像素），只剩约 2.8 万个。

注意力的账：token 多 31 倍，注意力贵 961 倍

自注意力里每个 token 都要和所有 token 算一次相似度，代价随 token 数平方增长（第 章）。红球视频有 \(111{,}600^2\approx 1.25\times 10^{10}\) 对 token，一张同分辨率的图只有 \(3600^2\approx 1.3\times 10^{7}\) 对，相差 \(31^2 = 961\) 倍。Transformer 里的线性层（QKV 投影、输出投影、MLP）代价只和 token 数成正比，所以 token 一多，注意力就从配角变成主角：

\[ \frac{\text{注意力}}{\text{线性层}} \approx \frac{4\,\htmlClass{sym-n}{n}^{2}\,\htmlClass{sym-d}{d}}{24\,n\,d^{2}} = \frac{n}{6d} \]
每个 token 过一层线性层约 \(24d^2\) 次运算，做注意力约 \(4nd\) 次，两者之比只取决于 \(n\) 和 \(d\)。推导见第 章「代价」一节，这里只代入视频的 \(n\)。

token 数
\(d\)

\(d = 5120\)，\(6d\approx 3.1\) 万。红球视频 \(n/(6d) = 111{,}600/30{,}720\approx 3.6\)：注意力占一层计算的约 78%。同分辨率的一张图 \(n = 3600\)，比值 0.12，注意力只占约 10%。据 STA 论文（2025-02）的测量，HunyuanVideo 生成一段 5 秒 720p 视频（约 11.5 万个 token）的 945 秒里，有 800 秒花在注意力上。

生成：整块 token 一起去噪

生成的流程和图像章一样：从一块和潜视频同样大小（\(31\times 90\times 160\times 16\)）的纯噪声出发，用流匹配一步步去噪，每步用 CFG 算有条件、无条件两次。区别只在每次前向要处理全部 111,600 个 token。去噪网络被调用的总次数叫函数评估次数（NFE）：50 步加 CFG 就是 100 次，每次都处理整段视频。下面的演示把这笔账算到“单张 H100 要多久”，默认就是红球的设置：

主流架构：3D VAE + 时空 patch + DiT + 流匹配

把上一节的零件拼起来，就是 2024 年以后几乎所有视频模型的结构：3D 因果 VAE 压缩，时空 patch 切成 token，DiT 去噪，流匹配训练与采样。文字条件的注入方式和图像章相同（Wan 用交叉注意力，HunyuanVideo 用 MMDiT 式的联合注意力）。视频特有的选择有两个。一是位置：每个 token 有三个坐标（时间、高、宽），位置编码（通常是 RoPE）分成三段分别编码，多镜头视频还会在时间坐标里编入“第几个镜头”。二是注意力怎么排，这是本节的主题。

注意力有两种基本排法。全 3D 注意力（full 3D attention）让每个 token 直接看所有潜帧的所有位置。时空分解注意力（factorized space-time attention）拆成两步：先在每个潜帧内部做空间注意力，再在每个空间位置上沿时间做注意力。

\[ \begin{aligned} \text{全 3D} &: (\htmlClass{sym-Nt}{N_t}\htmlClass{sym-Ns}{N_s})^2 \\ \text{分解} &: \underbrace{N_t N_s^2}_{\text{空间}} + \underbrace{N_s N_t^2}_{\text{时间}} \\ \frac{\text{全 3D}}{\text{分解}} &= \frac{\htmlClass{sym-Nt}{N_t}\,\htmlClass{sym-Ns}{N_s}}{N_s + N_t} \end{aligned} \]
全 3D：\(n = N_tN_s\) 个 query 各看 \(n\) 个 key。分解：空间一步里每个 query 只看本帧的 \(N_s\) 个，时间一步里只看同一位置的 \(N_t\) 个。每帧 token 远多于帧数时，节省的倍数约等于潜帧数 \(N_t\)。
\(N_t\)
潜帧数
\(N_s\)
每个潜帧的 token 数
红球：\(N_t = 31\)，\(N_s = 3600\)：全 3D 约 \(1.25\times 10^{10}\) 对，分解约 \(31\times 3600^2 + 3600\times 31^2\approx 4.1\times 10^{8}\) 对，便宜约 31 倍。60 秒的视频 \(N_t = 361\)，便宜约 328 倍。视频越长，分解越划算。

省下的算力不是白来的。分解之后，第 \(t\) 帧位置 \(s\) 的 token 想看第 \(t-1\) 帧位置 \(s'\) 的内容，必须先在第 \(t-1\) 帧内部把信息从 \(s'\) 传到 \(s\)，再沿时间传过来，走两跳。红球每个潜帧移动约 2.7 个 token，上一帧的球恰好不在同一个空间位置上。点下面网格里的格子，换几种注意力看看一个 token 能直接看到谁；下半张图把时长拉到 60 秒，全 3D 与分解的差距从 5 秒时的约 31 倍涨到约 328 倍：

两跳的代价在中转：中转的那个 token 只有一个向量，却要替整帧转达红球在哪、长什么样，它会优先保留和自己位置相关的内容，物体一快就丢细节。CogVideoX（2024-08）因此改用全 3D 注意力，HunyuanVideo、Wan 随后也用全 3D，这是 2024 年以后开源大模型的主流。全 3D 的平方代价改在推理时压：训练好的全 3D 模型自己分出了“空间头”（只看同一帧）和“时间头”（只看不同帧的同一位置附近），大部分注意力落在一个局部的三维窗口里，按这个结构裁掉其余部分即可。Sparse VideoGen（2025-02）让 HunyuanVideo 端到端提速约 2.3 倍，STA（2025-02）微调后约 3.5 倍。分解的思路没有消失，只是从“写死在结构里”变成了“从数据里学出来再利用”。

分解注意力的计算量，以及它丢掉了什么

第 1 步，数 key。记 \(n = N_tN_s\)。全 3D 注意力里每个 query 看 \(n\) 个 key，总共 \(n^2 = N_t^2N_s^2\) 对。空间注意力每个 query 看本帧 \(N_s\) 个，总共 \(nN_s = N_tN_s^2\)；时间注意力每个 query 看同一位置的 \(N_t\) 个，总共 \(nN_t = N_sN_t^2\)。比值

\[ \frac{N_t^2N_s^2}{N_tN_s^2 + N_sN_t^2} = \frac{N_tN_s}{N_s + N_t} \]

每帧 token 远多于帧数（\(N_s\gg N_t\)）时，它约等于 \(N_t\)。第 2 步，看信息怎么走。一层全 3D 注意力里，token \((t, s)\) 对 \((t', s')\) 有一个专属的注意力权重，由两者的 query 和 key 直接决定。一组“空间→时间”的分解层里，\((t', s')\) 的信息只能先在空间一步被 \((t', s)\) 收进去，再在时间一步传给 \((t, s)\)。中转的 \((t', s)\) 只有一个 \(d\) 维向量，却要替第 \(t'\) 帧所有 \(N_s\) 个位置“转达”信息，它会优先保留和自己相关的内容。

第 3 步，什么时候会出问题。物体不动或动得很慢时，前后帧里同一个物体落在同一列，时间注意力一步就连上了，分解几乎没有损失。物体移动快时，前一帧的它在另一列，只能靠中转。CogVideoX（2024-08）的报告举的正是这个例子：分解注意力里，第 \(i+1\) 帧的人头无法直接关注第 \(i\) 帧的人头，只能通过背景 patch 间接传递，于是大幅运动时容易不连贯。他们因此改用全 3D 注意力。

第 4 步，全 3D 并不意味着每对 token 都有用。Sparse VideoGen（2025-02）在 HunyuanVideo、CogVideoX 里发现，训练好的全 3D 注意力头会自己分成两类：“空间头”的注意力集中在同一帧内，“时间头”集中在不同帧的同一位置附近。STA（2025-02）发现大部分注意力落在一个局部的三维窗口里。模型学到的，基本就是分解结构加上局部窗口，只是它能在需要时（大幅运动、镜头切换）突破这个结构。

这个推导告诉我们：分解注意力省下的倍数约等于潜帧数，代价是把“运动”变成两跳的路径；而全 3D 模型学到的，基本就是分解结构加局部窗口，只是需要时能突破它。

并非所有人都放弃了分解。Seedance 1.0（2025-06）用的是空间层与时间层交替的结构，时间层里再按窗口切分，文字 token 只进空间层；它把 VAE 的空间压缩提到 16 倍、不再切 patch，用更少的 token 换取了在空间层里做全帧注意力的余地。省算力的三条路（更狠的压缩、分解或稀疏的注意力、更少的步数）在各家模型里有不同的组合。

最后是两个图像里没有、却决定了视频模型怎么用、怎么训的选择。图生视频（给定第一帧）利用了因果 VAE 的“第一帧就是一张图”：把给定的图编码成第一个潜帧，和噪声潜视频沿通道拼在一起，再拼一个标出“哪些帧已知”的掩码，模型只去噪未知的部分；在已有片段之后续写也是同样的做法。训练分阶段：先在低分辨率图片上学外观，再做图像视频联合训练，分辨率和时长逐级提高，最后用少量高质量视频微调。数据要按运动量、画质、字幕筛选，每段视频配上模型生成的详细描述（Sora 报告里叫“重写字幕”），提示词才能控制得住画面。

为什么要“时空联合”去噪

最朴素的想法是用图像模型一帧一帧地生成。问题在于每帧的去噪都是独立随机的：第 1 帧生成了左边的红球，第 2 帧可能生成右边的红球，画面跳动闪烁。视频扩散把整段视频当成一个样本联合去噪，所有帧在同一个去噪过程里互相“商量”，运动自然连贯。

差距有多大，可以在一个能精确求解的玩具里直接算。第 章讲过，完美的去噪器只会从训练集里挑一个样本。假设训练集里有 \(M\) 段视频，每段 \(T\) 帧。逐帧独立生成时，即使图像模型知道自己是第几帧，每一帧也各自从 \(M\) 段里“选”一段来模仿：

\[ \begin{aligned} P(\text{连贯}) &= \sum_{m=1}^{\htmlClass{sym-M}{M}}\ \prod_{f=1}^{\htmlClass{sym-T}{T}} P(k_f = m) \\ &= M\cdot M^{-T} = M^{1-T} \end{aligned} \]
“连贯”指所有帧选中了同一段视频。逐帧独立时，每帧的选择互不相关，全部选中同一段的概率随帧数指数下降。联合去噪时，所有帧共享一次选择，这个概率是 1。

逐帧独立的每一帧都是合理的图，连起来却乱跳，这是 2022 年以前用图像模型做视频的典型问题。时空联合整段一起去噪，运动连贯；公开了结构的模型（Wan、HunyuanVideo、CogVideoX、Seedance 1.0）都是这类，缺点是长度固定，第一帧要等最后一帧算完才能看到。自回归逐帧（第三行）让每一帧以前面已经生成的帧为条件去噪，可以无限延长、流式输出，也能在中途插入用户的动作，代价是误差逐帧累积。Diffusion Forcing（2024-07）训练时给每一帧独立的噪声水平，让模型习惯“前面的帧不完美”，是这条路线的起点之一，下一节细讲。

联合去噪为什么一致：一次共享的“选择”

第 1 步，最优去噪器长什么样。把训练集看成 \(M\) 段视频 \(\mathbf v^{(1)},\dots,\mathbf v^{(M)}\)，每段由 \(T\) 帧组成 \(\mathbf v^{(k)} = (\mathbf x^{1,(k)},\dots,\mathbf x^{T,(k)})\)。在噪声水平 \(t\) 下加噪：\(\mathbf v_t = a_t\mathbf v^{(k)} + b_t\boldsymbol\varepsilon\)。对整段视频的最优去噪器是后验均值：

\[ \begin{aligned} \mathbb E[\mathbf v\mid \mathbf v_t] &= \sum_{k} w_k(\mathbf v_t)\,\mathbf v^{(k)} \\ w_k &\propto \exp\Big(-\frac{\|\mathbf v_t - a_t\mathbf v^{(k)}\|^2}{2b_t^2}\Big) \end{aligned} \]

第 2 步，权重是所有帧的证据之和。整段的距离等于各帧距离之和：\(\|\mathbf v_t - a_t\mathbf v^{(k)}\|^2 = \sum_f\|\mathbf x_t^f - a_t\mathbf x^{f,(k)}\|^2\)。所以

\[ \log w_k = \sum_{f=1}^{T}\Big(-\frac{\|\mathbf x_t^f - a_t\mathbf x^{f,(k)}\|^2}{2b_t^2}\Big) + \text{常数} \]

每一帧给每段候选视频投一票（对数似然），票数相加。所有帧共享同一组权重 \(w_k\)，去噪到最后 \(w\) 收缩到某一个 \(k\) 上，所有帧就一起取第 \(k\) 段的内容。

第 3 步，逐帧独立时发生了什么。图像模型只看本帧，第 \(f\) 帧的权重是 \(w^f_k\propto\exp(-\|\mathbf x_t^f - a_t\mathbf x^{f,(k)}\|^2/2b_t^2)\)，只用本帧的那一票。不同帧从不同的初始噪声出发，各自收缩到各自的 \(k_f\)。生成的视频服从 \(\prod_f p(\mathbf x^f)\)，即各帧边缘分布的乘积，而不是联合分布 \(p(\mathbf x^1,\dots,\mathbf x^T)\)。连贯的概率就是上面公式卡里的 \(M^{1-T}\)。

第 4 步，自回归介于两者之间。第 \(f\) 帧以已经生成的前 \(f-1\) 帧为条件，相当于把前面帧的票当作先验：\(\log w_k = (\text{前 } f-1 \text{ 帧的票}) + (\text{第 } f \text{ 帧的票})\)。只要第一帧生成得清楚，后面就会沿着同一段视频走下去。可如果前面某一帧生成得有偏差，它投出的票就是错的，后面的帧会忠实地跟着错的方向走，这就是漂移的来源。演示里把去噪步数调到最小的 2，多点几次“重新生成”（约八分之一的概率）能看到自回归那一行偏离训练片段；3 步及以上几乎看不到。

这个推导告诉我们：一致性来自“所有帧共享一次选择”。在真实模型里，这次选择不是在训练集里挑一段，而是在注意力里让所有帧对人物身份、场景布局、运动方向达成一致；帧与帧之间的注意力就是投票的通道。这也说明了为什么联合去噪必须整段一起做完：任何一帧的最终结果都依赖所有帧的噪声。

自回归视频：漂移与强制训练

联合去噪的视频长度固定，而且要等整段算完才能看第一帧。想要无限长、可以边生成边播放、能随时响应用户动作的视频（这正是第 章世界模型需要的），只能回到自回归：按时间顺序一块一块地生成，每块以前面已经生成的帧为条件去噪。注意力加上因果掩码，前面的帧算完就固定下来，它们的 K、V 存进 KV 缓存，不用重算。

训练和生成之间有一道缝。最直接的训练方式是 teacher forcing：上下文用真实视频的前几帧，让模型去噪下一块。生成时，上下文却是模型自己刚画的帧，带着小瑕疵。这正是第 章讲过的暴露偏差：模型从没见过带瑕疵的上下文，不会纠正，只会照着画，瑕疵一帧帧传下去。

传多快，看一个数 \(L\)：上一帧里的误差经过模型、生成下一帧之后还剩几倍。设每帧新增的误差为 \(\varepsilon\)。误差每帧同向累积时，\(H\) 帧后约为 \(\varepsilon(L^H-1)/(L-1)\)；误差方向随机时按方差累加，标准差约为 \(\varepsilon\sqrt{(L^{2H}-1)/(L^2-1)}\)。\(L<1\) 时两者都停在一个上限；\(L=1\) 时前者按 \(H\varepsilon\) 线性增长，后者像随机游走一样按 \(\sqrt H\) 增长；\(L>1\) 时都指数增长。

这里的 \(L\) 是模型对上下文误差的放大。红球的世界本身很平稳，误差变大不是世界造成的，而是模型没学过怎样处理带瑕疵的输入。第 章还会遇到另一种放大：碰撞、多物体互动的世界会把小误差本身变大，那一部分由世界决定，训练改不了。训练技巧能改的是模型这一侧：让每帧新增的误差 \(\varepsilon\) 更小，或者让模型学会把上下文里的误差压下去（\(L<1\)）。下面两种修法，一种让模型学会压住误差，一种让训练时的上下文和生成时一样。

修法一：给上下文加噪

第一种修法是训练时故意把上下文弄脏。上下文加噪（context noise augmentation）在训练时给上下文帧加一定程度的噪声，并把噪声水平告诉模型；模型学会了“上下文不可全信，要自己补齐细节”。GameNGen（2024-08）用这个办法让扩散模型稳定地“运行”《毁灭战士》。Diffusion Forcing 是它的推广：训练时给序列里每一帧独立抽一个噪声水平，干净的、半干净的、纯噪声的帧混在一起，模型对任意“噪声水平组合”都会去噪。

\[ \begin{aligned} \tilde{\mathbf c} &= \htmlClass{sym-a}{a_s}\,\mathbf c + \htmlClass{sym-b}{b_s}\,\boldsymbol\varepsilon \\ D_{\text{KL}}\big(\tilde{\mathbf c}_{\text{真}}\,\|\,\tilde{\mathbf c}_{\text{生成}}\big) &= \frac{a_s^2\,\|\htmlClass{sym-dl}{\boldsymbol\delta}\|^2}{2\,b_s^2} \end{aligned} \]
把上下文 \(\mathbf c\) 加噪到水平 \(s\) 再交给模型。生成时的上下文比真实的多了一个误差 \(\boldsymbol\delta\)；加噪之后，两者的分布差异（KL 散度）按 \(a_s^2/b_s^2\) 缩小。模型越分不清，就越不会被误差带偏。

信号系数，流匹配下 \(a_s = 1-s\)
\(b_s\)

\(\boldsymbol\delta\)

设 \(\|\boldsymbol\delta\|^2 = 0.05\)。\(s = 0.1\)：\(a^2/b^2 = 81\)，KL ≈ 2.0，一眼就能分辨，模型落在没见过的输入上；\(s = 0.3\)：\(a^2/b^2\approx 5.4\)，KL ≈ 0.14，小了约 15 倍。代价是上下文本身也被噪声盖住了一部分，模型要“重新想象”前一帧的细节，一致性会变差。

Diffusion Forcing 的“每帧独立噪声”在生成时还带来了灵活性：可以让越靠后的帧噪声越大，形成一条流水线。开源的 MAGI-1（2025-04，24B）就这样做：每 24 帧一块，噪声沿时间单调增加，前一块去噪到一定程度就开始下一块，最多 4 块同时在流水线里。

修法二：在自己生成的帧上训练（Self Forcing）

加噪是在“猜”生成误差长什么样，用高斯噪声代替。更直接的办法是让模型在训练时就看到自己的真实误差。Self Forcing（2025-06）在训练时就按推理的方式自回归地滚动生成：每一块以模型自己刚生成的前几块为上下文，用 KV 缓存逐块往下生成一整段视频，然后对整段视频算损失。训练和推理看到的上下文分布从此完全一致。

这带来一个新问题：上下文是模型自己生成的，没有逐帧的标准答案，只能比整段视频的分布。Self Forcing 用第 章的分布匹配蒸馏（DMD）：拿一个在真实数据上训练好的双向大模型当老师，把学生生成的整段视频往老师的分布上推，不需要配对的答案。为了让“训练时滚动生成”算得起，学生只用 4 步去噪，并且只对随机选中的一步回传梯度，其余各步不保存反向传播要用的中间结果，省显存。

下面的玩具把三种训练方式放在同一个模型上比较。玩具里的“视频”是 32 个像素宽的一维波纹：上面四张图竖向是时间（往下是往后），横向是像素，颜色是像素值。模型是“残差式”的线性模型（下一帧 = 上一帧做一次卷积，没学过的方向默认照抄），每生成一帧会在三个高频方向上留下一点伪影；训练片段只有 16 帧，生成时一直往后滚。下面两张曲线：左图是伪影与信号之比，越低越干净；右图是信号保留，越接近 1 越不褪色。

默认设置下，教师强制学到的伪影方向 \(L = 1.00\)，伪影到第 64 帧涨到信号的约 64%；把长度拉到 128 帧，约 92%，是 64 帧时的约 \(\sqrt2\) 倍，正是 \(L = 1\) 时随机误差的 \(\sqrt H\) 增长。加噪（σ = 0.25）让 \(L\) 降到 0.29，伪影压在 9% 左右，画面却褪色到原来的约四成；自我强制的 \(L = 0.57\)，伪影约 11%，信号几乎不褪色（98%）。

加噪的“褪色”是这个线性玩具的副作用：噪声加在所有方向上，线性模型只能整体变保守。真实模型里对应的代价是前一帧的细节被噪声盖住、一致性变差（见上面公式卡），不是画面变淡。要带走的是那个权衡：加噪是在“猜”误差的形状，σ 小了盖不住误差，大了盖住内容，没有现成的刻度；Self Forcing 不用猜，直接拿模型自己的误差来训，代价是训练时要真的把视频生成出来。

暴露偏差的两种修法：把两个分布糊到一起，或者让它们相等

第 1 步，误差怎样传递。设生成第 \(t+1\) 帧的模型是 \(\mathbf x_{t+1} = f(\mathbf x_t)\)，真实轨迹是 \(\mathbf x^*_t\)。在真实轨迹附近线性化，误差 \(\mathbf e_t = \mathbf x_t - \mathbf x^*_t\) 满足

\[ \mathbf e_{t+1}\approx J\,\mathbf e_t + \boldsymbol\varepsilon_t,\qquad J = \frac{\partial f}{\partial \mathbf x}\Big|_{\mathbf x^*_t} \]

\(\boldsymbol\varepsilon_t\) 是每帧新产生的误差。\(J\) 在误差所在方向上的放大系数 \(L\) 决定一切：\(L<1\) 时误差的方差收敛到 \(\sigma_\varepsilon^2/(1-L^2)\)；\(L = 1\) 时像随机游走一样随 \(\sqrt t\) 增长；\(L>1\) 时指数增长。

第 2 步，teacher forcing 为什么管不住 \(L\)。训练只在真实上下文 \(\mathbf x^*_t\) 上进行，损失只约束 \(f\) 在数据流形上的取值，对“偏离流形的方向”上 \(f\) 怎样变化毫无约束。带残差连接的网络在没学过的方向上倾向于原样传递（\(L\approx 1\)），有时还会放大。玩具里，教师强制学到的伪影方向 \(L = 1.00\)。

第 3 步，加噪等于什么。对线性模型 \(\mathbf x_{t+1} = W\mathbf x_t\)，在上下文上加方差 \(\sigma^2\) 的各向同性噪声后求平方损失的期望：

\[ \begin{aligned} &\mathbb E_{\boldsymbol\xi}\big\|W(\mathbf x + \sigma\boldsymbol\xi) - \mathbf y\big\|^2 \\ &\quad= \|W\mathbf x - \mathbf y\|^2 + \sigma^2\|W\|_F^2 \end{aligned} \]

交叉项期望为 0，于是加噪恰好等于给 \(W\) 加了一个 \(\sigma^2\) 的权重衰减（Bishop, 1995）。玩具的模型是 \(W = I + M\)，对 \(M\) 有强度 \(\rho\) 的权重衰减（模仿“默认照抄”）。逐方向求解可得：在数据没有能量的伪影方向，增益 \(L = \rho/(\sigma_{\text{dir}}^2+\rho)\)；在信号方向（信号能量为 \(\lambda\)），增益约为 \((\lambda+\rho)/(\lambda+\sigma_{\text{dir}}^2+\rho)<1\)，\(\sigma_{\text{dir}}^2\) 是噪声落在这个方向上的方差。玩具里每个频率是一对坐标，\(\sigma_{\text{dir}}^2 = 2\sigma^2\)；\(\rho = 0.05\)，\(\lambda\approx 9.3\)。\(\sigma = 0.25\) 时伪影方向 \(L = 0.05/(0.125+0.05)\approx 0.29\)，信号方向每帧乘约 0.987，\(0.987^{64}\approx 0.43\)，64 帧后只剩约四成。噪声加在了所有方向上，模型的“保守”也作用在了所有方向上。

第 4 步，用 KL 看加噪。换个角度：加噪后真实上下文与生成上下文的分布差异是 \(a_s^2\|\boldsymbol\delta\|^2/2b_s^2\)（公式卡）。加噪并没有让两个分布相等，只是把它们都糊开，直到重叠得足够多。糊得越开，重叠越多，上下文里的有用信息也越少。

第 5 步，自我强制让两个分布相等。训练时的上下文直接从模型自己的生成分布里采：\(q_{\text{训练}}(\mathbf c) = q_{\text{模型}}(\mathbf c)\)，不匹配从定义上就是 0。模型见到的正是自己会犯的那种错，在误差真正出现的方向上学会纠正（玩具里伪影方向 \(L\approx 0.57\)，信号方向的增益和教师强制一样接近 1），在信号方向上不需要变保守。代价有两个：训练时要真的把视频生成出来，比 teacher forcing 贵得多；自己生成的上下文没有逐帧的标准答案，损失只能是分布级的（DMD、对抗损失等），要靠一个强的老师来判断“像不像真视频”。

这个推导告诉我们：加噪是用一个通用的噪声分布去覆盖未知的误差分布，覆盖得越全，付出的信息损失越大；自我强制直接在真实的误差分布上训练，不需要猜，但要付出训练时生成的算力。这和语言模型从离线蒸馏走向在线策略蒸馏（第 章）是同一个道理：在自己的分布上学。

实时与长视频：少步、缓存与记忆

少步蒸馏：为什么实时生成成为可能

上一节的自回归解决了“边生成边播放”的结构问题，但每一块仍要去噪几十步。实时的要求很具体：生成一块的时间不能超过这一块的播放时长（\(S\) 是每块的去噪步数）。

每块的潜帧数
16 帧每秒，每块 3 个潜帧 = 12 帧 = 0.75 秒。4 步、\(c = 1\)：\(\tau\le 187\) 毫秒，1.3B 的模型处理一块（832×480 时 \(3\times 1560 = 4680\) 个 token）做得到。50 步加 CFG（100 次前向）：\(\tau\le 7.5\) 毫秒，做不到。Self Forcing 用 4 步，在单张 H100 上达到每秒 17 帧，首帧延迟 0.69 秒。

要满足这个不等式，前三样缺一不可，第四样决定质量。①因果：每块只看自己和前面的块，去噪完就定稿、立刻播放；双向模型的第 1 帧依赖最后一帧的噪声，只能整段算完才出画面。②KV 缓存：定稿块的 K、V 存起来，之后每步只算新块自己的 token。③少步：50 步加 CFG 时每次前向只剩 7.5 毫秒，所以要蒸馏到 4 步左右，并把 CFG 也蒸进模型（\(c = 1\)）。少步蒸馏本身（一致性模型、对抗蒸馏、DMD）见第 章「少步生成」，视频特有的是第四件事：④老师可以看见未来。CausVid（2024-12）用一个双向的多步模型当老师、因果的少步模型当学生，用 DMD 蒸馏，效果比从因果模型蒸馏更好：老师的每一帧都参考了整段视频，对“什么样的视频是好的”判断更全面，学生只需在看不到未来时尽量接近它。CausVid 把 50 步压到 4 步，在自研的 352×640 模型上单卡每秒 9.4 帧。Self Forcing 沿用这套初始化，在同一个 Wan-1.3B 骨干上与 CausVid 速度相同（每秒 17 帧、首帧 0.69 秒），把训练换成自己滚动生成后，质量从 VBench 81.2 提到 84.3。分布匹配蒸馏恰好不需要逐帧答案，这让它和“在自己生成的帧上训练”天然配合。

细节：为什么双向不能流式，因果块的注意力要算多少

第 1 步，双向模型为什么不能流式输出。联合去噪的每一步里，每一帧都通过注意力看所有帧，包括后面的帧。第 1 帧的最终结果依赖第 121 帧的初始噪声，所以必须把整段的全部 \(S\) 步做完，才能输出第 1 帧。首帧延迟等于整段的生成时间，几分钟起。

第 2 步，因果掩码让帧可以“提前定稿”。第 \(j\) 块只看第 \(1,\dots,j\) 块。第 \(j\) 块去噪完成后，后面的任何计算都不会再改变它，可以立刻解码播放。它的 K、V 存进缓存，之后每一块的每一步只需算新块自己的 token，再读取缓存。一次前向的注意力代价约为 \(n_{\text{块}}\times(n_{\text{块}} + n_{\text{缓存}})\)，而不是整段的 \(n^2\)。

第 3 步，实际的前向要多久。Self Forcing 实测每秒 17 帧，每块 12 帧约 0.71 秒；4 步下平均每次前向（摊上 VAE 解码）约 175 毫秒，刚好落在 187 毫秒的预算以内。50 步加 CFG 要求的 7.5 毫秒比它短二十多倍，靠工程优化补不回来，只能减步数。

这个推导告诉我们：实时视频生成是几件事的乘积：因果结构让帧能提前定稿，KV 缓存把每次前向的注意力从整段的 \(n^2\) 降到 \(n_{\text{块}}(n_{\text{块}}+n_{\text{缓存}})\)，少步蒸馏把每块的调用次数从 100 降到 4。缺一件，预算就差一个数量级。

长视频的记忆

流式生成可以无限延长，但 KV 缓存随长度线性增长，注意力的代价也随之增长。几种办法：

  • 滑动窗口。只保留最近几秒的 KV。显存固定，但窗口外的内容会被“忘掉”。
  • 帧汇。类似语言模型的注意力汇，永远保留最开头的几帧，让整段视频有一个稳定的参照。NVIDIA 的 LongLive（2025-09）用“前两帧 + 短窗口”，在单张 H100 上以每秒 20.7 帧生成长达 240 秒的视频，并能中途换提示词。
  • 压缩历史。FramePack（2025-04）按“越久远越不重要”给历史帧分配越来越少的 token：
\[ \sum_{i=0}^{\infty}\frac{\htmlClass{sym-Lf}{L_f}}{\htmlClass{sym-lam}{\lambda}^{i}} = \frac{\lambda}{\lambda-1}\,L_f \]
最近一帧用完整的 \(L_f\) 个 token，往前每一帧缩小 \(\lambda\) 倍（通过改变 patch 的大小）。这是一个等比级数，无论历史多长，上下文总长度都不超过 \(\lambda L_f/(\lambda-1)\)。
\(L_f\)
一个完整潜帧的 token 数
\(\lambda\)
每往前一帧的压缩倍数，大于 1
\(L_f = 1560\)（一个 480p 潜帧），\(\lambda = 2\)：最近一帧 1560 个 token，再往前 780、390、195……总共不超过 3120 个。计算量和生成一张图差不多，与视频长度无关。

这些方法都让“生成几分钟”成为可能：Self-Forcing++（2025-10）把训练时的滚动延长到远超老师的 5 秒，生成了 4 分 15 秒的视频。它们共同的弱点是没有真正的长期记忆：一个物体被挡住很久再出现，样子可能变了。按需检索过去画面、维护三维场景记忆，是第 章的问题。

自回归会取代双向联合去噪吗

主张
长视频、直播式生成、可交互的世界都只能自回归。Self Forcing 在 5 秒视频上的质量已与同规模的双向模型相当（VBench 84.3 对 Wan2.1-1.3B 的 84.3）；和这个双向模型比，首帧延迟从 103 秒降到 0.69 秒（约 150 倍），吞吐从每秒 0.78 帧提到 17 帧（约 22 倍）；MAGI-1 证明了自回归视频可以做到 24B 的规模。
反方
目前公开技术细节的高质量文生视频模型（Wan、HunyuanVideo、Seedance 1.0）在一个片段内都是双向去噪。实时自回归模型几乎都从双向老师蒸馏而来（Self Forcing 的老师是 Wan 2.1；CausVid 论文的老师是自研的、结构类似 CogVideoX 的双向 DiT，开源代码换成了 Wan），质量上限由老师决定；超过训练长度后仍会逐渐退化，且没有长期记忆。
现在怎么看
界线在模糊：Self Forcing 每块 3 个潜帧、MAGI-1 每块 24 帧，块内双向、块间因果。问题变成“块取多大”：块越大越接近联合去噪的质量，块越小越实时。做电影片段和做可交互世界，答案不同。

Sora 之后：降本、声音、镜头与参考

Sora 之后的进展，几乎都能落到前面某个公式的某一项上：减少 \(n\)（更狠的压缩，如 Wan 2.2 5B 的 4×16×16 VAE、Seedance 的 16 倍空间压缩）；让每步更便宜（稀疏注意力），或者在每步计算不变的前提下加容量（下面按噪声分工的专家）；减少步数（上一节的蒸馏）；或者扩大“一个样本”包含的东西（音频、多个镜头、参考素材）。时间线见章末演进史，这里讲其中两类：每步的计算（Wan 2.2），以及一个样本包含什么（声音、镜头、参考）。

按噪声分工的专家：Wan 2.2

动的是“每步的计算”这一项：容量翻倍，每步计算不变。Wan 2.2（2025-07）把去噪过程按噪声水平切成两段，各用一个约 14B 的专家：高噪声专家负责前半程（构图、运动），低噪声专家负责后半程（细节）。总参数 27B，每一步只用其中一个，计算量和显存与 14B 模型几乎相同。这叫按噪声分工的 MoE，和第 章按 token 路由的 MoE 不同：它没有路由器，切换完全由去噪进度决定，切换点按信噪比（SNR，\(a_t^2/b_t^2\)，流匹配下为 \(((1-t)/t)^2\)）的一个阈值来定。为什么前半程只管构图、后半程只管细节：每个频率在信噪比约为 1 时“定下来”，分界频率随 \(\sqrt{\mathrm{SNR}}\) 从低频扫向高频，推导和第 章「图生图的强度」的尺度截止完全相同。

原生音频：把声音放进同一个样本

动的是“一个样本包含什么”。2025 年以前的主流（扩散）视频模型都是哑的，声音要靠另一个模型后期配上。分开生成时，视频模型画嘴型时不知道要说什么词，配音一侧只能事后去对齐，口型和音效的时机都靠后处理。联合生成让声音和画面在同一个去噪过程里互相作条件，对齐不靠后处理。Veo 3（2025-05）把对白、音效、环境声和视频一起生成，Sora 2（2025-09）、Seedance、Kling 跟进；开源方面，Ovi（2025-10）和 LTX-2（2026-01）公开了做法。

公开了做法的 Ovi 和 LTX-2 结构大同小异：一个视频塔、一个音频塔，每一层通过交叉注意力交换信息，两边的时间位置用同一套时间坐标对齐（LTX-2 在跨模态注意力里只保留 RoPE 的时间分量）。声音本身的 token 很少：LTX-2 的音频编码器每秒约 25 个 token，5 秒是 125 个，只有红球视频 11 万个 token 的千分之一，几乎不增加计算。这种做法叫音视频联合生成（joint audio-video generation）。难点不在算力，而在数据：需要大量声音与画面严格对齐、带文字转写的视频，以及评价口型同步的方法。

多镜头与参考

一段 5 秒的单镜头还不是影片。多镜头生成（multi-shot generation）在一次生成里包含多个镜头和镜头切换，并让同一个角色在不同镜头里保持一致。Seedance 1.0（2025-06）在位置编码里加入镜头信息来支持多镜头叙事；据报道，Kling 3.0（2026-02）一次最多生成 6 个镜头、15 秒。参考输入则把用户给的图片、视频片段、音频也编码成 token，拼进同一条序列：Seedance 2.0（2026-02）最多接收 3 段视频、9 张图和 3 段音频，生成 4–15 秒、480p 或 720p 的音视频。

它们的代价都落在 token 数上：参考素材越多、镜头越长，\(n\) 越大，注意力的平方代价又回来了。据报道，阿里的 Wan 3.0（2026-08）把单次生成延长到 30 秒、1080p 并带音频，没有开放权重。

视频模型学到了什么：物理与通用视觉

逼真的画面 ≠ 正确的物理

乐观
Sora 的技术报告题为“视频生成模型作为世界模拟器”：模型在没有任何物理先验的情况下，随规模涌现出三维一致性、遮挡后物体仍在、简单的交互（画笔留下笔迹、咬过的汉堡留下缺口），这说明扩大规模就能逐步学到物理规律。报告自己也承认，玻璃碎裂这类基本的物理交互仍然出错。
质疑
字节跳动的研究（Kang 等, 2024）用简单的 2D 物理场景训练视频模型：在训练分布内泛化完美；没见过的属性组合，随模型和数据规模增大可测地改善，但仍不完美；速度、大小等数值超出训练范围就失败。模型更像是在“检索最相似的训练样例”，优先匹配颜色，其次大小、速度，最后才是形状，而不是学到了运动定律。Google 的 Physics-IQ（2025）测试了多个商用模型，发现即使画面极为逼真，在预测物体运动、液体流动等任务上，物理理解得分都很低。
现在怎么看
视频模型学到的是“看起来合理”的统计规律，而非可以外推的物理定律；在常见场景下两者难以区分，在罕见场景、长时间预测下差距暴露。这是用视频模型做机器人和自动驾驶仿真（第 章）时必须警惕的地方。

“检索最相似的样例”和第 章“完美的去噪器只会背书”是同一个方向，只是真实模型会在样例之间插值、组合，离训练分布越远越不可靠。

意外：视频模型能“一帧一帧地思考”，零样本解决视觉任务

原以为
视频生成模型只会生成好看的视频，做不了检测、分割、推理这类“理解”任务。
实际发现
Google DeepMind 的 Wiedemer 等（2025）给 Veo 3 一张迷宫图和一句提示“让小球走到终点”，它生成的视频里小球真的走出了迷宫；给一张图让它“画出边缘”“把物体分割出来”“把这个形状对称补全”，它也能零样本完成，许多任务从未专门训练过。作者把这称为帧链（chain-of-frames），类比语言模型的思维链：视频的逐帧演化本身就是一步步的推理。
为什么
与语言模型从“预测下一个词”中学到通用能力一样，视频模型从“预测像素随时间的变化”中学到了大量关于视觉世界的通用知识；任务只要能表述成“画面接下来应该怎样变化”，它就有机会完成。
现在怎么看
视频模型可能成为视觉领域的“基础模型”，就像语言模型之于文字。但它们在精确推理上仍不可靠，这一方向与上面的物理争议密切相关，也直接引出了世界模型的研究。

常见误解

  • 视频生成就是一帧一帧地生成图像。主流模型把整段视频作为一个样本联合去噪，帧与帧之间通过注意力直接交流；逐帧独立生成连贯的概率随帧数指数下降。
  • 画面逼真说明模型懂物理。逼真来自统计规律；在没见过的条件下，物理常常出错。
  • 视频长度可以随便加长。联合去噪的长度受 token 数和显存限制；自回归延长会累积误差、逐渐漂移，靠强制训练、帧汇、压缩历史才能撑到几分钟，长期记忆仍未解决。

级联：先生成小而慢的视频，再逐级放大

卡在哪
在像素空间里一次生成高清长视频，算力承受不了。
怎么解决
级联扩散（cascaded diffusion）：一个基础模型先生成低分辨率、低帧率的短片，再用多个超分辨率（超分）模型逐级提高空间分辨率和帧率。Imagen Video 的基础模型生成 16 帧、40×24、每秒 3 帧，经过 3 个时间超分和 3 个空间超分，得到 128 帧、1280×768、每秒 24 帧（5.3 秒），7 个模型共 116 亿参数。Make-A-Video 在文生图模型上加时间层，完全不用成对的文字-视频数据。
代价
7 个模型各自采样，前一级的错误会被后一级放大；每个模型都要单独训练；时长固定。
引出
能不能先压缩，再在小得多的空间里一次去噪？
退居其次把视频当语言：离散 token 自回归
Phenaki（2022-10）用时间上因果的分词器把视频变成离散 token，按一串提示词生成可变长度的视频；VideoPoet（2023-12）用大语言模型预测 MAGVIT-v2 的视频 token 和 SoundStream 的音频 token：17 帧、128×128 的视频变成 \(5\times 16\times 16 = 1280\) 个 token，一张图是 256 个。它们在画质上输给了扩散，但留下了两样东西：因果的视频分词器（今天 3D 因果 VAE 的前身），以及“视频和音频放进同一条序列”的想法。

潜空间视频与数据筛选

卡在哪
像素空间的级联太贵；没有足够大、足够干净的视频数据。
怎么解决
Video LDM（2023-04）把时间层插进预训练好的潜空间图像模型，在 VAE 的潜空间里做视频扩散，并微调解码器减少闪烁。Stable Video Diffusion（2023-11）把训练分成三阶段：图像预训练、大规模视频预训练、少量高质量视频微调；它证明了数据筛选的价值：从约 5.8 亿段片段里按运动量、字幕、文字遮挡、美观度筛出 1.5 亿段，筛过的数据训练出的模型更好。

VAE 还是逐帧的二维编码，时间上没有压缩；U-Net 难以继续放大；只有 2–4 秒。
引出

AnimateDiff（2023-07）在冻结的文生图模型里插入可训练的运动模块，让社区已有的各种风格模型和 LoRA 直接“动起来”。它不追求最强的画质，而是复用了庞大的图像生态，这条思路后来演变成各种图生视频、视频编辑的插件。
2024

Sora：时空 patch + DiT，视频进入规模化

卡在哪
U-Net 难以扩展；不同时长、分辨率、宽高比要裁剪成固定尺寸，丢掉了大量数据和构图信息。
怎么解决
Sora（2024-02）在时间和空间上一起压缩，切成时空 patch，用 DiT 去噪；按原始尺寸训练，生成长达一分钟的视频。同年 CogVideoX（2024-08）开源了 3D 因果 VAE + 全 3D 注意力，Movie Gen（2024-10）用 30B 模型处理 7.3 万个 token（16 秒、每秒 16 帧）。
代价
token 数巨大，注意力占大部分算力，生成一段要几分钟到几十分钟；物理错误常见；没有声音。

两条并行的线：开源模型追上闭源并压低成本；把整段去噪改成边生成边播放。

开源追平与降本

卡在哪

自测

1. 10 秒、24 帧每秒、1080p（1920×1080）的视频，时间压缩 4 倍、空间压缩 16 倍、patch 为 1（不再切）。大约多少个 token？注意力对数是红球视频的多少倍？
241 帧压成 \(1 + 240/4 = 61\) 个潜帧；每帧 \(120\times 67.5\approx 8100\) 个 token（按 \(1920/16\times 1080/16\)）；共约 49.4 万个。注意力对数之比 \((494{,}100/111{,}600)^2\approx 19.6\) 倍。拆开看：潜帧数 61/31 ≈ 1.97 倍（时长约 2 倍），面积 \((1920\times1080)/(1280\times720) = 2.25\) 倍；每个 token 仍对应 16×16 个像素（16 倍压缩、不切 patch，和红球的 8 倍压缩加 2×2 patch 一样），压缩率没变。所以 token 数约 \(1.97\times 2.25\approx 4.4\) 倍，平方后近 20 倍。
2. 训练集里同一个物体有 4 种运动方式，视频 6 帧，用玩具里的完美去噪器。(a) 图像模型只看本帧、但知道自己是第几帧，逐帧生成得到连贯视频的概率是多少？(b) 如果它连自己是第几帧都不知道，候选是全部 24 张帧图呢？(c) 联合去噪呢？
(a) 每帧各自在 4 种运动里选一种，全部相同的概率是 \(4\times 4^{-6} = 4^{-5}\approx 0.1\%\)。(b) 每帧要从 24 张图里恰好挑中“同一段视频的第 \(f\) 帧”，4 段视频各有一种挑法：\(4\times 24^{-6}\approx 2\times 10^{-8}\)，连帧序都会乱。(c) 所有帧共享一组后验权重（每帧的证据相加），收缩到同一种运动，概率为 1。
3. 要以每秒 24 帧实时生成，每块 3 个潜帧（12 帧）。4 步、无 CFG 时，每次前向最多能用多少毫秒？50 步加 CFG 呢？
每块的播放时长是 \(12/24 = 0.5\) 秒。4 步、\(c = 1\)：\(500/4 = 125\) 毫秒。50 步加 CFG 共 100 次前向：每次 5 毫秒。后者对十亿参数级的模型不现实，所以实时生成必须做少步蒸馏，并把 CFG 也蒸馏进模型。
