自回归生成：训练时预测下一个 token，生成时一个一个地采样

GPT 类模型只做一件事：给定前文，输出下一个 token 的概率分布。训练时，让真实的下一个 token 概率尽量高；生成时，从分布里取一个 token 接到末尾，再预测下一个。对话、写代码、几万字的推理过程，都是这个循环跑很多次的结果。这一章先用 5 个词把训练和生成算一遍，再逐段讲训练目标、怎样挑词、怎样打破“一次一个”。

从零开始：一个只有 5 个词的语言模型

这一节不碰 Transformer，用一个只认识 5 个词的“语言模型”，把后面要用的概念各算出一个具体数字，最后再放回真实的大模型。

词表、前缀和下一个词的分布

这个模型的词表只有 5 个词：猫、吃、鱼、饭、句号“。”。它的全部工作是：读入一段前缀，给词表里每个词打一个分数（logit），再用 softmax 把分数变成概率（第 章）。前缀是“猫 吃”时，假设它打出的分数是：鱼 2、饭 1、。0、猫 −1、吃 −1。取指数再归一化，概率是鱼 62.4%、饭 23.0%、。8.4%、猫 3.1%、吃 3.1%：分数每差 1，概率就差 \(e\approx 2.7\) 倍。

“猫吃猫”不太可能，但概率不是 0。一个语言模型就是这样一个函数：任意前缀进去，一个词表大小的分布出来。

信息量与熵：衡量“意外”

要评价这个模型，先得能衡量“一个结果有多出乎意料”。概率为 \(p\) 的事件发生时，它带来的信息量（surprisal，也叫惊讶度）是 \(-\log_2 p\) 比特：概率 1/2 的事是 1 比特，1/8 的事是 3 比特，必然发生的事是 0 比特。取对数的好处是：两件独立的事同时发生，概率相乘，信息量相加。对数以 2 为底时单位是比特；用自然对数 ln 时单位叫 nat，1 nat ≈ 1.443 比特。把一个分布所有结果的信息量按概率加权平均，就是这个分布的熵：

\[ \htmlClass{sym-I}{I(w)} = -\log_2 p(w), \qquad \htmlClass{sym-H}{H(p)} = \sum_w p(w)\,\htmlClass{sym-I}{I(w)} = -\sum_w p(w)\log_2 p(w) \] 熵 = 平均信息量。5 个词均匀时 H = log₂5 ≈ 2.32 比特；总是同一个词时 H = 0
信息量：这一次的结果让人多意外。熵：还没看到结果之前，预计平均会有多意外，也就是这个分布“有多不确定”。
\(I(w)\)
结果 \(w\) 的信息量，单位比特
\(H(p)\)
分布 \(p\) 的熵，单位比特
上面的分布：\(I(\text{鱼}) = 0.68\)、\(I(\text{饭}) = 2.12\)、\(I(\text{。}) = 3.57\)、\(I(\text{猫}) = I(\text{吃}) = 5.01\) 比特。按概率加权：\(0.624\times0.68 + 0.230\times2.12 + 0.084\times3.57 + 2\times0.031\times5.01 \approx 1.52\) 比特，比均匀的 2.32 比特小：模型已经比瞎猜有把握。

熵还有一个直观的读法：\(2^{H}\) 是“等效的候选数”。熵 1.52 比特的分布，不确定程度相当于在 \(2^{1.52}\approx 2.9\) 个等可能的词里挑一个。

打分：交叉熵与困惑度

训练语料里，“猫 吃”后面真正出现的是“鱼”。模型给它 62.4%，信息量 0.68 比特：意外不大，预测得不错。如果真实的词是“猫”，信息量是 5.01 比特：模型被吓了一跳。用模型的概率去衡量真实出现的词有多意外，这个量叫交叉熵。熵按模型自己的概率加权，是模型自以为的不确定；交叉熵按真实数据加权，是模型实际被吓到了多少。对一段文本，就是每个位置的信息量取平均。

看一整句“猫 吃 鱼 。”。设模型在每一步给真实词的概率依次是 0.4（开头是“猫”）、0.5（“猫”后面是“吃”）、0.624（“猫吃”后面是“鱼”）、0.8（“鱼”后面是句号）：

\[ \begin{aligned} \text{总信息量} &= -\log_2 0.4 - \log_2 0.5 - \log_2 0.624 - \log_2 0.8 = 1.32 + 1 + 0.68 + 0.32 = 3.32\ \text{比特}\\ \text{交叉熵} &= 3.32 / 4 = 0.83\ \text{比特 / 词}\ \ (= 0.576\ \text{nat / 词}) \end{aligned} \]

交叉熵越小，模型越好；训练语言模型，就是在几万亿个 token 上把它压低。它的数值不直观，常换算成困惑度：\(2^{0.83} = e^{0.576}\approx 1.78\)。和熵的“等效候选数”一样读：这个模型在这句话上，平均相当于每一步在 1.78 个等可能的词里挑。一个什么都不懂、在 5 个词里均匀乱猜的模型，交叉熵是 \(\log_2 5 = 2.32\) 比特，困惑度是 5。

3.32 比特还有一个读法，「困惑度与预测即压缩」一节会展开：它就是用这个模型把“猫吃鱼。”压缩成 0 和 1 时需要的长度。预测得越准，压得越短。

生成：温度与一次采样

现在反过来，用这个模型写字。前缀“猫 吃”之后选哪个词？最简单的办法是总选概率最高的“鱼”，这叫贪心解码。另一种是采样：把 5 个词按概率排成一条总长为 1 的线段（鱼占 [0, 0.624)，饭占 [0.624, 0.854)，句号占 [0.854, 0.938)，……），抽一个 0 到 1 之间均匀分布的随机数 \(u\)，落在哪一段就选哪个词。每个词被选中的频率等于它的概率。为什么不总选最大的？同一个前缀会永远写出同一段话，长文还会掉进循环（后面专门讲），所以开放式的生成通常用采样。

采样之前，常先把所有 logit 除以一个正数 \(T\)，叫温度：

\[ p_T(w) = \frac{\exp\big(z_w / \htmlClass{c-new}{\htmlClass{sym-T}{T}}\big)}{\sum_v \exp\big(z_v / \htmlClass{sym-T}{T}\big)} \]
softmax 之前把所有 logit 除以温度 \(T\)。\(T<1\) 放大差距，分布变尖、更保守；\(T>1\) 缩小差距，分布变平、更发散；\(T\to 0\) 就是贪心。名字来自统计物理的玻尔兹曼分布 \(p\propto e^{-E/kT}\)：logit 相当于负的能量。
\(T\)
温度。常用 0.6–1.0；DeepSeek-R1、Qwen3 的思考模式都推荐 0.6 左右
同一个随机数 \(u = 0.70\)，三种温度（概率依次是鱼、饭、。、猫、吃）：
\(T = 0.5\)：(86.3%, 11.7%, 1.6%, 0.2%, 0.2%)，熵 0.68 比特，\(u\) 落在“鱼”。
\(T = 1\)：(62.4%, 23.0%, 8.4%, 3.1%, 3.1%)，熵 1.52 比特，落在“饭”。
\(T = 2\)：(41.3%, 25.1%, 15.2%, 9.2%, 9.2%)，熵 2.07 比特，落在“。”。
排序不变，只是差距被放大或缩小。

温度越高，越常选到靠后的词。\(T = 2\) 时，“猫”和“吃”加起来有 18.4% 的概率：大约每 5 次就写出一次“猫吃猫”或“猫吃吃”。温度只改形状，不会把任何词的概率变成 0；要彻底排除这些词，还得把尾部截掉。最常用的截断叫 top-p：从高到低累加概率，只在累计刚达到 \(p\) 的那几个词里抽（「温度与截断」一节）。

把一段文本的概率拆成一串条件概率

任何一段文本 \(x_1, x_2, \dots, x_n\) 的联合概率，都可以用条件概率的链式法则拆开。这一步对任何分布都成立，不需要任何假设；模型 \(p_\theta\) 要做的，就是逼近其中每一个条件概率：

\[ p_\theta(x_1, x_2, \dots, x_n) = \prod_{t=1}^{n} p_\theta\big(\htmlClass{sym-xt}{x_t} \,\big|\, \htmlClass{sym-prefix}{x_{<t}}\big) \]
整段文本的概率 = 第 1 个 token 的概率 × 在第 1 个之后第 2 个的概率 × 在前两个之后第 3 个的概率 × …… 模型只需要学会一件事：给定前缀，预测下一个 token。
\(x_t\)
第 \(t\) 个 token；\(n\) 是序列长度
\(x_{<t}\)
它前面的所有 token（前缀）
“今天 / 天气 / 很好”：\(p(\text{今天})\times p(\text{天气}\mid\text{今天})\times p(\text{很好}\mid\text{今天 天气})\)。若三个条件概率分别是 0.02、0.3、0.4，整句概率是 \(0.0024\)。玩具里的“猫 吃 鱼 。”是 \(0.4\times0.5\times0.624\times0.8\approx 0.0998\)。

按这种方式从左到右逐个生成的模型叫自回归模型：每一步的输出成为下一步的输入。训练目标是让真实文本的概率尽量大。几千个小于 1 的数相乘会下溢，也难求导，所以取对数，把乘积变成求和，再取负、求平均：

\[ \mathcal L(\theta) = -\frac{1}{n}\sum_{t=1}^{n}\log p_\theta\big(x_t \mid x_{<t}\big) \]

这就是「从零开始」里的交叉熵（每个位置信息量的平均），只是训练时通常用自然对数，单位是 nat。它对“自信地答错”惩罚很重：给真实 token 0.5 的概率，损失 0.69；给 0.01，损失 4.6；概率趋于 0，损失趋于无穷。最小化它等于最大似然，也等于让模型分布向真实分布靠拢（KL 散度变小），下限是数据本身的熵而不是 0（见下面的折叠）。

训练时整段文本一次输入，因果掩码让 \(n\) 个位置的预测在一次前向中并行完成。每一步的输入都是真实的前缀，而不是模型自己生成的前缀，这叫teacher forcing。生成时则不同：前缀是模型自己写的，只能一个一个来。训练快、生成慢，根源就在这里。

为什么偏偏是交叉熵：它等于最大似然，也等于缩小与真实分布的 KL

第 1 步，最大似然。训练数据整体的概率是每段文本概率的乘积，取对数后是逐 token 对数概率的总和。让它最大，就是让平均的 \(-\log p_\theta\)，也就是交叉熵最小。所以“最小化交叉熵”和“最大似然估计”是同一件事。

第 2 步，拆成熵和 KL。设真实的文本分布是 \(p_{\text{data}}\)。在大量数据上平均：

\[ \mathbb E_{x\sim p_{\text{data}}}\big[-\log p_\theta(x)\big] = \underbrace{\mathbb E\big[-\log p_{\text{data}}(x)\big]}_{H(p_{\text{data}})\text{，与 }\theta\text{ 无关}} + \underbrace{\mathbb E\Big[\log\frac{p_{\text{data}}(x)}{p_\theta(x)}\Big]}_{D_{\text{KL}}(p_{\text{data}}\,\|\,p_\theta)\ \ge\ 0} \]

这只是在 \(\log\) 里乘一个 \(p_{\text{data}}\) 再除一个。第一项是数据本身的熵，是任何模型都消不掉的不确定性；第二项是 KL 散度 \(D_{\text{KL}}(p\,\|\,q) = \sum p\log(p/q)\)，衡量模型分布和真实分布差多少，恒 \(\ge 0\)，两者相同时为 0。所以最小化交叉熵就是让模型分布逼近真实分布，损失的下限是数据的熵，而不是 0。

第 3 步，梯度。对单个位置，设 logit 为 \(\mathbf z\)，\(\mathbf p = \operatorname{softmax}(\mathbf z)\)，真实 token 的独热向量为 \(\mathbf y\)。利用第 章的 softmax 雅可比 \(\partial p_i/\partial z_j = p_i(\delta_{ij} - p_j)\)：

\[ \frac{\partial \mathcal L}{\partial z_j} = -\frac{\partial \log p_y}{\partial z_j} = -(\delta_{yj} - p_j) = p_j - y_j \]

代回玩具：真实词是“鱼”，梯度 \(= \mathbf p - \mathbf y = (-0.376,\ +0.230,\ +0.084,\ +0.031,\ +0.031)\)。沿负梯度走一步（学习率 1），logit 变成 \((2.38,\ 0.77,\ -0.08,\ -1.03,\ -1.03)\)，“鱼”的概率从 62.4% 升到 73.9%，这个位置的损失从 0.47 降到 0.30 nat。

这个推导告诉我们：梯度就是“预测概率减去正确答案”：真实 token 的 logit 被往上推 \(1 - p_y\)，其它每个 token 被往下推 \(p_j\)。形式极其简单，这是交叉熵加 softmax 成为标准组合的原因。而损失降不到 0、只能降到数据的熵，后面讲规模定律时会再次见到（第 章的不可约损失）。

从计数到神经网络：每一代语言模型在修什么

「从零开始」里那个 5 词模型的 logit 是手写的。真正的问题是：给定任意前缀，这组概率从哪来？七十多年里答案有过四种，每一种都在修上一种的一个具体毛病。

n-gram：直接数。最早的语言模型是n-gram：假设下一个 token 只依赖前 \(n-1\) 个 token，直接用训练语料里的出现次数估计概率：

\[ p(x_t \mid x_{t-n+1}, \dots, x_{t-1}) \approx \frac{\htmlClass{sym-cnt}{\operatorname{count}}(x_{t-n+1}, \dots, x_{t-1}, x_t)}{\operatorname{count}(x_{t-n+1}, \dots, x_{t-1})} \]
在语料里找出所有“前面这 \(n-1\) 个词”出现的地方，看后面接的是什么，按次数算比例。
\(\operatorname{count}(\cdot)\)
这串 token 在训练语料里连续出现的次数

神经语言模型（2003）修的是“相似的上下文不共享统计”。Bengio 等的神经语言模型把计数换成了一个函数：每个词先查出一个向量（第 章的嵌入），把前 \(n-1\) 个词的向量拼起来，经过一个隐藏层，再用 softmax 输出下一个词的分布。训练中，出现在相似上下文里的词得到相近的向量（分布假说），于是“猫”上学到的东西自动用在“狗”上。在 Brown 语料上，测试困惑度 252，比当时最好的 n-gram 好约 24%。代价：窗口仍固定为 \(n-1\) 个词，训练很慢。

RNN 语言模型（2010）修的是固定窗口。循环神经网络每读一个词更新一次隐藏状态，理论上能记住任意长的历史；Mikolov 等（2010）报告，几个 RNN 语言模型混合后，困惑度比 5 元 Kneser-Ney 回退模型低约 50%。代价是只能串行训练，梯度消失让它实际只记得住几十个词（第 章）。

Transformer 解码器（2017–2018）修的是“压成一个向量、只能串行训练”。注意力让每个位置直接查看前文，因果掩码让整段文本并行训练（teacher forcing）；代价是生成时每个新 token 都要读一遍前面所有 token 的 K、V（第 章）。训练一旦可以并行，问题就变成了“能做多大”：GPT-2（2019）15 亿参数，GPT-3（2020）1750 亿（第 章）。

困惑度与“预测即压缩”

计数模型没见过的上下文就给不出合理的概率，神经语言模型能把相似的上下文连起来。这个差别可以直接量出来：拿一段模型没见过的文本，让模型给每个 token 打概率，平均信息量就是交叉熵，它的指数就是困惑度（\(\operatorname{PPL} = e^{\mathcal L}\)，「从零开始」里算过）。困惑度有一个陷阱：它依赖分词方式。词表大、每个 token 包含更多字符的模型，每 token 的损失自然更高。跨模型比较时，常用每字节比特数（bits per byte）：

\[ \text{bpb} = \frac{\sum_{t} -\log_2 p_\theta(x_t\mid x_{<t})}{\text{文本的 UTF-8 字节数}} = \frac{n\,\mathcal L/\ln 2}{\text{字节数}} \]
把整段文本的总损失换算成比特，再除以文本本身的字节数。分子分母都和怎么切 token 无关，所以不同分词器的模型可以直接比。
一段英文 4200 字节。模型 A 切成 1000 个 token，平均损失 2.3 nat/token：困惑度约 10，总比特 \(1000\times2.3/0.693\approx 3318\)，bpb ≈ 0.79。模型 B 词表更大，切成 800 个 token，每 token 损失 2.8 nat：困惑度 \(e^{2.8}\approx 16\)，看起来更差；总比特 \(800\times2.8/0.693\approx 3232\)，bpb ≈ 0.77，其实更好。

香农的信源编码定理说，模型给一段文本的概率是 \(p\)，就可以用约 \(-\log_2 p\) 比特把它编码下来，平均来说不可能更短。算术编码（arithmetic coding）把这件事做成了真正的压缩算法。拿“猫 吃 鱼 。”试一遍：从宽度为 1 的区间 [0, 1) 出发，每读一个词，就把当前区间切开，只留下模型分给这个词的那一段。猫 0.4，区间宽 0.4；吃 0.5，宽 0.2；鱼 0.624，宽 0.125；句号 0.8，宽 0.0998。最后这段宽 0.0998 的区间就代表整句话。区间越宽，越容易在里面找到一个位数很少的二进制小数：宽 \(w\) 的区间里一定能放下一个 \(\lceil -\log_2 w\rceil + 1\) 位的二进制小数（连同它后面任意的尾巴都还在区间里），这里是 \(\lceil 3.32\rceil + 1 = 5\) 位。这 5 位就是压缩结果；解码方用同一个模型、同样地切区间，就能逐个还原。

所以语言模型的损失就是它压缩文本的码长：预测得越准，压缩得越小，两者是同一件事；训练损失每降低 0.01 nat/token，压缩时每个 token 就少用 0.0144 比特。大模型的压缩能力来自推广：Delétang 等（2023）把 Chinchilla 70B 当压缩器，按 2048 字节切块时，把英文维基百科（enwik9）压到原大小的 8.3%，同样切块的 gzip 是 48.1%。

为什么交叉熵就是码长，而且没有更短的编码

第 1 步，码长和概率可以互换。一种不会产生歧义的编码（任何码字都不是另一个码字的开头，叫前缀码），各码字长度 \(\ell(x)\) 必须满足克拉夫特不等式 \(\sum_x 2^{-\ell(x)}\le 1\)：一个长 \(\ell\) 的码字，占掉了所有二进制串里 \(2^{-\ell}\) 的份额，总份额不能超过 1。反过来，满足这个不等式的任何一组长度都能构造出前缀码。所以“一套编码”和“一个概率分布” \(q(x) = 2^{-\ell(x)}\) 本质上是一回事：给某段文本分配短码字，就是认为它概率高。

第 2 步，平均码长等于交叉熵。用模型 \(p_\theta\) 来定码长，\(\ell(x)\approx -\log_2 p_\theta(x)\)（算术编码做到这一点，整段文本只多 2 比特左右）。文本来自真实分布 \(p_{\text{data}}\) 时，平均码长是

\[ \mathbb E_{x\sim p_{\text{data}}}\big[\ell(x)\big] \approx \mathbb E_{x\sim p_{\text{data}}}\big[-\log_2 p_\theta(x)\big] = H(p_{\text{data}}) + D_{\text{KL}}(p_{\text{data}}\,\|\,p_\theta) \]

中间一项就是以比特为单位的交叉熵；右边的拆分和「把一段文本的概率拆成一串条件概率」一节折叠里的推导完全相同。

第 3 步，不可能更短。对任何前缀码，令 \(Z = \sum_x 2^{-\ell(x)}\le 1\)，\(q(x) = 2^{-\ell(x)}/Z\)。则 \(\mathbb E[\ell] = \mathbb E[-\log_2 q] - \log_2 Z \ge \mathbb E[-\log_2 q] = H(p_{\text{data}}) + D_{\text{KL}}(p_{\text{data}}\,\|\,q) \ge H(p_{\text{data}})\)。这就是信源编码定理：平均码长不可能低于数据的熵。

第 4 步，逐 token 地做。算术编码不需要对整段文本建表：整段的概率是逐 token 条件概率的乘积，区间可以一个 token 一个 token 地切，只要模型能给出 \(p_\theta(x_t\mid x_{<t})\)，就能边读边编码。正文里“猫吃鱼。”的手算就是这一步。

这个推导告诉我们：交叉熵减去数据本身的熵，剩下的 KL 就是“因为模型不完美而多花的比特”。训练损失每降低 0.01 nat/token，压缩时每个 token 就少用 0.0144 比特。“预测得更准”和“压缩得更短”不是比喻，而是同一个数。

意外：只用文本训练的模型，压缩图像和音频胜过 PNG 和 FLAC

原以为
语言模型只会处理语言，对其它数据没有用处。
实际发现
同一篇论文把图像块和音频的原始字节当“文本”喂给 Chinchilla 70B，按论文表 1，ImageNet 图像块压到 48.0%（同样切块的 PNG 是 61.7%），LibriSpeech 音频压到 21.0%（FLAC 是 30.3%）。论文摘要里的 43.4% 和 16.4% 与表 1 不一致。计入模型本身的大小，就完全不划算了：这说明的是预测能力，不是实用压缩。
现在怎么看
“压缩即智能”成了一个流行的视角：Huang 等（2024）发现，模型在新文本上的压缩率与它在各类基准上的得分几乎呈线性关系。但压缩率高只是能力的必要条件之一，不能说明模型会规划、会可靠推理（见本章最后的争议）。

为什么“概率最高”的文本反而不好

怎样从分布里挑出一段好文字？最直接的想法是挑最可能的：贪心每步选最可能的 token，束搜索（beam search）更进一步：同时保留得分（对数概率之和）最高的几条部分序列（条数叫束宽，常取 4–10），每步把每条都扩展一个 token，再留下最好的那几条，以此逼近“整段概率最高”的序列。在翻译、语音识别这类答案比较确定的任务里，它曾是标配。但用在开放式生成上，Holtzman 等（2019）发现它写出的文本空洞、重复，他们称之为文本退化（neural text degeneration）：人类文本里每个 token 在模型下的概率波动很大，常常不是第一名；束搜索的文本每一步的概率都又高又平。

原因有两层。第一层，“最可能”本身就不典型：人写的文字是从分布里抽出来的一个样本，几乎所有样本都落在“每 token 信息量接近熵”的典型集里，而概率最高的那条序列每一步的信息量都远低于熵，在典型集之外。例如每个 token 独立地以 0.6 是 a、0.4 是 b，写 100 个：最可能的是全 a，可它只占 \(6.5\times10^{-23}\)，而 a 的个数在 50 到 70 之间的序列合计占 96.8%（见折叠）。

第二层是重复的自我强化：模型写了一个短语，下次在相似的上下文里，归纳头（第 章）会找到它、复制它，于是重复的概率比第一次更高。Xu 等（2022）测得，一句话在上文中重复的次数越多，模型继续重复它的概率就越高，几乎单调上升，最后停在一个上限附近。贪心一旦进入这个循环就出不来。下面的玩具模型把这个机制单独拿出来：先看默认的贪心，所选词的概率一圈比一圈高；把 s 拉到 0，循环还在，但概率不再升高；再切到束搜索和采样比较：

最可能的序列为什么不典型

用最简单的模型：每个 token 独立，以 0.6 的概率是 a、0.4 的概率是 b，写 100 个。

峰顶。概率最高的单条序列是 100 个 a：概率 \(0.6^{100}\approx 6.5\times10^{-23}\)，每 token 的信息量只有 \(-\log_2 0.6 = 0.74\) 比特。

典型的样本。真正抽一次，a 的个数在 60 附近。每条“恰好 60 个 a”的序列概率只有 \(0.6^{60}\,0.4^{40}\approx 5.9\times10^{-30}\)，比峰顶小 7 个数量级；但这样的序列有 \(\binom{100}{60}\approx 1.4\times10^{28}\) 条，合起来占 8.1%。a 的个数在 50 到 70 之间的序列合计占 96.8%，而“全是 a”这一条只占 \(6.5\times10^{-23}\)。

一般结论。独立同分布时，按大数定律，\(-\frac1n\log_2 p(x_1,\dots,x_n)\) 收敛到熵 \(H\)（这里 \(H = 0.97\) 比特）。几乎所有样本的每 token 信息量都接近 \(H\)，这些序列组成典型集；峰顶的 0.74 比特远低于 \(H\)，在典型集之外。语言模型也一样：人写的文本每 token 的信息量在熵附近起伏，贪心和束搜索追求的却是信息量最低的那条路，读起来自然空洞、可预测。

和重复的关系。有了自我强化，重复片段的每 token 信息量随圈数下降，趋于 0（演示里束搜索的概率逼近 100%）。所以对“整段概率”最优的搜索，会主动把文本推向重复；搜得越好，推得越狠。

这个推导告诉我们：“似然最高”不等于“质量最好”，好的文本应当像一个典型样本。这是开放式生成用采样、不用搜索的根本原因。2022 年的典型采样（typical sampling）干脆把“每 token 信息量接近熵”写成了截断规则。

工程上的对策有两类。一是用采样代替贪心和束搜索：采样偶尔选到非第一名的词，就跳出了正在形成的循环。二是直接压低已经出现过的 token，即重复惩罚：

意外：精确搜索找到的“最可能译文”，一半以上是空的

原以为
束搜索找不到概率最高的译文，是搜索不够好；搜得越准，译文越好。
实际发现
Stahlberg 与 Byrne（2019）对一个 Transformer 翻译模型做精确搜索：WMT15 英德测试集上 51.8% 的句子的最优译文是空的（只有一个结束符），BLEU 从束搜索的 30.3 跌到 2.1。
为什么
整段的对数概率是逐 token 相加的负数，每多写一个 token 就多扣一点分，“立刻结束”常常总分最高。束搜索的搜索误差恰好掩盖了这个模型误差。
现在怎么看
模型分布的峰顶并不是模型“该输出”的东西。好的解码要么采样，要么在多个样本之间挑（例如第 章的多数投票），而不是去找峰顶。

从分布中挑 token：温度与截断

上一节的结论是要采样。采样要面对一个玩具里看不出来的问题：十几万个 token 的长尾。设某个上下文里合理的候选只有几十个，其余 15 万个 token 每个只有百万分之一的概率。单看每个都可以忽略，加起来却是 15%。哪怕把尾部总和压到 1%，生成 500 个 token 一次都不抽到尾部的概率也只有 \(0.99^{500}\approx 0.7\%\)。一旦抽到一个，后面的文本就接着这个错误往下写。温度不改变排序，挡不住尾部，所以采样之前还要截断：

\[ \begin{aligned} \text{top-}k:&\quad S = \{\text{概率最高的 }k\text{ 个 token}\}\\ \text{top-}p:&\quad S = \text{从高到低累加、使 }\textstyle\sum_{i\in S} p_i \ge p\text{ 的最小头部集合}\\ \text{min-}p:&\quad S = \{\,i : p_i \ge p_{\min}\cdot p_{\max}\,\} \end{aligned} \]
三种方法都是先划定一个候选集合 \(S\)，把 \(S\) 之外的概率设为 0，再在 \(S\) 内重新归一化后采样。区别只在于怎样划定 \(S\)。
玩具分布 \((62.4\%,\ 23.0\%,\ 8.4\%,\ 3.1\%,\ 3.1\%)\)。top-\(k\) = 2：保留鱼、饭，归一化为 \((73.1\%,\ 26.9\%)\)。top-\(p\) = 0.9：累计 62.4%、85.4%、93.8%，到第三个才达到 0.9，保留鱼、饭、句号，归一化为 \((66.5\%,\ 24.5\%,\ 9.0\%)\)。min-\(p\) = 0.1：门槛 \(0.1\times 62.4\% = 6.24\%\)，同样保留前三个。“猫吃猫”从此不可能出现。

top-k 最简单，但固定的 \(k\) 不随分布伸缩：分布很尖时混进垃圾，很平时砍掉合理的候选。top-p（核采样，nucleus sampling，Holtzman 等, 2019）按累计概率截断，候选数随分布自动伸缩，截掉的质量固定在约 \(1-p\)，是最常用的方法；但它保留的个数没有上界，高温下会把成千上万个尾部 token 一起放进来。min-p（2024）按相对于最高概率的比例截断，门槛跟着最高概率走，保留的个数最多 \(1/(p_{\min}\,p_{\max})\)，优势集中在高温（真实模型上有多大优势有争议，见下）。

试一遍：选“今天天气很…”，把 T 拉到 2，“蓝”“猫”“量子”三个不对的词合计从 0.3% 涨到约 3%；再把 top-p 拉到 0.9，只留前 10 个，它们被砍掉；点“采样 500 次”对比实际频率。再换“1 + 1 =”：T 从 1 升到 2，“2”的份额从 97% 跌到 68%，第一名再强，升温照样放大尾部。

上面每次只看一个分布。真正决定效果的是“温度 × 截断”的组合：温度越高，尾部越重，截断就越要紧。尾部还会累积：设截断之后每一步抽到“不该出现的 token”的概率是 \(\delta\)，各步近似独立，写 \(n\) 个 token 一次都不出错的概率是 \((1-\delta)^n\approx e^{-n\delta}\)；\(\delta = 0.1\%\) 时，500 个 token 也只有 61%。下面把温度从 0.3 扫到 3，比较三种截断漏进了多少垃圾、砍掉了多少合理的候选：

温度到底在权衡什么：期望分数与熵

第 1 步，温度 softmax 是一个优化问题的解。在所有分布 \(q\) 里，找让“期望 logit + \(T\) × 熵”最大的那个：

\[ q^* = \arg\max_{q}\ \Big[\sum_i q_i z_i + T\cdot H(q)\Big],\qquad H(q) = -\sum_i q_i\ln q_i,\quad \sum_i q_i = 1 \]

用拉格朗日乘子 \(\lambda\) 处理约束，对 \(q_i\) 求导并令其为 0：\(z_i - T(\ln q_i + 1) + \lambda = 0\)，即 \(\ln q_i = z_i/T + \text{常数}\)，\(q_i\propto e^{z_i/T}\)。这正是温度 softmax。第一项要“选分数高的”，第二项要“保持多样”，\(T\) 是两者之间的汇率。

第 2 步，熵随温度单调上升。记 \(\kappa = 1/T\)，\(p_i = e^{\kappa z_i}/Z\)，\(Z = \sum_j e^{\kappa z_j}\)。代入熵的定义：\(H = -\sum_i p_i(\kappa z_i - \ln Z) = \ln Z - \kappa\,\mathbb E_p[z]\)。再用两个对 \(\kappa\) 求导的结果 \(\frac{d\ln Z}{d\kappa} = \mathbb E_p[z]\)、\(\frac{d\,\mathbb E_p[z]}{d\kappa} = \operatorname{Var}_p(z)\)：

\[ \frac{dH}{d\kappa} = \mathbb E_p[z] - \mathbb E_p[z] - \kappa\operatorname{Var}_p(z) = -\kappa\operatorname{Var}_p(z),\qquad \frac{dH}{dT} = \frac{dH}{d\kappa}\cdot\frac{d\kappa}{dT} = \frac{\operatorname{Var}_p(z)}{T^{3}} \ge 0 \]

第 3 步，两个极限。\(T\to 0\)：\(\kappa\to\infty\)，最大 logit 那一项压倒其余，分布集中到 argmax 上，熵趋于 0，就是贪心（只要最大值唯一）。\(T\to\infty\)：所有 \(z_i/T\to 0\)，分布趋于均匀，熵趋于 \(\ln V\)（玩具里是 \(\log_2 5 = 2.32\) 比特）。

这个推导告诉我们：温度是一个连续的旋钮，在“只要最好的”和“完全随机”之间单调地移动；它不改变候选的排序，所以单靠它挡不住尾部，这是截断存在的理由。熵的变化率 \(\operatorname{Var}_p(z)/T^3\) 还说明：只有分布极尖时（例如低温下，第一名以外的概率乘以 logit 差的平方很小），\(\operatorname{Var}_p(z)\) 才接近 0，稍微升温几乎不变；第一名虽有 97%、但和其余候选差距有限时（演示里 \(T = 1\) 的“1 + 1 =”，\(\operatorname{Var}_p(z)\approx 0.80\)，和“今天天气很”的 0.86 差不多），升温照样会明显放大尾部。

三种截断各自截掉了什么，以及为什么非截不可

尾部从哪来。Hewitt 等（2022）的解释：交叉熵对“给真实 token 概率 0”的惩罚是无穷大，所以模型学会给每个 token 都留一点概率，好像在真实分布 \(p^*\) 上铺了一层均匀的底：\(p_\theta \approx (1-\lambda)\,p^* + \lambda\,u\)，\(u\) 是词表上的均匀分布。截断就是在估计 \(p^*\) 的范围，把这层底刮掉。

三种方法各自保证什么。把概率从大到小排成 \(p_{(1)}\ge p_{(2)}\ge\cdots\)：

  • top-k：保留的个数恒为 \(k\)；截掉的质量 \(1-\sum_{i\le k}p_{(i)}\) 没有上界，分布很平时可能砍掉大半合理候选。
  • top-p：截掉的质量不超过 \(1-p\)，这是定义保证的；保留的个数没有上界，分布越平留得越多，高温时可以上万。
  • min-p：保留下来的每个 token 都有 \(p_i\ge p_{\min}\,p_{(1)}\)，而它们的总和不超过 1，所以保留的个数 \(\le 1/(p_{\min}\,p_{(1)})\)。\(p_{\min} = 0.1\)、最高概率 0.3 时，最多 33 个。升温时 \(p_{(1)}\) 下降，这个上界随之放宽，但比 top-p 慢得多。

这个推导告诉我们：三种截断控制的是不同的量：top-k 控制个数，top-p 控制截掉的质量，min-p 控制相对门槛。没有一种在所有分布上都对。高温时最危险的是 top-p 的“个数无上界”；常用温度下最危险的是干脆不截断。

采样修重复，截断修采样。贪心和束搜索的毛病不是搜得不够好，而是目标错了；改成采样后问题换成长尾，三种截断是对“该刮掉多少尾部”的三种回答。之后的改进越来越小，因为模型变好了，需要刮掉的“底”越来越薄。

新采样方法真的更好吗：min-p 的争议

主张
min-p 论文（Nguyen 等）报告它在高温下兼顾创造性和连贯性，人类评测和基准评测都优于 top-p，获得 ICLR 2025 口头报告，并被 vLLM、llama.cpp 等广泛支持。
反方
斯坦福的 Schaeffer 等（2025）重新检查了四类证据：人类评测遗漏了部分数据、统计检验有误，重新分析后 min-p 并不优于基线；控制超参数搜索次数之后，基准上的优势消失；用大模型当评委的评测方法不清、报告不一致；“被数万个仓库采用”的说法已删除，修订后的说法仍有误导。
现在怎么看
min-p 在很高的温度下可能仍有一点优势，“全面优于 top-p”站不住。更普遍的教训是：采样方法的评测很容易受评测设计和调参次数影响。

剩下两个问题不是“怎样从分布里挑”能解决的：输出必须严格合法（下一节），以及一次一个 token 太慢（再下一节）。

约束解码与结构化输出

让模型调用工具或返回 JSON 时，输出必须能被程序解析，一个括号写错整个调用就失败。约束解码在每一步把不合法的 token 屏蔽掉：

\[ p'(x_t) \propto p_\theta(x_t \mid x_{<t})\cdot \htmlClass{c-new}{\mathbb 1\big[x_{<t}\,x_t\ \text{仍可能是合法输出的前缀}\big]} \]
用 JSON Schema、正则表达式或语法规则构造一个状态机，记录“到目前为止写了什么、接下来允许什么”。每一步只在允许的 token 里采样，保证最终输出一定合法。
Schema 要求 {"age": 整数}。已经生成了 {"age": ，此时只有数字 token 合法：模型原本最想写的 "twenty" 被屏蔽，概率重新分配给 2、20 等。

工程上的难点是速度：每步都要判断十几万个 token 哪些合法。现代实现（Outlines、XGrammar 等）把语法预编译成按 token 的查表，开销降到几乎可以忽略，主流推理框架和 API 都已内置。OpenAI 在 2024-08 推出的 Structured Outputs 同时用了两招：训练模型理解复杂的 schema，再在解码时做约束；据其发布说明，在它自己的复杂 JSON schema 评测上，旧模型不到 40%，新模型做到 100%。“先训练、再约束”的组合不是多余的，下面的推导说明了原因。

按步屏蔽为什么会扭曲模型的分布

我们真正想要的是“在合法输出里，按模型原本的概率抽”，即条件分布 \(p(y\mid y\in\mathcal G) = p(y)/P(\mathcal G)\)，\(\mathcal G\) 是所有合法输出的集合。按步屏蔽得到的却是

\[ q(y) = \prod_t \frac{p(y_t\mid y_{<t})\cdot\mathbb 1[y_{\le t}\ \text{还可能合法}]}{Z_t(y_{<t})},\qquad Z_t(y_{<t}) = \sum_{v\ \text{合法}} p(v\mid y_{<t}) \]

每一步的归一化常数 \(Z_t\) 随路径不同而不同，所以 \(q(y)\) 一般不正比于 \(p(y)\)。

一个例子。只允许回答“是”或“不是”。模型的第一步：“是”0.5，“不”0.4，其它 0.1（被屏蔽）。“不”之后，模型其实想写“不知道”（0.9），“不是”只有 0.1。假设写完“是”或“不是”之后模型一定结束。真正的条件分布是

\[ p(\text{是}\mid\mathcal G) = \frac{0.5}{0.5 + 0.4\times0.1} \approx 0.926,\qquad p(\text{不是}\mid\mathcal G) \approx 0.074 \]

按步屏蔽：第一步“是”和“不”都还可能合法，归一化后是 0.556 和 0.444；选了“不”之后只有“是”能接，被强制写成“不是”。结果“不是”的概率是 0.444，是模型本意的 6 倍。模型说“不”，是因为它打算说“不知道”；屏蔽让它保留了开头，换掉了结尾。

正确的做法。每个候选 token 还要乘上“接在它后面、最终能写成合法输出的概率”：\(p(v\mid y_{<t})\cdot P(\mathcal G\mid y_{<t}\,v)\)。例子里“不”要乘 0.1，于是是 \(0.5 : 0.04\)，正好还原条件分布。可这个“将来合法的概率”要对所有可能的后续求和，一般算不出来。Park 等（2024）的 ASAp 用多次采样逐步估计它，采得越多越接近正确的分布。

这个推导告诉我们：约束解码保证格式合法，不保证内容按模型的本意分布；模型越“不想”写成这个格式，扭曲越大。所以实践中先让模型在训练中学会这种格式（扭曲自然变小），再用约束兜底；把推理字段放在答案字段之前，也是在减少“开头已经锁死、只能硬接”的情况。

格式约束会不会让模型变笨

主张
Tam 等（2024）的 “Let Me Speak Freely?” 发现，要求模型按 JSON 等严格格式输出时，推理任务的准确率明显下降：模型没有空间先“想”再答。
反方
约束解码工具的开发者复现后指出，下降主要来自提示词写得不好和答案解析的问题；把推理过程也作为 schema 中的一个字段、放在答案之前，准确率不降反升。
现在怎么看
约束本身不必然有害，关键是不要剥夺模型先写推理过程的机会。字段的顺序很重要：先 reasoning 后 answer。另一个代价是多样性：2026 年一项覆盖 44 个模型的研究报告，结构化输出会让答案的多样性明显下降，这对需要多次采样再投票的用法不利。

超越“一次一个 token”

自回归有两个结构性的弱点。第一个是训练与生成的不一致：训练时看真实前缀，生成时看自己写的前缀，早期出错后，会在从没见过的错误前缀上继续写，误差逐步累积。这叫暴露偏差，强化学习用模型自己生成的样本训练，正好弥补这一点（第 章）。

第二个是生成无法并行：第 \(t+1\) 个 token 依赖第 \(t\) 个的采样结果，只能一个个算；而每一步都要把全部权重从显存里读一遍，串行的代价因此很高（第 章）。绕开它有三条路，改动从小到大：

  • 投机解码：不改模型，也不改输出分布，只改推理流程。用一个便宜的草稿先猜几个 token，再让大模型一次前向并行验证；接受规则加上被拒绝时的重抽，数学上保证输出分布和大模型自己一个个采样完全相同（推导和加速比见第 章）。
  • 多 token 预测（MTP）：改训练目标。训练时除了下一个 token，还额外预测后面第 2、3 个 token；多出来的预测头在推理时当草稿用，就是一种自带的投机解码。Meta 的 Gloeckle 等（2024）报告代码题多解出 12%、推理最多快 3 倍；DeepSeek-V3（2024-12）报告生成速度提高到 1.8 倍。
  • 扩散语言模型：彻底换掉从左到右。见下一节。

扩散语言模型：一次填很多个位置

扩散语言模型不从左到右生成，而是从一串全部被遮住的位置出发，每一轮并行地填出一部分，迭代若干轮得到全文。它借用的是图像扩散“从噪声逐步去噪”的思路（第 章），只是文本的“噪声”换成了遮盖：训练时随机遮住一部分 token，让模型把它们猜回来。

\[ \mathcal L_{\text{MDM}}(\theta) = \mathbb E_{\htmlClass{sym-tm}{t}\sim U(0,1]}\ \mathbb E_{\htmlClass{sym-xm}{\tilde x}}\Big[\htmlClass{c-new}{\frac{1}{t}}\sum_{\htmlClass{sym-M}{i\in\mathcal M}} -\log p_\theta\big(x_i \mid \htmlClass{sym-xm}{\tilde x}\big)\Big] \]
随机选一个遮盖比例 \(t\)，把原文每个位置以概率 \(t\) 换成 [MASK]，让模型同时猜出所有被遮住的位置；在这些位置上算交叉熵、求和，再乘以 \(1/t\)。
\(t\)
遮盖比例，相当于扩散的“时间”：接近 0 几乎没遮，等于 1 全部遮住
\(\tilde x\)
遮盖后的序列：原文 \(x\) 的每个位置独立地以概率 \(t\) 被换成 [MASK]
\(i\in\mathcal M\)
被遮住的位置；只在这些位置上算损失
\(1/t\)
权重：每个位置被遮住的概率是 \(t\)，乘 \(1/t\) 后每个位置在期望上恰好算一次，整个式子成为 \(-\log p_\theta(x)\) 的一个上界（即负的 ELBO），所以压低它就是在抬高文本概率的一个下界
一句 10 个 token，抽到 \(t = 0.3\)，遮住 3 个；模型在这 3 处的交叉熵是 0.5、1.2、0.8 nat，合计 2.5，乘以 \(1/0.3\) 得 8.3 nat，约每 token 0.83 nat，是这个上界的一次采样估计（期望上不低于这句话真实的负对数似然）。和自回归相比，结构上的差别只有一处：猜某个位置时，模型能看到它两边的上下文（双向注意力，没有因果掩码）。

生成时，从一串全是 [MASK] 的位置出发（比如 256 个）。每一轮，模型并行预测所有被遮住的位置，只保留最有把握的一部分，其余重新遮住，下一轮再猜。轮数少于位置数，就等于一轮填了多个 token，这是速度的来源。三个自然的问题。长度：位置的个数通常要事先定好，答案短了就用结束符把多余的位置填满。每轮的成本：每一轮都要对所有位置算一遍完整的前向，比自回归的一步贵得多，只有总轮数远少于 token 数才划算。KV 缓存：没有因果掩码，已填的位置的表示也会随新填入的内容改变，不能像自回归那样直接复用缓存。另一个代价是同一轮填的几个位置互相看不见对方的结果：

一轮填几个位置，代价是什么

模型每一轮给出的是每个位置各自的分布 \(p_\theta(x_i\mid\tilde x)\)。同一轮里填的几个位置是各自独立抽的，相当于用各位置分布的乘积代替了它们的联合分布。

一个例子。“我想去 __ __ 旅游”，两个空位，模型认为“北京”和“上海”各占一半。第一个空位是“北”或“上”各 50%，第二个是“京”或“海”各 50%。两个位置在同一轮独立地抽：“北京”“上海”“北海”“上京”各 25%，一半的结果拼错了。分两轮填：先填第一个（比如“北”），第二轮模型看到“北”，第二个位置几乎一定是“京”，就不会错。

误差有多大。同时填一组位置 \(A\) 时，用乘积代替联合分布，KL 损失恰好是这组位置之间的总相关：

\[ D_{\text{KL}}\Big(p(x_A)\,\Big\|\,\prod_{i\in A}p(x_i)\Big) = \sum_{i\in A}H(x_i) - H(x_A) \]

例子里是 \(1 + 1 - 1 = 1\) 比特。位置之间依赖得越强，越不能放在同一轮填。

为什么按把握大小挑位置。如果某个位置的分布已经几乎确定（熵接近 0），它和其它位置的互信息（知道一个位置能让另一个的熵减少多少）也接近 0，因为互信息不超过各自的熵，同一轮填它几乎没有误差。所以“先填最有把握的”方向是对的。它的另一面是灵活性陷阱（第 章）：推理里最关键的“因此”“但是”这类岔路口的词恰恰最没把握，总被拖到最后才填，等轮到它们时，前后文已经把结论锁死了。

这个推导告诉我们：扩散语言模型的速度和质量是同一个旋钮的两端：每轮填得越多越快，独立性带来的误差越大。自回归是这个旋钮的一个极端：每轮只填一个，这项误差为 0，速度最慢。

介于两者之间的是块扩散（block diffusion，也叫半自回归）：把序列切成块，块与块之间从左到右，块内部用扩散并行填写；块长为 1 就退回自回归（Arriola 等，ICLR 2025）。它把自回归的 KV 缓存和可变长度要了回来，又保留了块内的并行。

2025–26 年的现状。LLaDA（2025-02）从零训练的 8B 扩散模型与同规模自回归模型相当；LLaDA2.0（2025-12）把现成的自回归模型改造成 100B 总参数的混合专家（MoE）扩散模型。Gemini Diffusion（2025-05，实验性演示）官方报每秒 1479 个 token，Mercury 2（2026-02）官方报 1009，都是厂商自报。到 2026 年，扩散语言模型在速度和成本上有明显优势，质量上尚未超越前沿的自回归旗舰模型。

“预测下一个 token”够不够

一种看法
只是预测下一个 token 的模型，本质上只是在做局部的统计接龙，不可能真正地规划。Bachmann 与 Nagarajan（2024）构造了一个图上找路径的任务：从起点伸出几条岔路，只有一条通到终点。训练时后面每一步都能从真实前缀里“抄”：已经走上某条岔路，顺着走就行；唯独第一步无前缀可抄，必须从终点倒推。teacher forcing 训练出的模型学会了抄，始终学不会第一步。
另一种看法
“下一个 token”只是接口，不限制模型内部算什么。可解释性研究在模型内部找到了提前规划的证据，例如写押韵诗时提前选好行尾的韵脚（第 章）；思维链让模型把规划过程写出来，再一步步执行；强化学习（第 章）直接用最终结果训练，不再依赖 teacher forcing。
现在怎么看
纯粹的 teacher forcing 训练确实有盲区，但“预训练 + 思维链 + 强化学习”的组合在很大程度上弥补了它。多 token 预测和扩散模型则从训练目标本身入手，各自报告了在规划类任务上的改进；而扩散模型的灵活性陷阱又提醒我们，“不必从左到右”不一定是优点。

常见误解

  • 温度设成 0，输出就完全确定。理论上是，但在推理服务里，同一个请求和不同的请求拼在一起计算，批大小变化会改变浮点运算的顺序，结果可能出现细微差别并逐步放大。Thinking Machines（2025）指出主因是 GPU 内核缺乏“批不变性”，并给出了可复现的实现，代价是一定的速度损失。
  • 推理任务用贪心解码最稳。几千 token 的思维链里，贪心很容易陷入重复（见上文）。DeepSeek-R1 和 Qwen3 的官方建议都是温度 0.6 左右采样，Qwen3 明确写着不要用贪心。温度 0 只适合短的、答案唯一的输出。
  • 模型给出的概率就是它的把握程度。预训练模型的概率通常校准得不错（说 70% 时大约 70% 是对的），但 RLHF 等后训练会明显破坏校准：GPT-4 技术报告显示，后训练之后校准明显变差（报告图 8）。
  • 困惑度越低越好，可以直接比较不同模型。困惑度依赖分词：词表不同，每个 token 的含义不同，数值不可比。跨模型比较应换算成每字节比特数，并且要在同一份没被训练过的文本上测。

“无色的绿色想法狂怒地睡觉”语法正确但从未出现过，统计模型会给它和乱序句子同样的零概率，乔姆斯基据此认为概率无法刻画语法。Pereira（2000）用一个简单的平滑模型算出，语法正确的版本概率高出约 20 万倍。大模型时代这场争论以新形式继续：统计学习到的究竟是不是“语言能力”。
1980s–2020

语言模型从哪来 ②　从计数到神经网络，再到 GPT

卡在哪
要给任意前缀一个合理的分布。
怎么解决
计数 → 神经网络 → RNN → Transformer（见正文）；GPT-2（2019）直接写长文，GPT-3（2020）只靠提示词完成各种任务。
代价
模型会一本正经地编造，也不听指令（第 章）。
引出
训练目标不变、只扩大规模能走多远（第 章）；长文生成也让“怎么挑词”成了问题。
2018–2019

怎么挑词 ①　束搜索退化 → 采样与截断

卡在哪
翻译里好用的束搜索，用来写长文时空洞、不断重复。
怎么解决
top-k 采样（Fan 等 2018）；核采样（Holtzman 等 2019）。
代价
抽签带来随机性，偶尔抽到不合理的词，格式也没有保证。
引出
之后的截断方法（典型采样、min-p）只是在“刮掉多少尾部”上细调。
基本不用对比搜索、典型采样、η 采样等（2022）
为了兼顾多样性和连贯性提出了很多解码算法：对比搜索惩罚与前文过于相似的候选，典型采样只保留信息量接近熵的 token，η 采样按熵设定截断门槛。它们在当时的小模型上有改善，但模型变大、经过对齐之后，简单的温度 + top-p 已经足够好，这些方法很少用于生产。留下来的是一个视角：截断是在刮掉模型为了避免零概率而铺的“底”。
2023–2024

怎么挑词 ②　约束解码

卡在哪
工具调用和 JSON 输出必须能被程序解析。
怎么解决
按语法屏蔽非法 token，普及到各家 API（OpenAI Structured Outputs，2024-08）。
代价
按步屏蔽会扭曲模型的分布；结构化输出的多样性下降。
引出
先训练模型学会格式、再用约束兜底成为常规做法。
2023–2024

怎么更快 ①　投机解码与多 token 预测

卡在哪
一次一个 token，每步都要读一遍全部权重，长输出的延迟很高。
怎么解决
投机解码进入主流推理框架（第 章）；多 token 预测把草稿头训练进模型（DeepSeek-V3，2024-12）。
代价
仍然从左到右，每个 token 的位置仍要依次确定。
引出
能不能彻底抛开从左到右的顺序。
早期失败，后来复活非自回归翻译（2018）
Gu 等（2018）尝试一次并行输出整句译文，速度快但质量明显下降，因为各位置独立预测、彼此不协调（就是正文推导里的“北海”问题）。扩散语言模型用“多轮迭代、每轮只定一部分”缓解了这个协调问题，让并行生成重新变得可行。
2025–2026

怎么更快 ②　扩散语言模型规模化

卡在哪
逐 token 生成的延迟成为智能体和长推理的瓶颈。
怎么解决
LLaDA、LLaDA2.0、Gemini Diffusion、Mercury 2。
代价
输出长度要预设、难以复用 KV 缓存；质量和生态仍落后于自回归旗舰。
引出
生成方式定下来了，下一个问题是用什么数据训练（第 章）。
仍在发展块扩散：在自回归和扩散之间连续地调
块扩散（ICLR 2025）把块长当成旋钮：块长 1 是自回归，块长等于全文是纯扩散。LLaDA2.0 从自回归模型改造时，先逐步加大块长，再回到小块，说明这两种生成方式不是二选一，而是同一族模型的两端。

自测

1. 一个模型在验证集上的交叉熵是每 token 2.0 nats，困惑度是多少？如果把它给每个真实 token 的概率都提高到原来的 2 倍（假设仍合法），损失和困惑度变成多少？
困惑度 \(e^{2.0}\approx 7.39\)。概率翻倍，每个 token 的 \(-\ln p\) 减少 \(\ln 2\approx 0.693\)，损失变为 1.307，困惑度 \(e^{1.307}\approx 3.69\)，正好减半。
2. logit 为 \((2, 1, 0)\)，温度 0.5，用 top-p = 0.9 截断，最终的采样分布是什么？
\(T = 0.5\) 时相当于 logit \((4, 2, 0)\)，概率为 \((0.867,\ 0.117,\ 0.016)\)。累计 0.867 < 0.9，加上第二个达到 0.984 ≥ 0.9，保留前两个。归一化：\(0.867/0.984 = 0.881\)，\(0.117/0.984 = 0.119\)。第三个 token 永远不会被选到。
3. 在约束解码一节“是 / 不是”的例子里，如果“不”之后模型写“是”的概率是 0.5（而不是 0.1），真正的条件分布和按步屏蔽得到的分布各是多少？
条件分布：“是”0.5，“不是”\(0.4\times0.5 = 0.2\)，归一化为 0.714 和 0.286。按步屏蔽：仍是 \(0.5/0.9 = 0.556\) 和 0.444，因为屏蔽在第一步完全不看“不”之后模型想写什么。“不是”被放大的倍数从原来的 6 倍降到约 1.6 倍：模型越愿意按格式写，扭曲越小。
4. 一个模型在中文文本上平均每 token 损失 1.5 nats，平均每个 token 对应 1.4 个汉字（每个汉字 3 字节 UTF-8）。换算成每字节比特数是多少？
每 token \(1.5/\ln 2 \approx 2.16\) 比特；每 token \(1.4\times 3 = 4.2\) 字节；所以约 \(2.16/4.2\approx 0.52\) 比特 / 字节。也就是说，模型能把这些中文文本压缩到原始 UTF-8 大小的约 6.5%（\(0.52/8\)）。

必读

  1. Prediction and Entropy of Printed English（Shannon, 1951）让人猜下一个字母来估计语言的熵，“预测”与“信息量”的联系从这里开始。
  2. A Neural Probabilistic Language Model（Bengio 等, 2003）词向量与神经语言模型的起点，引言对维度灾难的讨论值得一读。
  3. The Curious Case of Neural Text Degeneration（Holtzman 等, 2019）为什么最大似然解码会退化，以及 top-p 采样的提出。
  4. Language Modeling Is Compression（Delétang 等, 2023）“预测即压缩”的系统阐述和实验。
  5. The Pitfalls of Next-Token Prediction（Bachmann 与 Nagarajan, 2024）teacher forcing 的盲区，一个干净的反例。
  6. Large Language Diffusion Models（LLaDA, 2025）扩散语言模型的训练目标、生成过程和规模化证据，篇幅不长。
