训练系统：把一个模型切到上万张卡上

训练一个前沿模型要用上万张 GPU 连续跑几个月。这一章算清楚训练时显存里放了什么（每个参数 16 字节），讲五种切分方式各解决什么问题、各付出什么通信代价，怎样衡量“用满了没有”（MFU），为什么低精度训练能省一半成本，以及在这种规模上，硬件故障是常态而不是意外。最后是强化学习带来的新问题：训练系统里还得塞进一个推理系统。

上一章的推理系统服务已经训练好的模型。训练的问题完全不同：要存下的不只是权重，还有梯度、优化器状态和每一层的激活值；所有卡必须在每一步同步；一次训练持续数月，任何一张卡出错都可能让整个任务停下。

  • HBM、NVLink、Roofline：第 章；FP8 / FP4：第 章
  • MoE 与专家并行：第 章；环形注意力：第 章

显存里放了什么

混合精度训练（2017 年起的标准做法）用 16 位做前向和反向计算，但保留一份 32 位的“主权重”来累积微小的更新，否则很多更新会在 16 位的舍入中丢失。加上 Adam 的两份状态，每个参数要占：

\[ \underbrace{2}_{\text{16 位权重}} + \underbrace{2}_{\text{16 位梯度}} + \underbrace{4}_{\text{32 位主权重}} + \underbrace{4 + 4}_{\text{Adam 的 } m,\,v} = \htmlClass{c-new}{16}\ \text{字节 / 参数} \]
这还不包括激活值（每一层前向时的中间结果，反向传播时要用）。推理时每个参数只需 1–2 字节，训练要 16 字节，差了一个数量级。
70B 模型：\(70\times 10^9\times 16 = 1.12\) TB，一张 80 GB 的 GPU 连十四分之一都放不下，必须切到多张卡上。再加上激活值：一个 70B 模型在 8K 序列长度下，每个样本的激活可达数十 GB，这还要靠“重算”来压缩（下文）。

激活值的大小随批大小、序列长度和层数线性增长。最常用的省法是激活重算：前向时只保存少数层的输入，反向时把中间结果重新算一遍。用约 30% 的额外计算换来数倍的显存节省；“选择性重算”（2022）只重算注意力里那些占显存多、算起来便宜的部分，额外计算降到几个百分点。

五种切分方式

把训练分到很多张卡上，每种切法解决一个问题、付出一种通信代价：

  • 数据并行（DP）：每张卡一份完整模型，各吃不同的数据，每一步结束时把所有卡的梯度求平均（全规约，all-reduce）。最简单，但每张卡要装下整个模型和优化器状态。
  • ZeRO / FSDP（2019）：在数据并行的卡之间切分优化器状态（ZeRO-1）、再切梯度（ZeRO-2）、再切参数本身（ZeRO-3，即 PyTorch 的 FSDP），用到时再从其他卡收集。\(n\) 张卡时每卡的状态显存约降为 \(1/n\)，代价是更多的通信。
  • 张量并行（TP, Megatron, 2019）：把每个矩阵乘法按行或列切到多张卡上，每层要做两次全规约。通信极频繁，通常只在一个 NVLink 域内（8 张卡或一个机柜）使用。
  • 流水线并行（PP, GPipe, 2018）：按层切成几段，放在不同的机器上，数据像流水线一样流过。通信量小，但有“气泡”（见下）。
  • 专家并行与上下文并行：MoE 的专家分布在不同卡上，token 通过全对全通信发送和收回（第 章）；把一条超长序列切到多张卡上，用环形注意力训练百万 token 的上下文（第 章）。

前沿训练通常把它们组合起来：机柜内用张量并行和专家并行（需要高带宽），机柜之间用流水线并行和数据并行（通信少），再在数据并行上叠加 ZeRO。这叫 4D 或 5D 并行。

\[ \text{气泡比例} = \frac{\htmlClass{sym-p}{p} - 1}{\htmlClass{sym-m}{m} + p - 1} \]
流水线有 \(p\) 段，一批数据切成 \(m\) 个微批次。开头要等第一个微批次流到最后一段，结尾要等最后一个反向传回第一段，这期间部分卡在空等。微批次越多，空等的占比越小。
\(p\)
流水线的段数
\(m\)
每批的微批次数
\(p = 8\)，\(m = 32\)：\(7/39\approx 18\%\) 的时间在空等。\(m = 128\)：降到 5%。但微批次太小，每张卡的矩阵乘法效率下降。交错调度、DeepSeek 的 DualPipe 通过更巧妙的排布和“计算与通信重叠”进一步压缩气泡。

通信：不让同步拖后腿

数据并行每一步都要对所有梯度做全规约。最常用的环形全规约算法，耗时为：

\[ T_{\text{全规约}} \approx \frac{2(\htmlClass{sym-n}{n} - 1)}{n}\cdot\frac{\htmlClass{sym-S}{S}}{\htmlClass{sym-BW}{\text{BW}}} \]
\(n\) 张卡排成一个环，每张卡把数据切成 \(n\) 份，先沿环传递并累加（\(n-1\) 步），再沿环传播结果（又 \(n-1\) 步）。每张卡总共收发约 \(2S\) 的数据，几乎与卡数无关。
\(S\)
要同步的数据量，如全部梯度的字节数
BW
每张卡的通信带宽
\(n\)
参与的卡数
7B 模型的 BF16 梯度 14 GB，8 张卡、每卡 NVLink 约 450 GB/s：\(2\times\tfrac78\times 14/450\approx 54\) ms。跨机器用 400 Gb/s（50 GB/s）的网卡则需约半秒，相当于很多步的计算时间。所以训练框架会把梯度分桶，在反向传播还在进行时就开始同步前面已经算好的梯度，让通信与计算重叠。

衡量训练系统效率的指标是MFU（模型算力利用率）：

\[ \text{MFU} = \frac{6N\times\text{每秒处理的 token 数}}{\text{GPU 数}\times\text{单卡峰值算力}} \]
用模型理论上需要的计算量（每 token \(6N\)，第 章）除以硬件的峰值算力。重算、通信等待、气泡、故障恢复都会拉低它。
Llama 3 405B 在 1.6 万张 H100 上训练，报告的 MFU 为 38–43%（BF16）。也就是说，硬件一半以上的算力花在了等待和额外开销上；大规模训练能做到 40–50% 就算很好。

低精度训练

训练的精度一路在降：2017 年的 FP16 混合精度（需要“损失缩放”防止梯度下溢），2020 年的 BF16（范围与 FP32 相同，不再需要损失缩放），2024 年 DeepSeek-V3 用 FP8 训练 671B 的 MoE（细粒度的分块缩放、高精度累加，关键部分保留 BF16），全部训练只用了约 279 万 H800 GPU 小时，按租价约 560 万美元（不含研究和失败实验的成本）。2025–26 年，NVIDIA 展示了用 NVFP4 预训练 12B 模型到 10 万亿 token、与 FP8 基线几乎无差距；DeepSeek V4、Kimi K3 把 FP4 量化感知训练做进了流程（第 章）。

低精度训练省下的不只是算力（FP8 的张量核心吞吐是 BF16 的 2 倍），还有显存和通信：梯度和激活值的字节数减半。难点在于数值稳定：梯度中的离群值、累加误差、损失尖峰（第 章），需要分块缩放、随机舍入、对部分敏感算子保留高精度等技巧。

规模上，故障是常态

意外：一万六千张卡，平均每三小时坏一次

原以为
数据中心的硬件很可靠，训练偶尔因为故障中断。
实际发现
Llama 3 405B 在 1.6 万张 H100 上预训练的 54 天里，发生了 466 次作业中断，其中 419 次是意外的，平均约每 3 小时一次。约 78% 的意外中断来自硬件，最多的是 GPU 本身（约 30%）和 HBM 显存（约 17%）。还有更隐蔽的“静默数据错误”：某张卡算错了却不报错，损失曲线慢慢变怪。
为什么
单个部件的故障率不高，但一万多张 GPU、上千台服务器、数万根光纤和交换机放在一起，总有某个在出问题；同步训练中任何一张卡停下，所有卡都得等。
现在怎么看
故障处理成了训练系统的核心功能：频繁保存检查点（并让保存本身足够快）、自动检测和隔离坏节点、快速重启、预留备用机器。Meta 报告在这种故障频率下仍保持了 90% 以上的有效训练时间。规模再扩大十倍，故障间隔就缩短到二十分钟以内，这也是“异步、低通信”训练受到关注的原因之一。

同步训练还能扩大多少：超大集群还是分布式训练

集中派
2025–26 年的前沿训练集群已达 10 万到数十万张 GPU、吉瓦级供电（第 章）。同步的数据并行在数学上最简单，收敛最可靠，工程上的问题（故障、通信）可以靠更好的网络和软件解决。
分布派
单个数据中心的电力和规模有物理上限，故障频率随规模线性增长。Google 的 DiLoCo（2023–25）让各个“岛”各自训练几百步才同步一次，通信量降低几百倍，几乎不损失质量，可以跨数据中心训练；Prime Intellect 等用类似方法在全球分散的算力上训练了开源模型。
现在怎么看
前沿训练仍以超大集群的同步训练为主，但跨数据中心训练已在大公司内部出现。低通信训练的规模定律研究表明，随着模型变大，异步同步带来的质量损失在缩小，这条路线的重要性可能上升。

强化学习：训练系统里塞进一个推理系统

RL 训练（第 章）的每一步都要先让模型生成大量回答（采样），再用这些回答更新参数。采样就是推理，常常占 RL 一半以上的时间；推理和训练对系统的要求又截然相反（一个要大批量、低精度、访存优化，一个要反向传播、高精度、大量通信）。于是 RL 系统要同时运行两套引擎：用 vLLM、SGLang 这样的推理引擎做采样，用 Megatron、FSDP 做训练，每一步把新的权重从训练端同步到推理端。几个关键问题：

  • 长尾等待：一批回答中最长的那条决定这一步何时结束，其余采样卡只能干等。异步 RL 让采样和训练在不同的卡上同时进行，训练使用“稍旧一点”的策略生成的数据，代价是要处理离策略问题（第 章的重要性采样）。
  • 训练与推理不一致：两套引擎的数值实现不同，同一个 token 的概率会有微小差异，在 RL 中会被放大（第 章）。
  • 环境：智能体 RL 需要成千上万个并行的沙盒（容器、浏览器、终端），环境本身成了需要调度的资源（第 章）。

开源的 RL 框架（verl、OpenRLHF、智谱的 slime 等）和各家的内部系统都在解决这些问题。据小米的报告，MiMo-V2.6（2026）用全异步的 GRPO 和超大批次，一次 RL 训练花费约 260 万美元：RL 已经和预训练一样，是一个需要专门系统支撑的大规模工程。

常见误解

  • 训练一个模型需要的显存和推理差不多。训练每参数约 16 字节（不含激活），推理 1–2 字节，差一个数量级以上。
  • 卡越多，训练越快，线性增长。通信、气泡、故障恢复都随规模增长，MFU 往往随规模下降；需要精心设计并行策略。
  • “560 万美元训练出 DeepSeek-V3”说明前沿模型很便宜。那是最终一次训练的 GPU 租用成本，不含前期研究、失败实验、数据和人员，更不含购买和维护整个集群。
  • 硬件故障是罕见事件。在万卡规模上，平均几小时就有一次；处理故障是系统的日常工作。
  • RL 只是换了个损失函数，系统和预训练一样。RL 要同时运行推理和训练两套引擎，加上大量环境，系统复杂度更高。

自测

1. 用混合精度 Adam 训练一个 30B 模型，权重、梯度和优化器状态共需多少显存？用 ZeRO-3 切到 64 张卡上，每卡多少？
\(30\times 10^9\times 16 = 480\) GB；ZeRO-3 切 64 份，每卡约 7.5 GB（不含激活和通信缓冲）。
2. 流水线 16 段，要让气泡低于 10%，每批至少要多少个微批次？
\((p-1)/(m+p-1) < 0.1\)，\(15 < 0.1(m + 15)\)，\(m > 135\)，至少 136 个。
3. 一个 405B 稠密模型训练 15 万亿 token，用 1.6 万张峰值 989 TFLOPS 的 GPU，MFU 40%。大约要多少天？
总计算 \(6\times 4.05\times 10^{11}\times 1.5\times 10^{13}\approx 3.6\times 10^{25}\) FLOPs。有效算力 \(1.6\times 10^4\times 9.89\times 10^{14}\times 0.4\approx 6.3\times 10^{18}\) FLOPs/s。时间 \(\approx 5.7\times 10^6\) 秒，约 66 天。
