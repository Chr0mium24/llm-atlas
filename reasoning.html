推理模型：让模型“想久一点”，并用强化学习教它怎么想

2024 年 9 月的 OpenAI o1 和 2025 年 1 月的 DeepSeek-R1 带来一个新的规模化维度：推理时算力（test-time compute）。模型先生成很长的思维链，再给答案；思考得越久，准确率越高。教会它这样思考的方法是 可验证奖励的强化学习（RLVR）。

思维链：把计算展开到 token 上

Transformer 每生成一个 token，做的计算量是固定的（约 2N FLOPs）。难题需要的计算量超过一次前向能完成的，就得 把中间步骤写出来，让后面的 token 能读到前面的中间结果。这就是 思维链（Chain-of-Thought, CoT）。2022 年发现，只要在 prompt 里加一句“让我们一步步思考”，大模型的数学题准确率就会大幅上升。

用更多推理算力换准确率，有两个方向：

  • 并行：同一个问题采样 N 次，然后 多数投票（self-consistency, 2022），或者用验证器 / 奖励模型挑最好的（best-of-N）。
  • 串行：一条思维链写得更长，中间自我检查、回溯、换思路。o1/R1 这类推理模型属于这一类。

强化学习：从 RLHF 到 RLVR

RLHF（2022 InstructGPT）：人类比较两个回答 → 训练奖励模型 → 用 PPO 优化策略。问题是奖励模型本身会被“钻空子”：策略学会写出奖励模型喜欢、但实际上并不更好的回答（reward hacking），比如更长、更讨好、格式更花哨。

RLVR（可验证奖励的强化学习）：只在答案能被程序自动判对错的任务上训练，比如数学题对答案、代码跑单元测试、智能体任务检查终态。奖励就是 0 或 1，很难被钻空子。DeepSeek-R1 证明了只靠这种稀疏奖励、不给示范的思考过程，模型就能 自己 学会长思维链、自我反思和验证（论文中的 “aha moment”），思考长度随训练稳定增长。

GRPO：用组内比较代替价值网络

PPO 需要一个和策略差不多大的价值网络来估计基线，很贵。DeepSeek 的 GRPO（Group Relative Policy Optimization）对同一道题采样一组 G 个回答，用组内平均奖励当基线：

2025–2026：RL 规模化与智能体

  • RL 算力暴涨：前沿模型投入后训练 RL 的算力已接近预训练的同一数量级，RL 也呈现规模定律。
  • 智能体 RL：奖励来自真实环境，比如在沙盒终端里把任务做完、在浏览器里找到答案、通过 MCP 工具完成操作。评测也随之转向 Terminal-Bench、SWE-bench、BrowseComp 这类任务。Kimi K3 的模型卡报告了 Terminal-Bench 2.1 88.3%、BrowseComp 91.2%。
  • 思考与工具交织：在思维链中途调用搜索、代码执行，再接着想（o3 起）。
  • 并行思考：同时展开多条思路再汇总（Gemini Deep Think 等），把“并行”和“串行”两种推理算力结合起来。
  • 不可验证领域：写作、开放问答没有标准答案，用细粒度评分细则（rubric）+ LLM 评审给奖励。
  • 在线策略蒸馏：学生模型自己采样，教师模型逐 token 给出概率作为密集信号。据报道 DeepSeek V4 的后训练用它替代了一部分 RL。

几种对齐 / 强化方法对比

方法奖励从哪来需要的模型特点
RLHF + PPO人类偏好训练的奖励模型策略 + 参考 + 奖励 + 价值，共 4 个通用但贵；容易被 reward hacking
DPO偏好对（隐式奖励）策略 + 参考简单、离线；上限不如在线 RL
GRPO + RLVR程序验证（对 / 错）策略 + 参考省掉价值网络；推理能力提升的主力
智能体 RL环境的终态检查策略 + 沙盒环境轨迹长、需要大规模异步 rollout 系统
在线策略蒸馏教师模型逐 token 的 log 概率学生 + 教师密集信号，样本效率高，但上限受限于教师
