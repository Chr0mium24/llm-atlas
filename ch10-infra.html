第 10 章 · 效率

Infra：模型怎么在成千上万张卡上训练，又怎么同时服务几百万人

模型结构决定理论上的计算量，真正决定成本和速度的是系统：显存带宽、批处理、KV cache 管理、并行策略、通信。这一章从一个 token 的生成开始，一直讲到 2026 年的 P/D 分离、宽专家并行和超节点。

两个阶段：Prefill 吃算力，Decode 吃带宽

一次请求分两段：

  • Prefill：把整个 prompt（可能几万 token）一次性送进模型，算出所有位置的 KV cache 和第一个输出 token。这是大矩阵乘大矩阵，算力受限（compute-bound），决定首 token 延迟（TTFT）。
  • Decode：之后每步只生成 1 个 token，权重矩阵乘一个向量。每读 1 字节权重只做约 2 次运算，GPU 大部分时间在等显存，带宽受限（memory-bound），决定每个 token 的间隔（TPOT）。

Roofline 模型：可达到的算力 = min(峰值算力, 带宽 × 算术强度)。算术强度 = 每字节数据对应的运算次数。decode 时把 B 个用户的请求合成一个 batch，读一次权重就能服务 B 个 token，算术强度乘以 B。这就是 批处理 能大幅降低成本的根本原因。

连续批处理与 PagedAttention

请求的输出长度差异很大，短的几个 token，长的几万 token。静态批处理 要等一批里最长的请求结束，才能换下一批，其余槽位只能空转。连续批处理（continuous / in-flight batching，Orca 2022）在每个解码步都检查：有请求结束就立刻从队列补上新的请求。

KV cache 的显存管理也是同样的问题。旧做法按最大长度给每个请求预留一整块连续显存，实际只用了一小部分。PagedAttention（vLLM, 2023）借鉴操作系统的分页：KV cache 切成固定大小的块（比如 16 token），按需分配，用块表映射。浪费从 60–80% 降到 4% 以下，同样的显存能多服务几倍的并发请求。

在这之上还有：前缀缓存（SGLang 的 RadixAttention，2024）：系统 prompt、多轮对话历史、智能体的工具定义都是共享前缀，算过一次的 KV 直接复用。Kimi、DeepSeek 等 API 对缓存命中的 token 收费低得多，原因就在这里。分块 prefill：把长 prompt 切块，和 decode 请求混在同一个 batch 里，避免长 prompt 卡住所有人。

投机解码：小模型先猜，大模型一次验证

decode 受带宽限制，GPU 算力闲着。投机解码（2022）利用这些闲置算力：用一个便宜的草稿模型连续猜 γ 个 token，大模型 一次前向 并行验证这 γ 个位置。从第一个猜错的位置截断，并在那里用大模型自己的分布补一个 token。用特殊的接受/拒绝采样规则，可以证明输出分布和大模型单独生成 完全一致，不是近似。

每轮期望产出 token 数 = (1 − αγ+1) / (1 − α)　　加速比 ≈ 上式 / (1 + γ·c)α：每个草稿 token 被接受的概率；γ：一次猜几个；c：草稿模型相对大模型的成本

草稿从哪来：独立的小模型；Medusa / EAGLE：在大模型上挂几个轻量预测头，利用大模型自己的隐藏状态，接受率高，EAGLE-3 是 2025–26 年 vLLM/SGLang 的主力；MTP：DeepSeek-V3/V4 训练时就带多 token 预测头，推理时直接当草稿（社区给 Bonsai 2 27B 加的 MTP 头，实测 decode 提升约 24.5%）；prompt lookup / n-gram：直接从上下文里找重复片段，改代码、引用原文时特别有效。注意：batch 很大时 GPU 已经接近算力受限，投机解码的收益会下降。

训练：怎么把一个模型切到上万张卡上

  • 数据并行 DP：每张卡一份完整模型，各吃不同的数据，梯度做 all-reduce。最简单，但每张卡要装下整个模型和优化器状态。
  • ZeRO / FSDP（2019）：把优化器状态（stage 1）、梯度（stage 2）、参数本身（stage 3）切分到各数据并行卡上，用到时再收集。
  • 张量并行 TP（Megatron, 2019）：把每个矩阵乘按行/列切开，放到多张卡上，每层都要通信，通常只在一台机器的 8 张卡内（NVLink）使用。
  • 流水线并行 PP（GPipe, 2018）：按层切成几段，放到不同机器。有 气泡：流水线填满和排空时部分卡在空等，要靠足够多的微批次摊薄。
  • 专家并行 EP：MoE 的专家分布在不同卡上，token 通过 all-to-all 发送和收回（第 7 章）。
  • 上下文并行 CP：把一条超长序列切到多张卡上（Ring Attention），用来训练 1M 上下文。

前沿训练通常是 4D/5D 并行：DP × TP × PP × EP × CP 组合使用。衡量效率的指标是 MFU（模型算力利用率）= 实际有效 FLOPs / 硬件峰值，大规模训练做到 40–50% 就算很好。

2026 年的推理系统

  • P/D 分离（DistServe、Mooncake，2024）：prefill 和 decode 放在不同的 GPU 池，KV cache 通过高速网络传输（NIXL、Mooncake Transfer Engine）。两类负载互不干扰，可以分别扩容。vLLM 2026 年 4 月的博客报告，在单台 8×MI300X 上做 P/D 分离，有效吞吐（goodput）提升 2.5 倍。NVIDIA Dynamo、SGLang、vLLM 都已支持。
  • 宽专家并行：DeepSeek 式的大规模 EP decode，几十到上百张卡共同服务一个 MoE，每张卡只放少数专家，靠 DeepEP 一类的通信库做 all-to-all。
  • KV cache 分层存储：GPU 显存 → CPU 内存 → SSD / 分布式存储（Mooncake Store 等）。Kimi 用 KV-centric 的架构在高缓存命中率下提供“百万上下文统一定价”。
  • 超节点：GB200 NVL72（72 张 GPU 共享 NVLink 域）、华为 CloudMatrix 384 等，把 TP/EP 的通信域扩大到整柜。Kimi K3 官方建议的部署是不少于 64 张加速卡的超节点。
  • 低精度推理：Blackwell 原生 FP4（NVFP4 / MXFP4），Hopper 上用 Marlin/Machete 一类的内核做 W4A16 反量化。
  • 本地推理：llama.cpp（GGUF、各类 K/I-quants、CPU 卸载 MoE 专家）、MLX（Apple Silicon）、Ollama 封装。新架构（线性注意力、Hadamard 旋转、三值）往往要等运行时补上算子支持，否则理论上更快，实际反而更慢。
