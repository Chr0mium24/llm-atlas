分词与嵌入：文字怎么变成向量

神经网络只会做矩阵乘法。一段文字进入模型之前，要经过两步：先切成一串离散的 token、换成整数编号（分词），再把每个编号换成一个几千维的向量（嵌入）。这两步看起来是预处理，其实决定了很多事：一句中文要花多少 token、模型为什么数不清单词里有几个字母、为什么它的算术时好时坏。这一章先在一个只有五个短语的小语料上把“切分、编号、查表”完整算一遍，再讲 BPE、字节级分词和 Unigram 为什么这样设计，词表该多大，词向量里的“意思”从哪来，最后讲 2026 年还在争论的问题：还要不要分词器。

这是正文的第一章。序章讲了九年的故事线；从这里开始，我们沿着一段文字在模型里走过的路，一步步往里看。第一站：文字怎么变成模型能计算的东西。

  • 概率与对数：知道 \(\log(ab) = \log a + \log b\) 就够了。

为什么要分词

模型的输入必须是一串整数。最直接的做法有两种，各有致命的问题：

  • 按字符或字节切。英文只有几十个字母，所有文本都是 256 种字节的组合，词表很小，什么都能表示。但序列太长：一句话几十上百个单位，而第 章会讲到，注意力的计算量随长度的平方增长。
  • 按词切。序列短，但词表会爆炸（英文有几十万个词形，中文还要先解决“怎么分词”），而且总会遇到没见过的词：新造的网络用语、拼错的单词、代码里的变量名。这些词只能被替换成一个“未知”符号（常写作 [UNK]），信息就丢了。这叫未登录词（out-of-vocabulary，OOV）问题。

现在所有大模型都用折中的方案：子词分词（subword tokenization）。高频的片段（“the”、“ing”、“模型”、“的”）整体作为一个单位，低频的词拆成几块，最坏的情况退回到单个字节。切出来的单位叫 token，所有可能的 token 组成词表（vocabulary），大小记作 \(V\)，每个 token 有一个编号。负责“切分并换成编号”、以及反过来“把编号拼回文字”的程序叫分词器（tokenizer）。它在训练模型之前单独训练好，之后就固定不变。

衡量一个分词器“省不省”，常用平均每个词（或字）切成几个 token，也叫 fertility：\(f = \text{token 数} / \text{词数（或字数）}\)。同一个分词器对不同语言的 fertility 差别很大，后面会看到这带来的不公平。词表大小 \(V\) 本身也是一个权衡：词表越大，句子越短，但模型里和词表有关的参数和计算越多。「词表多大」一节会把这笔账算清楚。

从零开始：五个短语，从文字到向量

这一节不涉及任何大模型。用一个只有五个短语的语料，把文字变成向量的每一步都算出具体数字：合并、切分、编号、查表、比较向量。后面每一节讲的，都是这几步在真实规模下的做法。已经熟悉的读者可以直接跳到「BPE」。

数相邻的两个字，合并出现最多的一对

把每个短语里相邻的两个字都数一遍，乘上短语的出现次数再加起来。例如“模 型”出现在大模型（6 次）、小模型（2 次）、模型训练（3 次）里，一共 11 次。全部相邻对是：

模·型 11，训·练 7，大·模 6，数·据 5，练·数 4，型·训 3，小·模 2，大·数 1。

出现最多的是“模 型”。把语料里所有相邻的“模 型”都换成一个新 token“模型”，编号 9，词表变成 \(V = 9\)。每换一次，两个 token 变成一个，所以语料从 55 个 token 变成 \(55 - 11 = 44\) 个。然后重新数一遍：原来的“大 模”不见了，因为这个语料里每个“模”后面都跟着“型”，它变成了“大 模型”，仍是 6 次；新 token 只会和它左右的邻居组成新的对，其余的对次数不变或变少。重复这个过程：

切一句没见过的话

“小模型训练数据”整句从没在语料里出现过。切新文本时不再数次数，而是把学到的合并规则按学到的顺序依次套用：

  • 开始：小 · 模 · 型 · 训 · 练 · 数 · 据（7 个）
  • 规则 1（模 + 型）：小 · 模型 · 训 · 练 · 数 · 据
  • 规则 2（训 + 练）：小 · 模型 · 训练 · 数 · 据
  • 规则 3（大 + 模型）：没有“大”，跳过
  • 规则 4（数 + 据）：小 · 模型 · 训练 · 数据
  • 规则 5（训练 + 数据）：小 · 模型 · 训练数据（3 个）

再查词表换成编号：小 = 4，模型 = 9，训练数据 = 13，模型看到的输入就是 \([4,\ 9,\ 13]\)。真实的分词器从 0 开始编号，这里从 1 开始，是为了和下面“第几行”对得上。

如果句子里有语料里从没出现过的字，比如“大模型推理”，“推”和“理”只能换成 [UNK]：按字切也躲不开未登录词。解决办法是从字节出发（「字节级 BPE」一节）：每个汉字在计算机里是 3 个字节，256 种字节全放进初始词表，就永远不会遇到不认识的东西，代价是没合并过的字要占 3 个 token。

编号变成向量：查一张表

神经网络要的是向量，不是编号。模型里有一张嵌入矩阵 \(E\)，形状是 \(V\times d\)：每个 token 一行，每行 \(d\) 个数。我们的玩具里 \(V = 13\)，取 \(d = 3\)；Llama 3 8B 是 \(128{,}256\times 4096\)。编号为 \(i\) 的 token 对应第 \(i\) 行，这一行叫它的嵌入（embedding）。假设训练之后，其中几行是这样的（数字是为了好算编的）：

编号token嵌入（第 1、2、3 维）
1大(0.8, 0.1, 0.3)
4小(0.7, −0.1, 0.4)
9模型(0.1, 0.9, 0.2)
13训练数据(−0.2, 0.3, 0.9)

查表这个操作可以写成矩阵乘法：用一个独热向量（长度为 \(V\)，只有第 \(i\) 位是 1、其余都是 0）去乘嵌入矩阵。

\[ \htmlClass{sym-e}{\mathbf e_i} = \htmlClass{sym-E}{E}^{\top}\, \htmlClass{sym-oh}{\mathbf 1_i} = \htmlClass{sym-E}{E}[\,i,\, :\,] \]
编号为 \(i\) 的 token，它的向量就是嵌入矩阵的第 \(i\) 行。写成“用一个只有第 \(i\) 位是 1 的向量去乘矩阵”，是为了说明它和普通的线性层一样，可以求梯度、可以训练。

\(E\)

“小”的编号是 4：\(\mathbf 1_4 = (0,0,0,1,0,\dots,0)\)，共 13 维。\(E^\top\mathbf 1_4\) 的第 \(k\) 个分量是 \(\sum_j (\mathbf 1_4)_j E_{jk} = E_{4k}\)，13 个乘积里只有一个不是 0，结果就是第 4 行 \((0.7,\ -0.1,\ 0.4)\)。

“小模型训练数据”的三个编号 \([4, 9, 13]\) 查表之后，变成三个 3 维向量，排成一个 \(3\times 3\) 的矩阵（\(n\times d\)，\(n\) 是序列长度）。这就是模型第一层收到的全部输入。实际实现不会真的去乘一个十几万维的独热向量，而是直接读出那一行，所以查嵌入几乎不花算力，只占内存。这一点在本章最后一节会变得重要。

两个向量有多像：余弦相似度

训练之后，意思或用法相近的 token，向量方向也相近。衡量两个向量方向是否接近，用余弦相似度：

\[ \cos(\htmlClass{sym-u}{\mathbf u}, \htmlClass{sym-v}{\mathbf v}) = \frac{\mathbf u\cdot\mathbf v}{\htmlClass{sym-len}{\|\mathbf u\|\,\|\mathbf v\|}} \]
两个向量的点积，除以它们长度的乘积。只看方向、不看长短，结果在 −1 到 1 之间：1 表示方向相同，0 表示垂直，−1 表示相反。

大 = (0.8, 0.1, 0.3)，小 = (0.7, −0.1, 0.4)：点积 \(0.56 - 0.01 + 0.12 = 0.67\)，长度 \(\sqrt{0.74}\approx 0.860\) 和 \(\sqrt{0.66}\approx 0.812\)，\(\cos \approx 0.67/0.699 \approx 0.96\)，几乎同向。大和模型 = (0.1, 0.9, 0.2)：点积 0.23，\(\cos \approx 0.23/(0.860\times0.927)\approx 0.29\)。

为什么“大”和“小”应该相近？看它们在语料里的邻居：“大”后面 7 次里有 6 次是“模型”，“小”后面 2 次全是“模型”。如果训练任务是“预测邻居”，邻居相同的 token 会被推向相同的方向。这里的数字是编的，「向量里的意思从哪来」一节会推导训练为什么会得到这样的结果。

到这里，一段文字走完了进入模型之前的全部旅程：文字 → token → 编号 → 向量。后面几节分别回答：合并规则怎样学得更好，词表该多大，向量里的意思从哪来，以及怎么从向量回到 token。

BPE：从单个字符开始，反复合并最常见的一对

上一节手算的就是 BPE。它本来是 Gage 1994 年提出的一个数据压缩算法，2015 年被 Sennrich 等人用到神经机器翻译上，此后几乎所有大模型的分词器都是它的变体。训练过程只有一句话：

\[ (a, b)^\star = \operatorname*{arg\,max}_{(a,b)}\ \htmlClass{sym-cnt}{\operatorname{count}(a, b)},\qquad \text{把所有相邻的}\ a\,b\ \text{合并成新 token}\ ab \]
在语料里数一数，哪两个相邻的符号一起出现得最多，就把它们合并成一个新符号，加进词表。重复，直到词表达到目标大小。
\(\operatorname{count}(a,b)\)
符号 \(a\) 后面紧跟符号 \(b\) 在语料中出现的次数
玩具语料里“模 型”11 次、“训 练”7 次、“大 模”6 次。第一轮合并“模 型”，得到新 token“模型”。之后原来的“大 模”全部变成了“大 模型”，仍是 6 次；第三轮它被合并成“大模型”。

合并之前还有一步预分词（pre-tokenization）：先用规则把文本切成“词块”，合并只在词块内部进行。GPT 系列用一个正则表达式做这一步：英文单词连同前面的空格是一块（“ the”），标点是一块，数字单独成块。所以 “the cat” 里的 “e c” 永远不会被合并。数字的规则各家不同：GPT-2 把整串数字当一块；GPT-4 的 cl100k 和 Llama 3 从左往右最多三位一组（“12345”切成“123 / 45”）；Llama 1/2、Qwen、Gemma 把数字切成单个数字。预分词是人定的硬边界，后面会看到，它既保护了结构，也限制了压缩。

BPE 为什么是一种贪心压缩，以及为什么越往后越不划算

第 1 步，一次合并省多少。设语料当前的 token 总数是 \(N\)。把相邻对 \((a,b)\) 合并后，它的每次出现都把两个 token 变成一个：

\[ N' = N - \operatorname{count}(a, b) \]

严格地说，这里的 count 要数不重叠的出现次数：“哈哈哈”里有两个相邻的“哈 哈”，但只能合并出一个“哈哈”。玩具语料里没有这种情况，55 → 44 → 37 → 31 → 26 → 22，每步省下的正好是 11、7、6、5、4。

第 2 步，贪心。“每次合并出现最多的一对”就是在每一步让 \(N\) 下降得最多：用 \(V\) 个符号的词表，尽量用少的符号写下整个语料。它不保证全局最优：Whittington 等（2024）证明，给定词表大小，找出能把语料压得最短的词表（或合并序列）是 NP 完全问题。所以实际中只能用贪心这类近似算法。

第 3 步，省下的数量单调不增。设第 \(k\) 次合并的那一对出现 \(c_k\) 次。合并前它是出现最多的一对，所以所有对的次数都 \(\le c_k\)。合并之后：

  • 不涉及新 token \(ab\) 的对：有些出现被 \(ab\) 吃掉了，次数只会不变或减少，仍然 \(\le c_k\)。
  • 涉及新 token 的对 \((x, ab)\) 或 \((ab, y)\)：每次出现都需要一个 \(ab\)，而语料里 \(ab\) 最多只有 \(c_k\) 个，所以次数 \(\le c_k\)。

因此 \(c_{k+1} \le c_k\)。语料的 token 数 \(N(V)\) 随词表变大而下降，但每多一个词表项，下降得越来越少，是一条越来越平的曲线。真实分词器的第十几万次合并，往往只对应某个罕见词或某种语言里的一个常见片段。

这个推导告诉我们：BPE 的目标是压缩，不是语言学上的“词素”。它切出的 token 往往和人对词的理解不一致，比如 “strawberry” 可能被切成 “str / aw / berry”，这是很多“模型不会数字母”的现象的根源。而且压缩的收益递减，词表不可能“越大越好”，这为后面的词表大小之争埋下了伏笔。

字节级 BPE：永远不会遇到不认识的字符

计算机里的文字先是一串 Unicode 码点（code point）：每个字符一个编号，“a”是 U+0061，“模”是 U+6A21，“😀”是 U+1F600，Unicode 目前收录了 15 万多个字符。存储时再按 UTF-8 编码成字节：

\[ \htmlClass{sym-nb}{\text{字节数}}(\htmlClass{sym-c}{c}) = \begin{cases} 1, & c < \text{U+0080}\ \ (\text{ASCII})\\ 2, & c < \text{U+0800}\ \ (\text{拉丁扩展、希腊、西里尔、阿拉伯……})\\ 3, & c < \text{U+10000}\ \ (\text{常用汉字、日文、印地文……})\\ 4, & \text{其它}\ \ (\text{emoji、罕见汉字}) \end{cases} \]
码点越大，占的字节越多。英文字母 1 个字节，常用汉字 3 个，emoji 4 个。每个字节有 256 种可能的取值。
\(c\)
一个字符的 Unicode 码点
字节数
这个字符在 UTF-8 里占几个字节（每个字节 8 位）
“模”= U+6A21，二进制 0110 1010 0010 0001，按 3 字节模板 1110xxxx 10xxxxxx 10xxxxxx 填进去：11100110 10101000 10100001，即 E6 A8 A1 三个字节。“a”只有一个字节 61。“😀”是 F0 9F 98 80 四个字节。

GPT-2（2019）的字节级 BPE把这 256 种字节当作起始符号，而不是字符。任何文本都能拆成字节，所以永远不会出现未登录词。代价是：一个汉字如果没被合并成单个 token，就要占 3 个 token。早期以英文为主训练的分词器，中文、印地语、阿拉伯语这类文字的 fertility 很高，同样的意思要多花几倍的 token，也就多付几倍的钱、少放几倍的上下文。在上面的 BPE 演示里切到“字节级”，合并次数调小，可以看到一个汉字被拆成三个字节。

另一条路是以字符为起点、再给它配一个保险：字节回退（byte fallback）。词表里放常用字符和子词，外加 256 个“字节 token”；遇到词表里没有的字符，就退回它的 UTF-8 字节。LLaMA（2023）的分词器就是这样做的，还把所有数字切成单个数字。

为什么字节级 BPE 能编码任何文本，又一定能原样还原

第 1 步，任何文本都是一串字节。UTF-8 给每个码点一个确定的 1–4 字节编码，不同的文本得到不同的字节串。所以“编码任何文本”等价于“编码任何字节串”。

第 2 步，最坏情况是一个字节一个 token。初始词表包含全部 256 种字节，所以任何字节串本身就是一个合法的 token 序列。如果以字符为起点，要做到同样的保证，初始词表得放下 15 万多个 Unicode 字符，而且新版本 Unicode 每年还在增加；以字节为起点，256 个就够了。

第 3 步，合并不改变内容。记 \(\operatorname{bytes}(t)\) 为 token \(t\) 对应的字节串。新 token \(ab\) 的字节串就是 \(\operatorname{bytes}(a)\) 接上 \(\operatorname{bytes}(b)\)。所以每次合并之后，整个序列所有 token 的字节串首尾相接，结果和合并之前完全相同。从最初的字节序列出发，做多少次合并都一样，于是

\[ \operatorname{decode}(\operatorname{encode}(s)) = s \]

对任何文本 \(s\) 都严格成立，一个字节都不会丢。

第 4 步，反过来不成立。不是每个 token 序列都能解码成合法的文字。模型逐个生成 token 时，可能先生成“模”的前两个字节 E6 A8，第三个字节还在下一个 token 里；这时只看前面的部分，就是一段不完整的 UTF-8，界面上会显示成替换字符“�”。流式输出里偶尔闪现的乱码就是这么来的，攒够字节再显示就好了。

这个推导告诉我们：字节级的正确性只来自“256 种字节全在词表里”和“合并只是拼接”这两条，与训练数据无关；而它的效率完全取决于合并学到了什么。哪种语言在分词器的训练数据里多，哪种语言的字节就被合并得多，这就是下面语言不公平问题的来源。

另一条路：Unigram，按概率挑一种切法

BPE 是“自底向上”地合并。Kudo（2018）提出的 Unigram 语言模型分词反过来：先准备一个很大的候选词表，给每个 token 一个概率 \(p(x)\)，然后在一句话所有可能的切法里，选整体概率最大的那一种：

\[ \htmlClass{sym-xs}{\mathbf x}^\star = \operatorname*{arg\,max}_{\mathbf x\, \in\, \htmlClass{sym-S}{\mathcal S(s)}}\ \sum_{i} \log \htmlClass{sym-p}{p(x_i)} \]
在句子 \(s\) 所有的切法里，挑一种：它的每个 token 的概率乘起来最大（等价于对数概率加起来最大）。
\(\mathcal S(s)\)
句子 \(s\) 所有可能的切法（只用词表里有的 token）
\(\mathbf x = (x_1, x_2, \dots)\)
其中一种切法，切出的 token 序列
\(p(x_i)\)
token \(x_i\) 的概率，训练时用 EM 算法估计
“推理加速”有两种切法：“推理 / 加速”：\(\log 0.009 + \log 0.008 \approx -9.53\)；“推 / 理 / 加 / 速”：\(\log 0.006 + \log 0.008 + \log 0.01 + \log 0.005 \approx -19.75\)。前者概率大得多，被选中。

切法的数目随句子长度指数增长，但最优的一种可以用动态规划（Viterbi 算法）找到：从左往右记下“切到第 \(j\) 个字为止的最大对数概率” \(\text{best}(j) = \max_{i<j}\big[\text{best}(i) + \log p(s_{i..j})\big]\)，计算量只和句子长度乘以最长 token 的长度成正比。训练时从大词表出发，反复估计概率、删掉对整体似然影响最小的 token（见下面的推导）。SentencePiece（2018）工具同时实现了 BPE 和 Unigram，并且把空格也当成普通字符处理（写成“▁”），不依赖空格分词，所以对中文、日文这类没有空格的语言很友好。

Unigram 还带来一个有用的副产品：子词正则化（subword regularization）。训练时不总用最优切法，而按概率随机采样一种，模型因此见过同一个词的多种切法，对拼写错误更稳健。

Unigram 的概率从哪来：EM 算法与剪枝

第 1 步，目标。每种切法的概率是各 token 概率之积 \(P(\mathbf x) = \prod_i p(x_i)\)。可我们不知道语料“本来”是怎么切的，所以一句话 \(s\) 的概率要把所有切法加起来，整个语料的对数似然是

\[ \mathcal L = \sum_{s}\log \sum_{\mathbf x\in\mathcal S(s)} \prod_i p(x_i) \]

对数里面有求和，没法直接求最大值。这正是 EM 算法（期望最大化，expectation–maximization）的用武之地：当数据里有“看不见的部分”（这里是切法）时，交替地猜它、再根据猜的结果更新参数。

第 2 步，E 步：按当前概率猜切法。用玩具语料里的“大模型”（出现 6 次）。设当前 \(p(\text{大}) = 0.2\)、\(p(\text{模}) = 0.1\)、\(p(\text{型}) = 0.1\)、\(p(\text{模型}) = 0.2\)、\(p(\text{大模型}) = 0.1\)。三种切法的概率：

\[ \begin{aligned} P(\text{大模型}) &= 0.1, \qquad P(\text{大 / 模型}) = 0.2\times0.2 = 0.04,\\ P(\text{大 / 模 / 型}) &= 0.2\times0.1\times0.1 = 0.002 \end{aligned} \]

归一化（除以总和 0.142），得到每种切法的后验概率：70.4%、28.2%、1.4%。于是每出现一次“大模型”，期望上贡献 0.704 个“大模型”、\(0.282 + 0.014 = 0.296\) 个“大”、0.282 个“模型”、各 0.014 个“模”和“型”。乘以 6 次，再对语料里所有短语求和，得到每个 token 的期望出现次数 \(\hat c(x)\)。

第 3 步，M 步：用期望次数重新估概率。\(p(x) \leftarrow \hat c(x) / \sum_{x'}\hat c(x')\)。这和“数次数再归一化”一模一样，只是次数换成了期望次数。EM 的一般性质保证，每做一轮 E 步加 M 步，\(\mathcal L\) 都不会下降。

第 4 步，剪枝。概率收敛后，对每个 token 算“把它从词表删掉，\(\mathcal L\) 会下降多少”。删掉“大模型”：这个短语只剩 \(0.04 + 0.002 = 0.042\)，每次出现的对数概率从 \(\ln 0.142 = -1.95\) 降到 \(\ln 0.042 = -3.17\)，损失 1.22；删掉“模型”：剩 \(0.1 + 0.002 = 0.102\)，损失只有 \(\ln(0.142/0.102) \approx 0.33\)。每轮删掉损失最小的一批（Kudo 的做法是保留前 80%），单个字符永远保留，保证任何文本都能切。重复 EM 和剪枝，直到词表缩到目标大小。

这个推导告诉我们：BPE 和 Unigram 的方向相反（一个往上加、一个往下删），但目标相同：让语料能用尽量少、尽量“可能”的 token 写下来。Unigram 多出来的是一个完整的概率模型，所以它能对切法采样（子词正则化），BPE 不能。

数字怎么切，会影响模型的算术能力

现象
GPT-2 把整串数字交给 BPE，“12345” 可能切成 “123 / 45”，也可能是 “1 / 2345”，取决于训练语料里哪些片段常见。同一个位值（个位、十位……）在不同 token 里位置不同，模型很难学会进位。
证据
GPT-4 的 cl100k 改成从左往右最多三位一组（据检查过它词表的用户统计，1 到 3 位的数字串全部 1110 个都是单独的 token），但边界仍按“从左数”而不是按位值。Singh 与 Strouse（2024）在 GPT-3.5 和 GPT-4 上对比发现：用逗号强制数字从右往左每三位一组（与千位分隔对齐），加法的准确率明显高于默认的从左往右。Llama 1/2、Qwen、Gemma 则干脆把数字切成单个数字。
现在怎么看
分词不是中性的预处理，它决定了模型“看到”的结构。2026 年 COLM 的 TokEval 专门把“数字是否按右对齐的三位边界切分”列为一项分词器评价指标。下面「每一代在修什么」一节的对比演示里，可以切换四种数字规则看效果。

词表该多大：一笔具体的账

第 1 步，每个 token 的计算量。前向时，模型主体的每个参数对每个 token 做一次乘加，约 \(2N_{\text{主体}}\) 次运算；输出层是一个 \(V\times d\) 的矩阵乘向量，\(2Vd\) 次；输入端查表只是读一行，可以忽略。所以每个 token 约 \(2(N_{\text{主体}} + Vd)\) 次。

第 2 步，换词表什么时候划算。同一段文字，用词表 \(V_0\) 切成 \(n_0\) 个 token，用更大的 \(V\) 切成 \(n\) 个。总计算量不增加的条件是 \(n\,(N_{\text{主体}} + Vd) \le n_0\,(N_{\text{主体}} + V_0 d)\)，即

\[ \frac{n}{n_0} \le \frac{N_{\text{主体}} + V_0\,d}{N_{\text{主体}} + V\,d} \]

第 3 步，代入三个真实模型（\(V_0 = 32{,}000\)，\(V = 128{,}256\)）：

  • Llama 3.2 1B（\(d = 2048\)，\(N_{\text{主体}} \approx 9.7\) 亿）：右边 \(= (9.73 + 0.66)/(9.73 + 2.63) \approx 0.84\)，序列至少要短 16%。
  • Llama 3 8B（\(d = 4096\)，\(N_{\text{主体}} \approx 69.8\) 亿）：\((69.8 + 1.3)/(69.8 + 5.3) \approx 0.947\)，至少短 5.3%。
  • Llama 3 70B（\(d = 8192\)，\(N_{\text{主体}} \approx 684.5\) 亿）：\(\approx 0.989\)，至少短 1.1%。

Meta 报告 Llama 3 的分词器比 Llama 2 少用最多 15% 的 token。对 8B 和 70B 这是明显的净收益；对 1B 模型差不多打平，所以 Llama 3.2 1B 还把输入和输出两张表共享（「输出端」一节），省下 2.6 亿参数。

第 4 步，公式里没有的成本。（1）注意力的计算量随序列长度平方增长，序列变短的收益比上面算的更大。（2）训练时每个位置都要存 \(V\) 个分数：8192 个 token × 128,256 × 4 字节 ≈ 4.2 GB，一条序列就要这么多显存。Apple 的 Cut Cross-Entropy（2024-11）把这一步改成边算边丢，Gemma 2 2B 的损失计算显存从 24 GB 降到 1 MB。（3）词表越大，每个 token 平均分到的训练数据越少，罕见 token 的向量学不好（「嵌入」一节的推导）。

这个推导告诉我们：输出层的成本占比 \(Vd/(N_{\text{主体}} + Vd)\) 随模型变大而变小，所以最优词表应该随模型变大而变大。Tao 等（2024）用规模定律的方法得到了同样的结论：按他们的估算，Llama 2 70B 的最优词表至少 21.6 万，而它只用了 3.2 万。反过来，小模型用大词表最吃亏。

词表到底该多大

主张
Tao 等（NeurIPS 2024）把词表大小也纳入规模定律：模型越大，最优词表越大，大多数模型的词表都偏小。上面的推导给出了直观的原因：大模型里输出层只占很小一部分算力。
反方
对小模型，大词表的代价很显眼：Gemma 3 1B 的 26.2 万词表让嵌入参数达到 3.02 亿，占全部 10 亿参数的 30%（只算一张表）；输出层更慢，端侧部署更吃内存。
现在怎么看
大模型往 15 万到 26 万靠拢；同一家族的小模型通常与大模型共用词表，便于蒸馏（第 章需要学生和老师的 token 一一对应），再靠共享嵌入省参数。2025 年以后还有一条新思路：输入端和输出端用不同大小的词表（本章最后一节）。

同一段话，中文更贵还是更便宜

同一段内容翻译成不同语言，切出的 token 数之比叫分词溢价（tokenization premium）：比 1 大，说明这种语言要多付 token。Petrov 等（NeurIPS 2023）用 FLORES-200（同样 2000 个句子、人工翻译成 200 种语言）做了系统测量。把溢价拆成两个因子，就能看清它从哪来：

\[ \frac{\htmlClass{sym-nz}{n_{\text{中}}}}{\htmlClass{sym-ne}{n_{\text{英}}}} = \htmlClass{sym-lr}{\frac{\ell_{\text{中}}}{\ell_{\text{英}}}}\times\htmlClass{sym-fr}{\frac{f_{\text{中}}}{f_{\text{英}}}} \]
token 数之比 = 字符数之比 × 每个字符平均切成几个 token 之比。前一项由语言本身决定，后一项由分词器决定。
\(n_{\text{中}}, n_{\text{英}}\)
同一段内容的中文版、英文版切出的 token 数
\(\ell_{\text{中}}/\ell_{\text{英}}\)
字符数之比。FLORES-200 上中文约为英文的 0.34（汉字信息密度高）；按 UTF-8 字节数算约为 0.93
\(f_{\text{中}}/f_{\text{英}}\)
每个字符切成的 token 数（fertility）之比。英文一个 token 平均约 4 个字符，\(f_{\text{英}}\approx 0.25\)
汉字完全没被合并（每字 3 个字节 token）：\(0.34\times 3/0.25 \approx 4.1\)。每个汉字 1 个 token：\(0.34\times 1/0.25 \approx 1.36\)。平均 1.5 个汉字一个 token：\(0.34\times 0.67/0.25 \approx 0.91\)，中文反而更省。实测：GPT-2 的分词器 3.21，GPT-4 的 cl100k 1.91，XLM-R、BLOOM 这类多语言分词器约 0.95–0.97。

所以“中文费 token”不是中文的性质：同样的内容，中文的字符数只有英文的三分之一，字节数也略少；贵不贵取决于分词器训练时见过多少中文。OpenAI 发布 GPT-4o 时给过一组例句：换成 o200k 之后，一句中文从 34 个 token 降到 24 个，同一句英文从 27 降到 24，两者打平；印地语从 90 降到 31。上面演示 A 部分可以亲手复现：把训练语料里的中文比重从 10% 拉到 90%，中文对英文的 token 比从约 1.8 倍降到约 0.4 倍。溢价 2 倍，就是同样的内容付 2 倍的钱、上下文只装得下一半。

特殊 token 与聊天模板

词表里除了普通 token，还有一类特殊 token：标记一段文本的开始和结束、区分系统提示和用户消息、包住思维链（如 <think>）、标记工具调用、给图像和音频占位。把一段对话按固定格式加上这些特殊 token，叫聊天模板。对话、推理、工具调用这些“能力”，在输入层面都只是序列里插了特定的 token；用错模板，模型的表现会明显下降。gpt-oss 的 o200k_harmony 就是在 o200k 上专门加了一批对话格式用的特殊 token（消息开始、结束、频道、工具调用等）。

“故障 token”：词表里有、训练时却几乎没见过

现象
2023 年有人发现，向 GPT-3 输入 “SolidGoldMagikarp” 这样的字符串，模型会胡言乱语、拒绝复述，甚至答成别的词。这类 token 后来被叫作故障 token（glitch token）。2025 年的一项研究统计，GPT-4o 的词表里超过两个汉字的中文长 token，四成以上与色情或网络赌博有关，它们来自分词器训练语料里的垃圾网页。
原因
分词器和模型是用不同的数据训练的。“SolidGoldMagikarp”是一个 Reddit 用户名，在分词器的训练数据里很常见，所以成了一个独立的 token；但在模型的训练数据里几乎没出现过，它的嵌入向量几乎没被更新，停在初始化附近，模型不知道它是什么意思（下面「嵌入」一节的推导说明了为什么）。发现者正是通过找“离所有嵌入的平均位置最近”的那些 token 把它们找出来的。
启示
分词器和模型应该用一致的数据训练；上线前要检查训练中从未或极少出现的 token。

嵌入：一张训练出来的表

「从零开始」一节已经算过：嵌入就是从 \(V\times d\) 的嵌入矩阵里取出一行。真实模型里这张表有十几万行、几千列，和其它参数一样从随机数开始，靠训练学出来。训练的信号只有一个：让模型预测下一个 token 的交叉熵损失变小（第 章）。梯度沿着网络传回第一层，最后落到被查到的那几行上。

嵌入表的梯度：为什么没出现过的 token 学不到东西

第 1 步，只有被查到的行有梯度。一条序列 \(x_1,\dots,x_n\) 查表得到 \(\mathbf e_t = E^\top\mathbf 1_{x_t}\)，损失 \(L\) 通过这些向量依赖 \(E\)。由链式法则：

\[ \frac{\partial L}{\partial E} = \sum_{t=1}^{n} \mathbf 1_{x_t}\Big(\frac{\partial L}{\partial \mathbf e_t}\Big)^{\!\top} \]

每一项是“独热向量 × 一个 \(d\) 维向量”的外积，只有第 \(x_t\) 行不为 0。所以一步训练只改动这一批里出现过的 token 的那几行，其余十几万行纹丝不动。

第 2 步，从没出现过的 token。如果 token \(j\) 在模型的训练数据里一次都没出现，第 \(j\) 行在输入端永远收不到梯度，停在初始化的随机值附近；如果训练用了权重衰减（每步把参数往 0 拉一点），它会慢慢缩到 0 附近。模型的其它部分从没见过这个向量，遇到它时的行为是未定义的：这就是故障 token。

第 3 步，共享嵌入时还有一股力。如果输出矩阵就是 \(E\)（共享嵌入），输出端的梯度是 \(\partial L/\partial \mathbf w_j = (p_j - \mathbb 1[j = y])\,\mathbf h\)：每个位置上，不是正确答案的 token \(j\) 都会被沿 \(-\mathbf h\) 推一点，推的力度是它的概率 \(p_j\)。罕见 token 几乎从来不是正确答案，所以每一步都被往同一个方向（各位置隐藏状态平均值的反方向）推，最后挤在一起。Gao 等（2019）把这叫作表示退化（representation degeneration）。

这个推导告诉我们：一个 token 的向量只能从它出现的那些位置学到东西。词表里的每一行都需要足够多的训练数据，这是大词表的一个隐藏成本，也解释了故障 token 为什么会挤在嵌入空间的中心附近。

向量里的“意思”从哪来

为什么训练会让意思相近的词向量相近？背后是语言学里的分布假说：一个词的意思由它出现的上下文决定（Firth, 1957: “You shall know a word by the company it keeps”）。“猫”和“狗”经常出现在相似的句子里（“喂___”“___在睡觉”），只要模型的任务是预测上下文，它们的向量自然会被推到一起；玩具语料里的“大”和“小”也是这样。

2013 年的 word2vec 把这个想法做成了一个很小的网络：给一个词，预测它周围的词（skip-gram）：

\[ \max\ \sum_{t}\sum_{-\htmlClass{sym-m}{m}\le j\le \htmlClass{sym-m}{m},\ j\ne 0} \log p(w_{t+j}\mid w_t),\qquad p(o\mid c) = \frac{\exp(\htmlClass{sym-u}{\mathbf u_o}\cdot \htmlClass{sym-v}{\mathbf v_c})}{\sum_{w}\exp(\htmlClass{sym-u}{\mathbf u_w}\cdot \htmlClass{sym-v}{\mathbf v_c})} \]
对语料里的每个词，让模型给它前后 \(m\) 个位置上的真实邻居尽量高的概率；某个词作为邻居出现的概率，正比于两个向量点积的指数。
\(\mathbf v_c\)
中心词 \(c\) 的向量（这就是最后拿来用的词向量）
\(\mathbf u_o\)
词 \(o\) 作为“上下文”时的向量
\(m\)
窗口大小：中心词前后各看几个词
句子“我 喂 猫 吃 饭”，中心词“猫”，\(m = 1\)：要让 \(p(\text{喂}\mid\text{猫})\) 和 \(p(\text{吃}\mid\text{猫})\) 尽量大。语料里“喂 狗 吃”也很常见，所以“狗”的向量会被推到和“猫”相似的方向。

分母要对整个词表求和，词表有几十万个词时太慢。实际训练用负采样（negative sampling，SGNS）：不再做一个几十万选一的分类，而是做很多个“是不是真邻居”的二分类：真实的（词, 上下文）对要判为“是”，随机抽来的 \(k\) 个假上下文要判为“否”。

\[ \ell(c, o) = \log\htmlClass{sym-sig}{\sigma}(\htmlClass{sym-u}{\mathbf u_o}\cdot\htmlClass{sym-v}{\mathbf v_c}) + \sum_{j=1}^{\htmlClass{sym-k}{k}}\log\htmlClass{sym-sig}{\sigma}(-\htmlClass{sym-un}{\mathbf u_{n_j}}\cdot\htmlClass{sym-v}{\mathbf v_c}),\qquad \htmlClass{sym-un}{n_j}\sim \htmlClass{sym-Pn}{P_n(w)} \propto \#(w)^{3/4} \]
真邻居与中心词的点积要大（\(\sigma\) 接近 1），随机抽的假邻居的点积要小（取负号后 \(\sigma\) 接近 1）。假邻居按词频的 3/4 次方抽取，常见词抽得多，但没有按原频率那么多。
\(\sigma(x)\)
sigmoid 函数 \(1/(1+e^{-x})\)，把任意实数压到 0 到 1 之间，当作“是真邻居”的概率
\(k\)
每个真样本配几个负样本；原论文建议小数据集 5–20，大数据集 2–5
\(\mathbf u_{n_j}\)
第 \(j\) 个随机抽出的“假上下文”词的向量
\(P_n(w)\)
抽负样本的分布：词频 \(\#(w)\) 的 3/4 次方再归一化
真邻居点积 2，两个负样本点积 1 和 −0.5：\(\log\sigma(2) + \log\sigma(-1) + \log\sigma(0.5) \approx -0.13 - 1.31 - 0.47 = -1.91\)。梯度会把第一个点积往上推、把第一个负样本的点积往下推（它目前太像真邻居了）。两个词的频率 0.9 和 0.1，取 3/4 次方再归一化后被抽中的概率是 84% 和 16%：罕见词当负样本的机会比按频率多。

训练完的词向量出现了著名的“向量算术”：\(\text{国王} - \text{男人} + \text{女人} \approx \text{王后}\)。下面用一个手工构造的小例子演示这种现象：每个词有 11 个可以解释的维度，图上是降到 2 维后的样子。

word2vec 其实在分解一个“共现矩阵”

第 1 步，把目标按词对整理。对整个语料把负采样的目标加起来。某一对 \((w, c)\) 作为真样本出现 \(\#(w,c)\) 次；作为负样本，\(w\) 出现 \(\#(w)\) 次、每次抽 \(k\) 个负样本、每个抽中 \(c\) 的概率是 \(\#(c)/|D|\)（为了推导简洁，这里用原始词频代替 3/4 次方）。把目标函数里和 \(x = \mathbf v_w\cdot\mathbf u_c\) 有关的项收集起来：

\[ \ell(x) = \#(w,c)\,\log\sigma(x) + k\,\#(w)\,\frac{\#(c)}{|D|}\,\log\sigma(-x) \]

其中 \(\#(w)\)、\(\#(c)\) 是各自出现的次数，\(|D|\) 是总的词对数。

第 2 步，求最优点。假设向量维度足够大，每一对的点积可以独立取值。对 \(x\) 求导并令其为 0，利用 \(\frac{d}{dx}\log\sigma(x) = \sigma(-x)\) 和 \(\sigma(x)/\sigma(-x) = e^x\)：

\[ \begin{aligned} \#(w,c)\,\sigma(-x) &= k\,\frac{\#(w)\#(c)}{|D|}\,\sigma(x) \;\Rightarrow\; e^{x} = \frac{\#(w,c)\,|D|}{k\,\#(w)\,\#(c)} \\ \Rightarrow\; x &= \underbrace{\log\frac{\#(w,c)\,|D|}{\#(w)\,\#(c)}}_{\mathrm{PMI}(w,c)} - \log k \end{aligned} \]

括号里的量叫点互信息（PMI）：两个词一起出现的频率，比“各自独立出现时偶然碰到一起”的频率高多少倍，再取对数。所以最优解满足 \(\mathbf v_w\cdot\mathbf u_c = \mathrm{PMI}(w,c) - \log k\)：word2vec 在用低维向量的点积去拟合 PMI 矩阵（Levy 与 Goldberg, 2014）。维度不够大时，它给出的是这个矩阵的一个低秩近似。

第 3 步，向量算术为什么成立。如果“国王”与“王后”的共现模式之差，和“男人”与“女人”的差大致相同（都只差在“他、她、丈夫、妻子”这类与性别相关的上下文上），那么对每个上下文 \(c\) 都有 \(\mathrm{PMI}(\text{国王}, c) - \mathrm{PMI}(\text{王后}, c) \approx \mathrm{PMI}(\text{男人}, c) - \mathrm{PMI}(\text{女人}, c)\)，于是 \(\mathbf v_{\text{国王}} - \mathbf v_{\text{王后}} \approx \mathbf v_{\text{男人}} - \mathbf v_{\text{女人}}\)，移项就是向量算术。

这个推导告诉我们：词向量里的“意思”就是统计意义上的共现模式，没有什么神秘的东西；大模型的嵌入层也遵循同样的原理，只是它预测的“上下文”是整段前文。

大模型的嵌入层和 word2vec 有两点不同。第一，它不单独训练，而是和整个模型一起，为“预测下一个 token”这个任务端到端地学出来（第 章）。第二，嵌入层给出的只是每个 token 的“字面”向量，同一个 token 在任何句子里都一样；“bank”是银行还是河岸，要等后面的注意力层结合上下文才能区分（第 章）。真实模型的嵌入有几千维，单独的一维通常没有可读的意思，概念分布在很多维度的组合方向上，这一点在第 章还会讲。

输出端：从向量回到 token

模型处理完一个位置后，得到一个 \(d\) 维向量 \(\mathbf h\)。要预测下一个 token，就用输出矩阵（也叫 LM head）把它和词表里每个 token 比一比，得到 \(V\) 个分数，叫 logit；再用 softmax 把分数变成概率：

\[ \htmlClass{sym-z}{\mathbf z} = \htmlClass{sym-W}{W}\,\htmlClass{sym-h}{\mathbf h},\qquad p(y = i \mid \mathbf h) = \operatorname{softmax}(\mathbf z)_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}} \]
用输出矩阵把最后的向量变成 \(V\) 个分数，每个分数取指数，再除以总和，得到下一个 token 是每个词的概率。
\(\mathbf h\)
模型在这个位置的最终向量，\(d\) 维
\(W\)
输出矩阵（LM head），\(V\times d\)，每行对应一个 token
\(\mathbf z\)
logit：\(V\) 个未归一化的分数，第 \(i\) 个是 \(\mathbf h\) 和第 \(i\) 个 token 的输出向量的点积
三个候选 token 的 logit 是 \((2,\ 1,\ 0)\)：\(e^{z} \approx (7.39,\ 2.72,\ 1)\)，总和 11.11，概率 \(\approx (66.5\%,\ 24.5\%,\ 9.0\%)\)。所有 logit 同时加 5，概率不变，只有差值才重要。

输入的嵌入矩阵 \(E\) 和输出矩阵 \(W\) 形状相同，都是“每个 token 一行向量”：前者回答“这个 token 是什么”，后者回答“下一个是不是它”。让两者共用同一张表（\(W = E\)），叫共享嵌入（tied embeddings），省下 \(Vd\) 个参数（Press 与 Wolf, 2017）。词表占比越大越值得共享：Llama 3.2 1B、Qwen3 的 0.6B 到 4B 都共享，词表有 25.6 万的 Gemma 2 从 2B 到 27B 都共享；Llama 3 8B 和 70B、Qwen3-8B 以上、Kimi K3 则让两张表各自学习，在大模型里多一张表只占百分之几的参数。怎么从这个概率分布里挑出下一个 token（温度、top-p 等），是第 章的内容。

2024–2026：每一代在修什么

分词器是整个系统里少数还靠“手工规则 + 单独训练”的部分：模型看不到字母和位值、不同语言付出的 token 不公平、预分词的硬边界限制了压缩。2023 年以后的改进大致是四步，每一步都在修上一步留下的问题。

更大、更多语言的词表。卡在哪：3 万到 5 万、以英文为主的词表下，同一段内容的中文要多花 1.9 到 3.2 倍 token。改了什么：直接加大 \(V\)，同时提高分词器训练语料里其它语言的比例。cl100k（约 10 万）到 o200k（约 20 万），Llama 3 的 128K，Qwen3.5 的约 25 万，Gemma 的约 26 万。代价：嵌入和输出层随 \(V\) 线性增长，小模型最吃亏；BPE 收益递减，新增的十万个 token 大多是罕见片段。引出：词表再大，预分词仍然规定 token 不能跨过空格。

超词：让 token 跨过空格。卡在哪：“by the way”“in order to”这样的固定搭配，被预分词按空格切开，永远至少是 3 个 token。改了什么：SuperBPE（COLM 2025）分两个阶段训练：先照常在空格以内学子词，学到一定规模后去掉“不能跨空格”这条预分词规则，继续学跨越多个词的超词（superword）。20 万词表下，同样的文本比普通 BPE 少用最多 33% 的 token；8B 模型在 30 个评测上平均提升 4.0 个百分点（MMLU 提升 8.2），推理算力少 27%。SupraTok（2025-08）等方法沿同一方向继续改进。代价：token 和词的边界不再对齐，约束解码要处理“半个词组”。引出：既然输出端的成本限制了词表大小，能不能只把输入端做大？

把输入词表和输出词表拆开。卡在哪：输出层的 \(2Vd\) 让小模型用不起大词表；可输入端只是查表，几乎不花算力（「从零开始」一节）。改了什么：只放大输入端，给相邻几个 token 的组合也配上向量，叫 n-gram 嵌入：组合太多存不下，就用哈希函数把每个组合映射到一张大表里的某一行，和单个 token 的嵌入加在一起。字节跳动 Seed 的 Over-Tokenized Transformer（2025-01）把输入词表扩到 1280 万，训练损失随输入词表大小对数线性下降，效果接近两倍大的模型，额外算力几乎为 0。DeepSeek 的 Engram（2026-01）把它做成一个独立的“记忆”模块，DeepSeek-V4.1-Flash（2026-09）在 5520 亿主体参数之外配了 1960 亿个 Engram 参数；Gemma 3n（2025-06）给每一层配一张额外的嵌入表，放在加速器之外按需读取。代价：上千亿参数的表要放在主机内存甚至闪存里，系统更复杂。引出：输入端只要“查得到”就行，那它为什么不能直接是字节？

不要分词器：字节加学到的分组。卡在哪：分词器不可学习、看不到字母、带着训练语料的语言偏见。改了什么：直接读字节，再让模型自己决定怎么把字节分组。Meta 的 BLT（Byte Latent Transformer, 2024-12）用一个小的字节语言模型估计“下一个字节有多难猜”，熵超过阈值就开一个新组，叫按熵分组（entropy patching）：好猜的地方组长、难猜的地方组短，把算力花在难的地方。它做了第一个控制算力的字节级规模化研究，到 80 亿参数、4 万亿字节，与 Llama 3 同等训练算力下表现相当。H-Net（2025-07）把分组边界也做成端到端可学的，算力相同时超过基于 BPE 的 Transformer，在中文和代码上优势更大。2026 年 10 月的一篇论文称，配合合适的训练方法，纯字节 Transformer 随模型变大可以持续超过子词模型。代价：字节序列比 token 序列长约 4 倍，整个工具链都围绕 token 建立。现状：截至 2026 年 10 月，主流前沿模型仍然使用 BPE 类分词器。

下面把同一句话交给六种切法：按词、按字符、UTF-8 字节、字符起点的 BPE、字节级 BPE、字节加按熵分组。它们大致就是这一章的历史顺序。

分词器会被淘汰吗

主张
字节级模型没有未登录词、没有语言偏见、能看到每个字母和数字位，而且 BLT、H-Net 证明了它在算力相同时可以和子词模型打平甚至更好。
反方
字节序列比 token 序列长约 4 倍，注意力和 KV 缓存的成本随之增长；分组的小模型增加了系统复杂度；最大规模的验证只到几十亿参数，离前沿模型差两个数量级。
现在怎么看
截至 2026 年，前沿模型的主流做法是“更大的 BPE 词表 + 输入端加嵌入”，字节级与动态分组是活跃的研究方向，还没有进入主流产品。两条路也在靠拢：n-gram 嵌入和按熵分组都在把“token 的边界”从固定规则变成可以学的东西。

常见误解

  • 一个 token 就是一个词（或一个字）。token 是统计上常见的片段，可能是半个词、一个词、几个字，也可能是一个字节。按 OpenAI 的经验值，英文一个 token 平均约 4 个字符、0.75 个单词；中文因分词器不同而差异很大。
  • 中文费 token 是因为中文更复杂。同样的内容，中文的字符数只有英文的三分之一左右，UTF-8 字节数也略少。贵不贵取决于分词器的训练数据：以英文为主的分词器溢价可达 3 倍，多语言分词器接近 1 倍甚至更省。
  • 分词器和模型是一起训练的。分词器先在单独的语料上训练好，然后冻结。两者的数据不一致，就会出现故障 token；想换分词器，嵌入表和输出层基本要重新训练。
  • 嵌入向量的每一维都有一个含义。单独的一维通常没有可读的含义，概念体现为很多维度组合出的方向。演示里“每一维可解释”是为了教学而手工构造的。
  • 词表越大越好。BPE 的压缩收益递减，而嵌入、输出层的参数和计算随词表线性增长；最优大小随模型规模变化，小模型尤其不该用过大的词表。

演进史

2013

word2vec：按词切，每个词一个稠密向量

卡在哪
传统方法用独热向量表示词，任意两个词都正交，“猫”和“狗”与“猫”和“汽车”一样远，模型无法利用词之间的相似性。
怎么解决
训练一个小网络预测上下文，把每个词压成几百维的稠密向量；意思相近的词向量相近，还出现了向量算术。
代价
按词切，词表是封闭的：没见过的词没有向量，只能变成 [UNK]；一个词只有一个向量，无法区分多义词。
引出
新词、罕见词、拼错的词怎么办？
同时期GloVe 与 fastText
GloVe（2014）直接分解全局共现矩阵，和 word2vec 本质相同（见上面的推导）。fastText（2016）把词拆成字符 n-gram 再求和，第一次让没见过的词也能有向量，是子词思想在词向量上的先声。
2015–2016

子词 BPE 进入神经机器翻译

卡在哪
翻译模型的词表只能有几万个词，人名、地名、复合词大量被替换成 [UNK]，译文里出现成片的空洞。改成按字符切又让序列长好几倍。
怎么解决
Sennrich 等把 BPE 压缩算法用于分词：常见词完整保留，罕见词拆成子词，任何由已知字符组成的词都能表示。
代价
依赖按空格的预分词，对中文、日文这类不用空格的语言不友好；切法和语言学无关。
引出
需要一种不依赖空格、对所有语言一视同仁的分词方法。
没成为主流字符级模型
2016 年前后的字符级翻译模型、2021 年的 CANINE 和按字节建模的 ByT5 证明了“不要词表”可行，但序列长几倍，同等算力下打不过子词模型。“从最小单位出发”的思路后来在字节级 BPE 和 BLT 里重新出现。
分支WordPiece、SentencePiece 与 Unigram
WordPiece（Schuster 与 Nakajima, 2012，最初用于日语和韩语语音搜索）和 BPE 类似，但按“合并后似然提升最多”来选择合并，Google 翻译（2016）和 BERT（2018）都用它。SentencePiece（2018）把空格当作普通字符，不再需要各语言的预分词规则，并实现了 Unigram 和子词正则化；T5、早期 Llama、Gemma 都用它。
2019

字节级 BPE：彻底消灭 [UNK]

卡在哪
任何以字符为基础的词表都可能遇到没见过的字符（罕见汉字、emoji、各种符号），而 Unicode 有 15 万多个字符。
怎么解决
GPT-2 以 256 种字节为起点做 BPE，任何文本都能编码、能原样还原，未知符号彻底消失。
代价
非拉丁文字被拆成多个字节，以英文为主的训练语料下 fertility 很高，同样内容要多花几倍 token。
引出
多语言的 token 成本不公平，需要更大、更多语言的词表。
另一种保险字节回退
以字符为起点，再加 256 个字节 token 兜底（LLaMA, 2023；Gemma 系列）。和字节级 BPE 一样不会遇到 [UNK]，常用字符则保证是完整的 token。
2023–2026

大词表与多语言

卡在哪
3 万到 5 万的词表下，中文、印地语等语言的 token 成本是英文的 2 到 3 倍以上；上下文窗口被白白占用。
怎么解决
词表扩大到 10 万到 26 万，用多语言语料训练分词器；数字按位或按三位切分。
代价
嵌入和输出层的参数随词表线性增长，小模型尤其吃亏；新加的 token 越来越罕见、越来越难训好。
引出
能不能让输入端的词表大、输出端的词表小，或者让 token 的边界不再由固定规则决定？
争论词表的规模定律
Tao 等（2024）认为最优词表应随模型规模增大，多数模型的词表偏小。反方认为小模型和端侧部署承受不起大词表。见上文的推导与争议框。
2025–2026

超词与 n-gram 嵌入：松开分词器的两个约束

卡在哪
预分词不许 token 跨过空格；输出层的成本限制了整个词表的大小。
怎么解决
SuperBPE 在训练后期放开空格限制，学跨词的超词；Over-Tokenized Transformer、Engram 只放大输入端，用哈希 n-gram 嵌入查表，输出端词表不变。
代价
token 边界和词边界不再对齐；巨大的嵌入表要放在主机内存或闪存里。
引出
如果 token 的边界和输入端的表都可以学，固定的分词器还有必要吗？
2024-12 → 2026

字节级模型：让模型自己分组

卡在哪
子词分词器看不到字母和位值，有语言偏见，和模型分开训练。
怎么解决
直接读字节，按下一个字节的熵分组（BLT），或把分组边界端到端地学出来（H-Net）。
代价
字节序列更长、系统更复杂，整个工具链需要重写；还没有在前沿规模上验证。
引出
无论用哪种方式切分，下一步都是让序列里的每个位置能“看到”其它位置：注意力。
被取代MegaByte（2023）
Meta 早期的字节级尝试，用固定长度的字节块。固定分块无法根据内容难度分配算力，被按熵动态分块的 BLT 取代。它留下的思想是“用一个小模型处理块内的字节、用大模型处理块之间的关系”。

自测

1. 动手算：语料是“大模型”5 次、“模型”3 次、“大模块”2 次，一个字一个 token 起步。BPE 前两轮合并哪两对？每轮之后语料共有多少 token？第一轮之前“大 模”出现 7 次，比第二轮被合并的那一对还多，为什么第二轮不合并它？
起步共 \(15 + 6 + 6 = 27\) 个 token。相邻对：模·型 \(5 + 3 = 8\)，大·模 \(5 + 2 = 7\)，模·块 2。第一轮合并“模型”（8 次），剩 \(27 - 8 = 19\) 个。重新数：“大模型”里的“大 模”变成了“大 模型”（5 次），“大 模”只剩“大模块”里的 2 次，模·块 2。第二轮合并“大 + 模型 → 大模型”（5 次），剩 \(19 - 5 = 14\) 个。“大 模”的 7 次里有 5 次在第一轮被“模型”吃掉了：合并会改变其它对的计数，所以每轮都要重新数。
2. 为什么字节级 BPE 永远不会遇到未登录词，而且解码一定能还原原文？它付出了什么代价？
任何文本在 UTF-8 下都是字节序列，而 256 种字节全在初始词表里，所以最坏情况下可以逐字节编码；每次合并只是把两个 token 的字节串拼接起来，所有 token 的字节首尾相接始终等于原文，所以解码严格还原。代价是没被合并的非拉丁字符要占多个 token（汉字 3 个），序列变长、成本变高；另外模型生成的 token 序列不一定是合法的 UTF-8。
3. 一个模型 \(V = 128{,}256\)、\(d = 4096\)，输入嵌入和输出矩阵不共享，用 BF16（每个参数 2 字节）存储。这两张表一共占多少显存？如果换成 \(d = 2048\) 的 1B 模型并且共享嵌入呢？
8B：参数量 \(2Vd = 2\times 128{,}256\times 4096 \approx 10.5\) 亿，每个 2 字节，约 2.1 GB，占整个 8B 模型（约 16 GB）的 13%。1B 共享：\(Vd = 128{,}256\times 2048 \approx 2.6\) 亿，约 0.53 GB；Llama 3.2 1B 全部约 12.4 亿参数，这一张表占 21%。
4. 动手算：同一段内容，中文的字符数是英文的 0.34 倍。英文平均 4 个字符一个 token。分词器 A 平均每个汉字 1 个 token，分词器 B 平均 1.5 个汉字一个 token。两种分词器下中文相对英文的分词溢价各是多少？
溢价 = 字符数之比 × fertility 之比，\(f_{\text{英}} = 0.25\)。A：\(0.34\times 1/0.25 = 1.36\)，中文多付 36%。B：\(f_{\text{中}} = 1/1.5\approx 0.67\)，\(0.34\times 0.67/0.25\approx 0.91\)，中文反而便宜 9%。同一种语言是贵是便宜，取决于分词器。

必读

  1. Neural Machine Translation of Rare Words with Subword Units（Sennrich 等, 2016）BPE 用于神经网络的起点，篇幅很短，算法描述只有十几行。
  2. Subword Regularization（Kudo, 2018）Unigram 分词和子词正则化的原始论文，讲清了“切法”本身也可以是概率模型。
  3. Distributed Representations of Words and Phrases（Mikolov 等, 2013）与 Neural Word Embedding as Implicit Matrix Factorization（Levy 与 Goldberg, 2014）前者给出负采样和向量算术，后者给出解释：词向量在分解 PMI 矩阵。
  4. Language Model Tokenizers Introduce Unfairness Between Languages（Petrov 等, 2023）在 200 种语言上量化分词溢价，看清“同样的话付多少 token”取决于什么。
  5. Scaling Laws with Vocabulary（Tao 等, 2024）词表大小也有最优值，而且应随模型变大。
  6. Byte Latent Transformer（Meta, 2024）字节级模型第一次在控制算力的条件下规模化到 8B，理解“不要分词器”这条路的关键论文。
